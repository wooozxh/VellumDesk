## 2. 实探结论（2026-10-04，全部实测，不猜）

### 2.1 CLI 本体：一个原生 exe，比一期想象的还要好带

| 项 | 实测结果 |
|---|---|
| 形态 | npm 包 `@wecom/cli` 的 `bin/wecom.js` **只是个启动器**；真正的 CLI 是平台可选依赖里的 **`wecom-cli.exe`（原生 Rust 单文件）** |
| 依赖 | **零依赖、免 Node** —— 直接 `spawn("...wecom-cli.exe", args)` 就能跑（一期还要 `node wecom.js`） |
| 体积 | 9.62 MB（10 091 560 字节），SHA-256 `10ec26b4…84`，对比 FFmpeg 267 MB 可忽略 |
| 版本 | `wecom-cli 1.3.4 (wecom 2026-09-23T11:47:44Z f9b2815)`；MIT 许可（LICENSE 随包分发） |
| 凭据位置 | `%USERPROFILE%\.config\wecom\credentials.enc`（+ `.encryption_key`）—— **跟 exe 放哪无关**；升级/重装软件不用重扫，换电脑/换 Windows 账号要重扫 |

### 2.2 授权：`auth init` 能出二维码，且**只能出在临时目录**

```
wecom-cli auth show --status                       # authorized / unauthorized
wecom-cli auth init --noninteractive --no-browser --output-qrcode <PNG路径>
```

- `auth init` 会打印「授权链接 + ASCII 二维码」并在终端等扫码；`--output-qrcode` 额外落一张 PNG
- ⚠️ **踩坑（本批实测）**：CLI 有自己的**文件访问白名单**，
  允许范围 = **CLI 进程的工作目录 + 系统临时目录**，其余路径直接
  `893006 PermissionError: 目标路径超出可访问范围`
  —— 也就是说二维码 PNG **必须写在 `os.tmpdir()`**，
  写进工作区会被拒（第 19 批 `media upload` 遇到的是同一条规则）。
  已落成代码注释，避免后人「顺手改成工作区目录」把授权搞坏。
- 授权成功后 CLI 进程自己退出；界面靠轮询 `auth show --status` 判定完成（不需要解析它的退出码）

## 3. 设计：定位下沉 + 内置优先

### 3.1 新增 `src/main/wecomCli.ts`（定位与调用唯一入口）

一期的定位逻辑散在「环境变量 → 开发机硬编码路径」两步里，那是"每人自己装 CLI"时代的写法。
本批把**定位（纯逻辑，可断言）**与**调用（副作用，异步 spawn）**拆开：

```
resolveCliCommand(input)   纯函数：只看入参 + 一个 exists 判定 → 返回 { cmd, pre, source } | null
spawnCli / runRaw          真 spawn（异步，绝不 spawnSync）
runCliJson                 跑 + 解析 JSON + 识别三类失败
getCliInfo / readAuthStatus / startWecomAuth / cancelWecomAuth
```

**定位顺序**（`docs/16` §4.1）：

| 序 | 来源 | 说明 |
|---|---|---|
| ① | `WECOM_CLI_EXE` | 运维逃生口：临时换一版 CLI 排查，不动安装包 |
| ② | **内置** `resources/wecom-cli/wecom-cli.exe` | 打包后 `<安装目录>/resources/…`；开发态是项目 `resources/…` |
| ③ | `WECOM_CLI_JS`（+ `WECOM_CLI_NODE`） | 一期老配法，保留不删（老开发机/同事机不受影响） |
| ④ | 开发机硬编码路径 | 最后兜底 |
| — | 都没有 → `null` | 界面显示「内置组件缺失」，工单之外的功能不受影响 |

内置命中时**直接 spawn exe**（`pre = []`），不再需要 Node 中转。

### 3.2 打包配置（`package.json`）

```jsonc
"files": [ …, "!resources/ffmpeg/**", "!resources/wecom-cli/**" ],   // 与 asar 去重
"extraResources": [
  { "from": "resources/ffmpeg",     "to": "ffmpeg" },
  { "from": "resources/wecom-cli",  "to": "wecom-cli" }              // 新增
]
```

- `wecom-cli.exe` **不入 git**（二进制，`.gitignore` 已排除），目录里留 `README.md` 写清来源与重建方式（照 FFmpeg 那套）
- 安装包体积 +9.6 MB

## 4. 设计：授权引导界面（`WecomAuthModal`）

### 4.1 状态机（每一步都有明确出口）

```
打开 ─► wecom:cliInfo
   ├─ available=false / auth=cli-missing ──► 讲人话「内置组件缺失，重装最新版」+ 原始日志，不给重试按钮骗人
   ├─ authorized ────────────────────────► 亮本机身份 + 「重新授权」「完成」
   └─ unauthorized / unknown ────────────► 「开始扫码授权」
              │点击
              ▼
        wecom:authStart → auth init → 拿到二维码（data URL）
              │每 2 秒 wecom:authStatus（最长 3 分钟）
              ├─ authorized ──► 读身份 → 提示成功 → 变成「已授权」
              └─ 超时 ────────► 给「重新授权」，不死等
```

- 关弹窗 / 点取消 → `wecom:authCancel` 杀掉等待中的 CLI、删掉临时二维码（不留孤儿进程）
- 二维码外还给出 CLI 打印的**授权链接**（可选中复制），扫码不顺时兜底
- 出错才展示 CLI 原始输出（`<pre>`，可选中）—— 平时不吓人

### 4.2 三个入口（互相补位）

| 入口 | 触发条件 | 为什么这么设计 |
|---|---|---|
| **首次启动自动弹** | 组件在 + **未授权** + 从没弹过（meta `wecom_onboard_seen`） | 这时扫码一次就能解决，弹了有意义；弹过就不再自动弹 |
| **工单设置弹窗顶部常驻一行** | 永远 | 自动弹窗错过之后的正式入口（状态 + 来源 + 版本 + 「打开连接引导」） |
| **同步失败兜底** | 点「同步工单」撞上 cli-missing / auth-expired | 用户此刻正需要它 —— 直接把引导摆出来，而不是只吐一句 toast |

**故意不弹**的两种情况：组件缺失、状态未知 —— 免得每次开机都挡路（入口常驻，够用）。

### 4.3 文案

`copy.ts` 新增 `wecom` 分组（约 40 条）。措辞约定：说「扫码一次」不说「CLI / 环境变量」；
「连接」是组件+授权的总称，「授权」专指扫码那一步；
排查信息（来源/路径/版本）都收进悬停提示，主界面不喧哗。
（按流程这批新文案**待回有 mcporter 的机器 `publish`**。）

## 5. 界面微调两处

### 5.1 顶栏改序改名

- `App.tsx`：`.tabs` 三格顺序改为 工单队列 / 任务视图 / 文件视图（顺手清掉该区块三处游离空行）
- `copy.ts`：`ticket.viewTab` `工单` → `工单队列`（只改一处，所有引用点跟着变）

### 5.2 下拉白底

根因：`.tk-assign-pick select` 只写了 `max-width`，`.tk-sheetrow select` **完全没有样式** ——
闭合态落到浏览器默认的浅色控件（白底黑字）；而且**展开的弹出列表由系统绘制，改 `background` 管不到**。

修法：

```css
select { color-scheme: dark; }          /* 一处生效：所有下拉的弹出层跟随深色主题 */
.tk-assign-pick select { …深色底/描边/文字色… }   /* 与 .claimbar select 对齐 */
.tk-sheetrow select    { …同上… }                 /* 顺带补上（子表类型下拉，同病） */
```

## 8. 刻意不做

- **不做多平台 CLI**（mac / linux 二进制）—— 全公司 Windows
- **不做 CLI 自动升级** —— 版本随安装包钉死，升级 = 出新安装包（避免"同事之间 CLI 版本不一致"的排查噩梦）
- **不做「授权到期自动弹」** —— 到期时同步会失败、失败即弹引导（够用），不必常驻轮询打扰
- **不改默认视图** —— 用户只提了排序（已记入下一批候选）
- **不做二维码以外的桌面端授权路径** —— 企业微信授权本来就是手机扫码

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 二维码写不进临时目录（白名单） | 已实测 + 代码注释钉死；写失败会把 CLI 原始报错原样展示 |
| 沙箱/杀软拦截内置 exe | `spawn` 失败 → `cli-missing`，界面降级提示，其他功能不受影响 |
| `auth init` 留下的等待进程 | 关弹窗/取消即 `kill`；主进程再超时兜底 |
| 同事机器上第一次弹窗太突兀 | 只弹一次 + 「稍后再说」；且只在"扫码就能解决"时弹 |
| CLI 版本与软件不匹配 | 版本号在界面上可见（「内置组件 v1.3.4」），排查时一眼可比 |
