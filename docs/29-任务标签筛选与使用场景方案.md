# 29 · 任务标签筛选打通 + 使用场景绑定（第 23 批 · 修 bug 会话）

> 日期：2026-10-05　性质：bug 修复 + 小幅功能扩展　分支：`main`（当前唯一分支）

## 一、背景：用户报的三个问题

1. **bug**：本机新建任务 / 工单自动建任务后，会为任务写好「物料类别」，但左侧筛选标签面板里
   对应标签的数字不更新、手动扫描也不更新、点击该标签筛不出任务。
2. **功能缺口**：「使用场景」标签目前在软件里无作用——任务上绑不了它。
3. **UI**：建任务面板绑定标签的控件现在是平铺按钮，标签多了窗口会臃肿，建议改下拉（注意深色底色）。

## 二、现状真相（排查结论）

- 任务分类存 `packs.category`（字符串字段）；左侧标签面板的数字算的是 `asset_tags` 里
  **贴了该标签的素材文件数**，跟任务完全两套账。
- 点左侧标签只筛**文件视图**（`listAssets` 的 `tagIds`），任务视图（`listPacks`）根本不响应。
- 任务上只有「物料类别」字段，没有「使用场景」字段；工单表其实有「物料使用场景」列
  （`tickets.ts` 的 `COL.useScene`），但同步时没提取、建任务时也没写。

## 三、用户拍板（2026-10-05）

| 决策点 | 结论 |
|---|---|
| 左侧标签的数字与筛选怎么管任务 | **任务 + 文件一起管**：数字 = 任务数 + 文件数；点标签任务视图筛任务、文件视图筛文件 |
| 任务绑定「使用场景」取值 | **单值**（与物料类别对称，一个任务一个场景） |

## 四、改动方案

### 4.1 数据模型（迁移 17，幂等）

- `packs` 加 `channel` 列（TEXT，默认空串；与 `category` 完全对称，存「使用场景」名字）。
- `tickets` 加 `material_scene` 列（TEXT，存工单「物料使用场景」原始值；与 `material_category` 对称）。

### 4.2 主进程

- `createPack` / `updatePack` / `movePackTo`：入参、INSERT/UPDATE 带上 `channel`。
- `listPacks(opts?: { tagIds?: number[] })`：新增标签筛选。把选中 tagId 按维度拆成
  「category 名字集合」「channel 名字集合」，分别筛 `packs.category` / `packs.channel`
  （跨维度「并且」、同维度「或」，与 `listAssets` 的 tagIds 语义一致）。
- `listTagDimensions`：每个标签的计数从 `assetCount` 扩成 `assetCount + packCount`
  （category 维度数 `packs.category`、channel 维度数 `packs.channel`）。
- 工单同步：`extractRow` 提取 `useScene` → `material_scene` 落库 → 自动建任务时
  `createPack({ channel })` 一并带上。

### 4.3 标签改名 / 删除联动（与物料类别对称，默认做）

- 「使用场景」标签改名 → 已有任务的 `packs.channel` 同一事务跟着改。
- 「使用场景」标签删除 → 已有任务的 `packs.channel` 归「未分类」。
- 理由与第 10 批物料类别完全一致：`channel` 存的是名字不是外键，只改标签名会把任务留成
  一个面板里查不到的老名字。

### 4.4 渲染层

- 左侧标签面板：数字显示「任务 + 文件」合计，悬停提示分解（`N 个任务 + M 个文件`）；
  0 条仍压暗。点击标签后 `selectedTagIds` **同时**驱动任务视图与文件视图的筛选。
- 任务视图：`shownPacks` 按选中标签的 category/channel 名字集合过滤（或由 `listPacks` 主进程筛）。
- 建任务 / 编辑任务面板：物料类别「平铺按钮」→ 下拉 `select`；新增「使用场景」下拉。
  两个下拉都允许留空（记「未分类」，与现状一致）；深色底色沿用第 21 批已做好的
  `select { color-scheme: dark }` 与深色 select 样式。

### 4.5 文案

- 新增少量文案（使用场景下拉标签、悬停分解模板等），走 `copy.ts` 新增并接线，
  在线表格 `publish` 待回到有 mcporter 的机器再刷（与第 18 批同口径）。

## 五、默认值（有异议请指出，否则按此施工）

1. 「使用场景」改名 / 删除联动**与物料类别完全对称**（见 4.3）。

## 七、执行记录（2026-10-05，第 36 次会话）

### 7.1 施工中抓到的真正根因（比方案预判更深一层）

`App.tsx` 有一条第 4/7 批留下的 effect：`if (tagChanged && view !== 'files') setView('files')`
—— 那是「标签筛选只作用于文件」时代的写法。结果：**用户在任务视图点标签，会被强行拽到文件视图**，
根本看不到任务被筛。这是「点标签筛不出任务」的直接原因（光改数据层不够）。
**改为**：点标签留在当前视图；只有工单视图（不响应标签筛选）点标签才切到任务视图给反馈。

### 7.2 与方案的实现差异（均为「更小改动」取向）

- **任务筛选落在渲染层**（`shownPacks` 按选中标签的 category/channel 名字集合过滤），
  没有给 `listPacks` 加 `tagIds` 参数 —— 包数据量小、前端过滤足够，避免动 IPC 链路。
  标签计数 `packCount` 仍在主进程 SQL 算（它必须跟随左栏项目范围）。
- **抽了一个 `packsInProject`**：文件视图的项目范围用它（不含标签筛选），避免文件视图被任务标签二次收窄
  （原写法用 `shownPacks` 推导项目范围，加了标签筛选后会顺手把文件也筛窄）。
- **迁移 17 只需 `packs.channel`**：`tickets.use_scene` 第 13 批就已全量同步，本批只是建任务时带出去。
