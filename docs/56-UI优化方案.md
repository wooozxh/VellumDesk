# UI 优化方案（docs/56）

> 状态：**方案 + 原型阶段**（未动产品代码）
> 日期：2026-10-30　｜　基线：v1.12.0 / `3a56394` / accept 1441
> 审阅对象：任务视图 / 文件视图 / 工单队列 / 模板库 / 通用库 / 任务详情 / 首次配置引导（7 个真实界面截图 + 真机量测）

---

## 0. 一句话结论

现在的界面**不是不好看，是"没有规范"**。

同一份代码里同时存在 3 套按钮高度、4 套徽标样式、3 种字号的弱化文字、2 种含义相同的视图切换图标、
1 个"同一件事提示两遍"的模板库告警。单个页面看还行，连着走一遍就有一种"哪儿都不对劲但说不出哪儿"的感觉。

**所以这轮不做"美化"，做"立规范"**：定一套 token（间距 / 字号 / 高度 / 圆角 / 徽标 / 阴影），
把 7 个界面按这套 token 收一遍，改动落在 CSS 与少量组件，不动业务逻辑。

## 1. 参照的规范（都来自成熟桌面 / 中后台产品）

| 来源 | 拿它来定什么 |
|---|---|
| **Ant Design 5** | 整体骨架（Header / Sider / Content）、4px 栅格间距、按钮三档高度 24/28/32、Modal 宽度分档、Tag 规范、Table 列对齐 |
| **Ant Design Pro / ProTable** | 数据表四件套：**搜索 / 排序 / 列设置 / 密度切换**；工具条右对齐、批量操作条浮于底部 |
| **Material Design 3** | Elevation 分层（卡片 / 浮层 / Toast）、State layer（hover 8%、focus 12%）、Shape scale（4/8/12/16） |
| **IBM Carbon（数据表格）** | 紧凑密度（32px 行高）、数字与日期**右对齐 + tabular-nums**、超长文本用 tooltip 不用换行 |
| **Fluent 2（Windows）** | Command Bar 概念：全局动作与页面内动作分层；图标按钮统一 30/32px 方钮 |
| **Radix / shadcn（无障碍）** | `:focus-visible` 焦点环、`aria-*`、命中区不小于 24px、键盘可达 |
| **GOV.UK / Stripe** | 文案说"点完会变成什么"；危险操作必须二次确认并说明后果 |

> 说明：**不引入任何 UI 库**。上面这些是"照着抄规范"，不是"装个库"。理由：现有 `main.css` 已 4900 行、
> 变量体系已在（深浅双主题），换库等于推倒重来、且会把刚做完的主题能力冲掉。

### P1 —— 一看就"不整齐"

| # | 现象 | 根因 | 规范依据 | 改法 |
|---|---|---|---|---|
| 6 | **按钮三种高度**：顶栏 30px、工具条 28px、弹窗里 32px | 各自定义 | AntD 三档 24/28/32 | 全站只用两档：**28（默认）/ 24（表格行内、密集处）** |

### P2 —— 效率与秩序

| # | 现象 | 改法 |
|---|---|---|
| 11 | 表格没有「共 N 条 / 排序 / 列设置 / 密度」四件套 | 工具条统一右侧：搜索 → 排序 → 列 → 密度 → 主操作 |
| 12 | 文件行信息过载：长路径 + 4 个带 × 的标签胶囊 + 右侧类型徽标 | 主行只留「名称 + 关键元信息」，路径/标签进第二行且**折叠为一行摘要**，× 仅悬浮出现 |

## 3. 设计令牌（本次的核心产出）

在 `main.css` 顶部加一组 token，所有组件只用 token，不再写裸值。

```css
:root {
  /* 间距：4px 栅格 */
  --sp-1: 4px;  --sp-2: 8px;  --sp-3: 12px; --sp-4: 16px;
  --sp-5: 20px; --sp-6: 24px; --sp-8: 32px;

  /* 字号：不再出现 12.5 / 13 这种野生值 */
  --fs-xs: 11px;  /* 仅角标 */
  --fs-sm: 12px;  /* 辅助信息、表格次要列 */
  --fs-md: 13px;  /* 正文、表格主列（当前主界面基准） */
  --fs-lg: 15px;  /* 卡片标题、弹窗标题 */
  --fs-xl: 18px;  /* 空状态标题 */

  /* 控件高度：只剩两档 */
  --h-ctl: 28px;      /* 按钮 / 输入 / 下拉 */
  --h-ctl-sm: 24px;   /* 表格行内小按钮 */
  --h-row: 32px;      /* 紧凑表格行 */
  --h-row-lg: 40px;   /* 舒适表格行（可切换） */

  /* 圆角：AntD shape scale */
  --r-sm: 4px; --r-md: 6px; --r-lg: 8px; --r-xl: 12px;

  /* 阴影：只留两层（Material elevation） */
  --el-1: 0 1px 2px rgba(0,0,0,.28);   /* 卡片 */
  --el-2: 0 6px 24px rgba(0,0,0,.42);  /* 浮层 / 菜单 / Toast */

  /* 语义色：状态只允许这 6 个 */
  --st-info: --accent; --st-ok: #2f9e6b; --st-warn: #d98b1f;
  --st-danger: #d9534f; --st-mute: #6f7681; --st-dim: var(--text-3);
}
```

**新增规则（写进 DECISIONS）**：
1. 任何新组件**不得**写裸 `px` 字号/圆角/阴影，只能用 token。
2. 弱化信息**一律用文字色**，禁止 `opacity`（这条 v1.12.0 已经吃过教训）。
3. 表格里的数字、日期、编号**右对齐 + `font-variant-numeric: tabular-nums`**（Carbon）。
4. 表格单元格过长 → `ellipsis + title tooltip`，**不许换行撑行高**。
5. 按钮只有两个尺寸；小一档只允许出现在表格行内与工具条右侧。

## 4. 分界面改法

### 4.1 全局骨架（所有界面）

```
┌ 品牌 ─ 搜索 ─────── 视图切换(Segmented) ─────────── 图标按钮组 ┐
│  Sider  │            视图工具条：标题+计数 ......... 工具组   │
│  标签树 │            ───────────────────────────────────────  │
│  项目   │            内容区（卡片 / 表格）                    │
└─────────┴            底部状态条：上下文 · 工作区 · 版本        ┘
```

- 顶栏只放**全局**动作：主题、刷新、设置、插件（图标按钮，hover 出文字）。
- 「新建任务」是唯一主按钮，固定在**视图工具条右端**而不是顶栏（它只对当前视图有效）。
- 搜索框：全局搜索只搜文件/任务；**列表内的筛选/排序进视图工具条**。

### 4.2 工单队列

- 列宽固定：`编号 132 / 物料名称 flex / 状态 84 / 申请人 96 / 业务归属 140 / 设计师 96 / 交稿日期 104 / 关联任务 flex`。
- 编号、日期**右对齐 tabular-nums**；物料名称 ellipsis。
- 行高 32（紧凑）/ 40（舒适）可切。
- 状态用统一 Tag（审批中=蓝、已通过=绿、已驳回=灰、待指派=橙、异常=红），**表头下方给一行图例**（首次出现时）。
- 顶部两排胶囊合并成一行：左边=视图（我的/全部/未指派…），右边=操作（同步/导出）—— **同步不是主按钮**。
- 工具条右端补：排序、列设置、密度。

### 4.3 任务视图（卡片）

- 卡片等高 168px，封面固定 16:9，标题 **2 行截断**（现在两行标题会溢出封面）。
- 卡片底部信息一行放下：`3 个文件 · 289 KB · 5 天前`（现在分两行、字号还小）。
- 徽标：任务类型用 Tag（橙=待指派），客户/渠道用 Chip（纯文字），两种不再混用。
- 左侧标签树：色点加图例说明，计数用 Chip，`0` 也显示（淡）。

### 4.4 模板库

- 信息卡内部字号统一：字段名 12 / 值 13 / 值内强调（CMYK、3mm）13 加粗。
- 「无多步专色 / 4 步多步专色」徽标统一 Tag 样式、位置一致。
- 橙色告警条保留，**删掉重复 toast**；文件名超长时 ellipsis。
- 右侧工具条按钮顺序：扫描磁盘（图标 + 文字）· 导入 PSD（主）· 重建卡片（次）· 新建分组（次）· 视图模式（图标）。

### 4.5 任务详情弹窗

- 顶部：标题 + 归属项目（可点）+ 右侧 `⋯` 菜单（编辑 / 移动 / 绑定文件夹）+ `×`。
- 动作按钮**收敛到弹窗底部固定操作栏**：主操作 1 个（打包交付），次操作 2-3 个（编辑信息、打开文件夹），其余进 `⋯`。
- 版本区：`V2（当前）` 用描边 + 角标；`未分版本` 文案改成「未归入任何版本」。
- 「成品 / 素材 / 工程文件 / 未归属」四组用**同一套小节样式**：标题 + 计数 + 右侧动作，内容缩略图统一 96×64。

### 4.6 文件视图

- 行结构：主行 = 勾选框 + 类型图标 + 名称 + 右侧状态 Tag；第二行 = 路径摘要 + 标签（**折叠**，悬浮展开）。
- 标签的 `×` 仅在**该行悬浮**时出现。
- 类型从彩色方块改线性图标 + 单色底。

### 4.7 首次配置引导

- 弹窗宽 720（AntD 大尺寸档），文案每行 ≤ 42 字。
- 步骤条做成**可视化进度**（6 段进度 + 当前步高亮），不要纯文字。
- 背景的空状态文案在引导期间**不渲染**，避免两个空态叠加。
- 「我以后再说」放左下角弱化，主按钮右下（现在两者并排在右下，容易误点）。

## 6. 原型

`docs/56-UI优化原型.html` —— 单文件，双击打开（无需服务器、无外部依赖）。

| 功能 | 说明 |
|---|---|
| 5 个屏可切 | 任务视图 / 工单队列 / 模板库 / 文件视图 / 任务详情（顶栏 Segmented 切换） |
| 深 / 浅两色 | 顶栏太阳钮，与产品里那颗一致 |
| **改动点抽屉** | 右上角「改动点」按钮 → 列出该屏改了哪几处（编号与本方案对应，共 22 条） |
| 直接对比 | 抽屉里每条改动都能点，点完对应界面元素高亮一下 |

原型是**照着改完的样子画的**（同一套 token、同一批真实数据），尺寸按真实窗口 1360×880。

### 实现时容易踩的两个坑（原型阶段就踩到了）

1. **grid 单元里的 Tag 会被拉成整列色块**：`display:grid` 的子项默认 `stretch`，
   `<span class="tag">` 被拉满整列 → 一个 12px 小标签变成 84px 色块。
   ⇒ 凡是 grid 里的 Tag / 徽标，必须 `justify-self: start`。
2. **离屏截图里带 `transition` 的按钮会渲成旧帧**（浅色下整排按钮发黑）：
   DOM 与 computed style 都正常，但 `capturePage` 抓到的是切换前的帧。
   ⇒ 截图前要么去掉 transition，要么强制重绘 + 延时；**别据此去改产品 CSS**（这是工具的坑，不是界面的坑）。
