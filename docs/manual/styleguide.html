STRUCTURE

页面骨架

手册是「章 → 小节 → 三级标题」三层。章头用 chapterhead（没有白底卡片），小节用 section（白底卡片）。

S.1章头

每章开头一个。三件套：kick（英文栏目名）+ h2.ct（章标题）+ 一句导语。

PART THREE

任务管理

从「接单」到「交付」的主战场：把一堆散文件变成一个能被验收的成品。

<section class="chapterhead" id="ch3">
  <div class="kick">PART THREE</div>
  <h2 class="ct">任务管理</h2>
  <p>一句导语，说清这一章解决什么问题。</p>
</section>
编号规则章头 id 固定为 ch1…ch6；小节 id 为 s<章>-<节>（如 s3-5）。新增小节必须同时加进目录页，否则体检 ② 会报。

S.2小节

一节一张白底卡片。标题用 h2 + <span class="n">（那个小方框里的编号）；节内分层用 h3（自带虚线分隔）。

顶部按钮组

从左到右：编辑任务信息 / 打开文件夹 / 打包交付 / 完成任务。

TEXT

文字元素

正文能用的只有这几样，够用。

T.1段落、列表、行内标记

普通段落。提到界面上的东西用 打包交付 这种胶囊标记，让读者一眼知道"这是个能点的东西"。

路径和字段名用 02-素材 这样标出来；按键用 Esc。外部链接可以放 下载地址。

  • 无序列表项
  • 第二项，粗体只用来强调关键动作
    • 可以嵌一层
用在哪　正文默认就是段落；btnchip 只给"界面上真实存在的按钮/开关"用
<p>点 <span class="btnchip">打包交付</span> 生成 zip。</p>
<p>成品放进 <code>01-成品</code>，按 <kbd>Esc</kbd> 关窗。</p>
为什么按钮要单独标记体检脚本会拿这些胶囊里的文字去比软件的文案字典 —— 软件把「打开文件夹」改名叫「打开所在文件夹」时，这一处会被自动标红。所以按钮名一定要用 btnchip，别混在正文里手写。
CALLOUT

提示条

四种颜色，含义固定，别混用。

C.1四色各自管什么

信息补充说明、设计意图。读者跳过也不影响操作。
好消息 / 已修复某个坑已经不存在了，或者"这样做就是对的"。
注意容易踩的坑、容易误解的地方。看一眼能省一次返工。
危险可能造成数据丢失的操作。动手前必须读。
<div class="call info"><span class="h">信息</span>补充说明。</div>
<div class="call ok"><span class="h">已修复</span>…</div>
<div class="call warn"><span class="h">注意</span>…</div>
<div class="call danger"><span class="h">危险</span>…</div>
克制一节里超过两个提示条，就该考虑把内容并进正文 —— 满屏色块会让真正危险的那条被忽略。

CARD & STEP

卡片与步骤

用来压缩篇幅：并列的三件事、按顺序的一串动作。

G.1并列卡片（grid2 / grid3）

只想马上干活
读第一部分的「安装」与「第一次启动」。
想搞懂为什么
从「四层结构」开始读。
想查一个按钮
直接看对应章节的对照表。
<div class="grid3">
  <div class="mini"><div class="t">标题</div><div class="d">说明</div></div>
  <div class="mini">…</div>
  <div class="mini">…</div>
</div>
grid2 / grid3　两列用 grid2，三列用 grid3。卡片里只能放 .t（标题）和 .d（说明）两个元素。

G.2编号步骤（steps）

  1. 打开任务详情，点 打包交付。
  2. 勾掉不需要进包的分组，选压缩质量。
  3. 点「生成」，等进度条走完 —— 完成后会直接把 zip 所在文件夹打开。
<ol class="steps">
  <li>第一步…</li>
  <li>第二步…</li>
</ol>
别和普通有序列表混用讲"操作顺序"用 steps（带圆点和竖线的）；只是列举几条并列事项，用普通 <ol>。
FAQ

问答

折叠块。用于「现象 → 怎么办」的排查，每条一问一答。

F.1折叠问答

顶部出现黄条「工作区『xxx』连不上」？

说明工作区所在的位置这次没能读到（移动硬盘拔了、网络盘断了）。软件不会自动换位置，里面一件东西都没动。把盘接上，然后点黄条右边的「重试」。

按钮点了没反应？

先看右下角有没有红色提示条 —— 软件把失败原因都写在那里。

<details class="faq"><summary>现象是什么？</summary>
  <p>怎么办。</p>
</details>
summary 写法　直接写读者看到的现象（带疑问语气），不要写"关于 xx 的说明"这种。
