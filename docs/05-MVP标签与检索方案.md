# 第 3 批方案：标签体系与检索（M2 + M3）

> 定稿日期：2026-09-24　｜　经用户确认：**做全 5 个维度**、**打标签入口在列表勾选批量打**
>
> 这是 MVP 的**核心批次**。需求文档反复强调：*"先用一两个月真实跑一跑，验证标签体系合不合理——标签一旦定错，后面所有数据都要重打，代价很高。"*
> 所以本批的目标不只是"功能能用"，而是**让用户在真实素材上尽快跑起来、把体系问题暴露出来**。

---

## 1. 本批做什么（用户可以照着验）

| 编号 | 功能 | 用户看到的样子 |
|---|---|---|
| C-01 | 5 个标签维度 | 界面出现「项目 / 类别 / 渠道 / 状态 / 时间」五组标签 |
| C-02 | 标签可增删改 | 每个维度下能自己加标签、改名、改色、删掉（删时提示影响多少条素材） |
| C-03 | 批量打标签 | 列表里勾选多条素材 → 弹面板勾标签 → 一次全打完；也能批量去标签 |
| C-04 | 多维组合筛选 | 左栏点标签，条件之间是「并且」关系，多点几个越筛越窄 |
| C-05 | 关键词 + 标签混用 | 顶部搜索框和标签筛选可同时生效 |
| C-06 | 标签颜色 | 标签带色块，列表和筛选栏里一眼区分 |
| C-07 | 标签自动建议 | 按文件所在文件夹名 / 文件名，推荐可能的标签（点一下即贴） |
| C-08 | 维度式左栏 | 左栏从「只有项目」升级为「5 个维度分组」，可折叠 |

**本批不做**（留到后面）：OCR 文字搜索、相似图检索、按颜色检索、智能分类。
理由：这三样是"锦上添花"，且 OCR/相似图都要引大依赖（模型、向量库）。先把**标签体系本身**跑通，验证它合不合理——这才是本批的目的。

## 2. 与现状的接缝（重要，先讲清楚）

现状已经有两套"分类"了，本批要跟它们理顺关系，不能打架：

| 现状 | 说明 | 本批怎么处理 |
|---|---|---|
| **左栏「所属项目」** | 已经是可管理的实体（projects 表），有颜色、有包数、能排序 | **不推翻**。项目维度直接复用 projects 表——不给素材另存一套"项目标签"，避免同一件事两处维护 |
| **文件的 `role`**（成品/素材/工程/未归属） | **按所在子文件夹自动判定**，是硬盘上的归类 | **不推翻**。这跟"物料类别"是两件事：role 回答"这文件在包里的位置"，类别回答"这是什么物料"。两者并存，界面上分别显示 |
| **「类别」现在是建包时选的**（海报/视频/折页…） | 挂在**包**上，不是挂在文件上 | 本批把类别做成**素材级标签**（同一包里可以既有海报又有视频）。包上原有的类别字段保留不动，作为兜底 |

**一句话**：项目维度复用现有 projects；role 保持自动不动；类别升级为素材级标签，与 5 个维度统一管理。

## 3. 标签维度设计（5 个）

| 维度 key | 显示名 | 可多选 | 是否可自定义 | 默认内容 |
|---|---|---|---|---|
| `project` | 所属项目 | ❌ 单选 | ✅（复用 projects 表） | 已有的项目列表 |
| `category` | 物料类别 | ✅ 多选 | ✅ | 海报 / 折页 / 详情长图 / 短视频 / 宣传片 / 直播物料 / 字体 / 图标素材 / 参考图 |
| `channel` | 使用渠道 | ✅ 多选 | ✅ | 公众号 / 朋友圈 / 视频号 / 抖音 / 线下门店 / 官网 |
| `status` | 状态 | ❌ 单选 | ✅ | 草稿 / 待审核 / 已交付 / 已归档 |
| `time` | 时间（年 / 月） | ✅ 多选 | ✅（可自动生成） | 自动从文件修改时间生成 `2026`、`2026-09` |

**设计要点**：
- **项目维度单选**：一条素材属于哪个项目，逻辑上唯一（需求文档 5.2 也是这个意思）
- **状态单选**：一条素材同一时刻只处于一种状态
- **类别 / 渠道多选**：一张海报可以同时发朋友圈和公众号
- **时间可自动生成**：入库时按文件修改时间自动贴年月标签，省得手动打（用户可关）

## 4. 数据库

### 4.1 用需求文档定的三张表结构

需求文档 7.4 节已定：`tags`（标签）+ `asset_tags`（关联表）。本批落地这两张，并按实际需要加一个 `dimensions` 概念（用常量表，不建表）。

```sql
-- 标签：每个标签一行
CREATE TABLE IF NOT EXISTS tags (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  dimension  TEXT    NOT NULL,          -- project | category | channel | status | time
  name       TEXT    NOT NULL,          -- 标签名，如「海报」
  color      TEXT    NOT NULL DEFAULT '#4f8cff',
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT    NOT NULL,
  UNIQUE(dimension, name)                -- 同一维度下不重名
);
CREATE INDEX IF NOT EXISTS idx_tags_dim ON tags(dimension, sort_order);

-- 关联表：一条素材可贴多个标签（标准做法，别省）
CREATE TABLE IF NOT EXISTS asset_tags (
  asset_id INTEGER NOT NULL,
  tag_id   INTEGER NOT NULL,
  PRIMARY KEY (asset_id, tag_id)
);
CREATE INDEX IF NOT EXISTS idx_at_tag ON asset_tags(tag_id);
CREATE INDEX IF NOT EXISTS idx_at_asset ON asset_tags(asset_id);
```

### 4.2 项目维度的特殊处理

`project` 维度的标签**不存进 tags 表**，而是从 `projects` 表实时映射（id 复用为负数或加前缀区分，实现细节见第 6 节）。
理由：项目已经是独立实体（有包、有排序、有删除时的去向逻辑），再存一份必然不同步。

> 若后续发现映射太绕，可退化为"tags 表里也存项目镜像，projects 变更时同步"。**先按映射做，简单且不会不一致。**

### 4.3 空库初始化

首次启动落 4 个维度的预制标签（项目维度不落）。用户可自由增删。

- 每组可折叠（点标题收起），默认全展开
- 已选中的标签高亮 + 显示色块
- 标题右侧显示该维度已选数量（如「物料类别 ②」）
- 顶部显示「已选 N 个条件」+ 一键清除

### 5.2 素材列表

- 每行左侧复选框（已有）+ 文件名下方显示**该素材的所有标签小色块**
- 选中多条后，列表上方浮出一条操作栏：`已选 12 条　[ 🏷 打标签 ]　[ ✕ 去标签 ]　[ 取消选择 ]`
- 打标签弹窗：按维度分组列出标签，勾选后点「应用」

### 5.3 标签管理弹窗（新增）

- 按维度分区，每个标签一行：色块 + 名字 + [改色] [改名] [删除]
- 删除时提示影响范围：**「该标签被 320 条素材使用，确认删除？」**（需求文档明确要求）
- 每个维度底部有「＋ 新标签」

### 5.4 标签自动建议

打标签弹窗里，根据文件所在文件夹名/文件名做简单匹配，把可能相关的标签置顶并标「建议」。
例：文件名含「小红书」且有「小红书」标签 → 建议它；文件夹名含「海南升学」→ 建议「海南升学规划中心」。
**只做推荐，绝不自动贴**（贴着用户的文件乱贴标签比不贴更糟）。

## 6. 技术实现要点

- **筛选 SQL**：多条件用 `INTERSECT` 或 `GROUP BY ... HAVING COUNT(DISTINCT dimension) = N` 实现"并且"关系
  ```sql
  -- 同时满足：类别=海报 且 渠道=公众号 且 状态=已交付
  SELECT a.* FROM assets a
  JOIN asset_tags at ON at.asset_id = a.id
  JOIN tags t ON t.id = at.tag_id
  WHERE (t.dimension='category' AND t.name='海报')
     OR (t.dimension='channel'  AND t.name='公众号')
     OR (t.dimension='status'   AND t.name='已交付')
  GROUP BY a.id
  HAVING COUNT(DISTINCT t.dimension) = 3
  ```
  项目维度另走 `pack_id → packs.project_id` 的 join
- **性能**：`asset_tags` 两个索引已覆盖；3 万条量级无压力（需求：1 秒内出结果）
- **IPC**：新增 `tag:list` / `tag:create` / `tag:update` / `tag:remove` / `tag:stats` / `tag:apply`(批量打) / `tag:removeFrom`(批量去) / `tag:suggest`
- **类型**：`Tag`、`TagWithCount`、`TagSelection`（筛选项）加到 `src/shared/types.ts`

## 9. 已知取舍与债务

| 项 | 说明 |
|---|---|
| 项目维度走映射而非存 tags 表 | 避免双份数据不一致；代价是筛选 SQL 多一个 join |
| role（成品/素材/工程）与"类别"并存 | 两个概念确实不同（位置 vs 物料类型），同时显示可能显得信息多；先跑起来看用户反馈 |
| 时间维度自动生成 | 能自动贴年月；若用户觉得多余，管理弹窗里可一键清空该维度 |
| 不做 OCR / 相似图 / 颜色检索 | 留后续批次，需引大依赖，不是本批目的 |
