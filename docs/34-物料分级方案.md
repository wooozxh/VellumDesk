## 3. 关键定义

### 3.1 维度 key = `grade`

`category` / `channel` / **`grade`**。全项目 grep 过，`grade` 无冲突
（唯一的 `level` 是 `exportPack.ts` 里 archiver 的 `zlib: { level: 6 }`，无关）。

### 3.2 兜底值 = `未分级`，**不复用 `未分类`**

现有 `UNCATEGORIZED = '未分类'` 是为「类别 / 场景」写的。物料没有类别时叫「未分类」通顺，
**没有分级时叫「未分类」是错词**（读起来像"归类失败"而不是"还没定优先级"）。

因此新增独立常量：

```ts
/** 包没分级时的兜底值（与 UNCATEGORIZED 同机制，但用词不同 —— 见 docs/34 §3.2）*/
export const UNGRADED = '未分级'
```

> ⚠️ **这带来一处必须改的地方**：`tags.ts` 的 `removeTag` 目前对**所有**能绑任务的维度
> 都用 `UNCATEGORIZED` 归拢（`UPDATE packs SET ${col} = UNCATEGORIZED`）。
> 加了 `grade` 之后必须**按维度取各自的兜底值**，否则删一个分级标签会把任务的
> 分级写成「未分类」—— 一个查得到的错词。

### 3.3 单值

`packs.grade` 一个任务一个分级（S/A/B/C 天然互斥），与 `category` / `channel` 对称。

### 3.4 素材侧的 `mode`：建议 `multi`（与另两个维度一致）

`DimensionDef.mode` 只影响**文件**打标签时的选择行为（`TagPanel` / `TagPickerModal` /
`TagManagerModal` 三个组件读它），**与任务侧无关**（任务侧永远是单列）。

| 选项 | 说明 | 我的判断 |
| --- | --- | --- |
| `multi` | 一张文件可同时贴 S 和 B | ✅ **建议**。与另两个维度零差异、不碰任何冷路径 |
| `single` | 贴一个自动替换同维度其他 | 语义更正，但这是第 14 批砍掉状态维度后**首次走single 分支**，有 latent bug 风险 |

> 老实说：单张文件同时标 S 和 B 确实别扭。但物料分级的**主要价值在任务侧**（哪个任务急），
> 文件侧是顺带的；为了一个边缘语义去激活一条三年没跑过的代码路径，不划算。
> **这一条列入待拍板项，你若坚持 `single` 我照办，但会连带把三个组件的 single 分支都测一遍。**

### 3.5 预制清单与配色

只在**空库初始化**时落（迁移 5，同另两个维度）。配色从 `PROJECT_COLORS` 池里取，
深色主题下都已验证可辨：

| 分级 | 颜色 | 理由 |
| --- | --- | --- |
| **S** | `#f0603f` 红 | 最高优先级 → 红（与「涨红」的中文习惯一致，也与业务直觉一致） |
| **A** | `#e8a33d` 橙 | 次高 |
| **B** | `#4f8cff` 蓝 | 常规 |
| **C** | `#6b7280` 灰 | 最低 / 暂不做 |

> 「S 最高、C 最低」是我们内部的约定。**如果你公司的分级习惯是 S 最低（有些体系用 S 表示
> "Standard/普通"），现在说，我调换顺序与配色。**

| --- | --- | --- |
| 新建 | `项目在左栏「所属项目 → ＋ 新建项目」里维护（可自己新增）` | 静态说明 |
| 编辑 | `这个任务现在没有项目：文件夹直接躺在工作区根目录。选一个项目就能归位。` | 动态警示（待归类时） |
| 编辑 | `任务文件夹会搬进「{name}」的项目文件夹` | 动态预告（会动磁盘） |
| 编辑 | `任务文件夹会搬回工作区根目录（待归类）` | 动态预告（会动磁盘） |

**并排后这些提示会被压进半宽列（弹窗 460px，每列约 215px），12px 字号下会换行成 2~3 行**，
且编辑弹窗那两条是「**会动磁盘**」的重要告知，压窄了不好读。

**处理办法（建议）**：提示文字**不放在自己那半列里**，改为 `.field-row` 下方**整行**显示
（仅在有提示时出现）。视觉上更清楚，也符合「重要告知值得整行」的道理。

> 备选方案 B：物料分级不跟项目并排，而是跟物料类别/使用场景并排成三列
> `[物料类别 │ 使用场景 │ 物料分级]`。这会保住项目提示的现有排版，但**与你说的
> 「与项目选择放在一起」不符**，所以我没选它。你要是改主意，说一声我改。

## 6. 标签联动（三处，与 category / channel 同一条规矩）

### 6.1 `PACK_DIM_COLUMN` 加一列

```ts
const PACK_DIM_COLUMN: Record<string, string> = {
  [CATEGORY_DIM]: 'category',
  channel: 'channel',
  grade: 'grade'// ← 本批
}
```

加完这一行，以下三处**自动生效**（它们本来就是按维度 key 写的，不是写死两个）：

| 行为 | 位置 | 效果 |
| --- | --- | --- |
| **改名联动** | `updateTag` | 分级标签改名 → 同事务把`packs.grade` 跟着改 |
| **删除联动** | `removeTag` | 删分级标签 → 用它的任务归 `未分级`，删前弹确认「目前有 N 个任务正在使用」 |
| **计数** | `listTagDimensions` | 左侧数字 = 任务数 + 文件数（第 23 拍板口径） |

### 6.2 `listTagDimensions` 的 CASE 要加一支

```sql
CASE WHEN t.dimension = 'category' THEN kp.category = t.name
     WHEN t.dimension = 'channel'  THEN kp.channel  = t.name
     WHEN t.dimension = 'grade'    THEN kp.grade    = t.name   -- ← 本批
     ELSE 0 END
```

### 6.3 任务视图筛选（`App.tsx` `shownPacks`）

```ts
const gradeNames = selectedTagObjs.filter((t) => t.dimension === 'grade').map((t) => t.name)
// 同维度「或」、跨维度「并且」—— 与现有两维完全一致
if (gradeNames.length && !gradeNames.includes(p.grade)) return false
```

## 10. ⭐ 待你拍板的4 件事

### 1. 老库要不要补灌 S/A/B/C？（最关键）

**背景**：预制标签历来**只在空库初始化时落**（迁移 5：整张 `tags` 表为空才灌全部维度）。
你的本机库已经有 18 项标签了→ **不会**自动拿到这 4 个分级 → 左栏会出现一个**空的
「物料分级」分组**，建任务时那个下拉会显示「清单为空，去左栏管理里加一个」。

| 选项 | 说明 |
| --- | --- |
| **A（我建议）** | **迁移 19 里补灌**：只在「`grade` 维度一条标签都没有」时灌 S/A/B/C（幂等）。 |
| B | 严格守老规矩，老库你去左栏「管理」里手动加 4 个。 |

**我建议 A 的理由**：那条规矩的原意是「**别覆盖用户改过的清单**」。而`grade` 是个
**全新维度**—— 不存在「用户改过的分级清单」这回事，灌 4 项不破坏任何东西。
若不灌，你第一次打开软件会看到「软件说这个维度该有值、但它没有」的错位观感。

**A 的写法也是幂等的**：只在 `SELECT COUNT(*) FROM tags WHERE dimension='grade'` = 0 时才灌，
你要是已经手动加了 4 个（或加了别的分级名），一个字节都不动。

### 2. 分级顺序与配色对不对？

S 红（最高）/ A 橙 / B 蓝 / C 灰（最低）。**若你们内部是 S 最低**，现在说，我调。

### 3. 素材侧 `mode`：`multi` 还是 `single`？

建议 `multi`（见 §3.4）。要 `single` 我也照办，但会连带测三个组件的 single 分支。

### 4. 项目提示文字移到整行，同意吗？

见 §5.3。或者你要「就让它挤在半列里」也行，说一声。

## 11. 验收标准

### 11.1 accept（档案基线 931 → 只增不减）

**维度与清单（`[42]` 段）**

- 空库初始化后 `grade` 维度有 4 项、名字与顺序为 S/A/B/C、颜色符合 §3.5
- `listTagDimensions` 里`grade` 分组出现，`mode` / `editable` 与定义一致
- 迁移 19 幂等：重复跑不重复加列、不重复灌标签

**任务侧读写**

- `createPack({ grade: 'A' })` → 落库 A；不传 → `未分级`
- `updatePack({ grade: 'S' })` → 落库 S；传空串 → `未分级`
- `movePackTo`（改名 / 换项目）**不丢** `grade`（搬完仍是原值）
- 工单自动建的任务 → `未分级`（本批不接工单侧）
- **改分级不碰磁盘**（与改类别同规矩：只有改名 / 换项目动磁盘）

**标签联动（第 10 / 23 批同款断言，换维度再来一遍）**

- 分级标签改名 → 用它的任务跟着改（同事务）
- 删分级标签 → 任务归**`未分级`**（不是「未分类」！这就是§3.2 那处改动要钉的）
- 删标签前 `tagUsage` 返回该分级的任务数
- **跨维度不误伤**：`grade` 维度有个同名标签，改/ 删它**不影响** `category` 维度的任何包
- 计数：`listTagDimensions` 的 `packCount` = 用该分级的任务数（**全库**含已解绑项目的）

**筛选语义**

- 左侧点S → 任务视图只剩 grade=S 的任务、文件视图只剩贴了 S 的文件
- 同维度多选 S+A → 两个都要（**或**）；跨维度 S + 海报 → 两个条件都要满足（**并且**）

### 11.2 界面

- `category` 场景扩断言：新建/ 编辑弹窗里**所属项目与物料分级并排**（同一 `.field-row`）
- `category` 场景扩断言：分级下拉清单与左栏维度一致（改左栏 → 这里跟着变）
- `tagcount` 场景扩断言：分级标签的数字 = 任务数 + 文件数
- `lifecycle` 场景：「可改几块」的断言数要**跟着重数**（第 47 批已因加扫描开关从 4 改成 5，本批结构又变了）
- 收尾跑全量 **12 个场景**，全部绿、控制台零报错

### 11.3 人工验收（真机，你自己做）

1. 新建任务 → 分级下拉能选 S/A/B/C，左栏「物料分级」维度同步出现这 4 项
2. 左栏点 S → 任务视图只剩 S 级任务
3. 把某个任务从 S 改成 C → 左栏 S 的数字减 1、C 加 1
4. 左栏「管理」里把 S 改名为「SS」→ 用它的任务在编辑弹窗里也显示「SS」
5. 删掉S 标签 → 弹确认「有 N 个任务正在使用」→ 确认后那些任务变「未分级」
6. 改项目 / 改名 → 分级不丢
