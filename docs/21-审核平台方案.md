## 0. 一句话

加一个「审核平台」模块：设计师把某个版本提交审核（带成品图）→ 审核人这边看到待审提示、看图、在 WorkBuddy 里让 AI 审稿出 HTML 报告、手敲评语 → 意见（报告 + 评语）回传给设计师。核心难点是「图 + HTML 报告」这类**文件**在设计师端 ↔ 审核人端之间的传输，方案倾向**企微微盘当文件通道 + 企微表当元数据通道**，零成本、复用现有 wecom-cli。

## 1. 需求源头（用户原话，2026-10-04）

> 希望加一个比较大的模块：一个审核平台。设计师认为做好一个版本后，有一个「提交」按钮；审核人这边会有一条提示，附上成品的缩略图 / 成品图；可以调用 WorkBuddy 的一些 Skill 来审，审完后返回审改意见——这个审改意见是 AI 生成的 HTML 报告 + 审核人手敲的评语。最大的问题在于文本和图像的传输，通过 wecom-cli 可能不太好实现，能不能通过其他途径（租小型服务器 / 其他方式），尽量成本低一些。先探讨可能性。

## 2. 核心结论：先厘清「AI 审稿发生在哪」

**「AI 审稿」这一步发生在审核人本机的 WorkBuddy 里**，不需要额外部署 AI 服务、不需要买模型 API：

- 审核人在软件里看到设计师交上来的图，切到 WorkBuddy 说「审一下这张图」，WorkBuddy 多模态读图 → 按标准挑问题 → 生成 HTML 报告存到本地。
- 所以整条链路真正要解决的是**「设计师端 ↔ 审核人端」之间三样东西的传输**：成品图、HTML 报告、评语文本。
- 其中**评语文本你们已经跑通了**（企微智能表格 + wecom-cli 同步 + 机器人通知，就是现在工单模块那套）。
- 唯一的新问题是：**图和 HTML 报告这类「文件」怎么传**。

## 3. 传输路线三选一（推荐 A）

### 3.1 路线对比

| 路线 | 成本 | 要新学 / 新维护 | 风险 |
|---|---|---|---|
| **A. 企微微盘 + 企微表**（推荐） | **0 元** | 无，复用现有 wecom-cli | 需实探：共享文件夹权限、上传体积上限 |
| B. WorkBuddy 云服务 | 0 元（托管，但按 app 绑定、有配额） | 引入新后端 + SDK，桌面软件要适配 | 和企微表两套中枢并存，架构变重 |
| C. 自租轻量服务器 + 对象存储 | 约 3～50 元/月 + 域名 ICP 备案 | 部署、运维、公网安全 | 备案麻烦、要自己扛安全 |

### 3.2 微盘实探结论（只读探查，2026-10-04 已做）

- wecom-cli 1.3.4 已授权，微盘能力是通的。
- 微盘里已能看到 **1.1 GB 的 Word、135 MB 的收集表**——存几十 MB 的成品图、几十 KB 的 HTML 报告毫无压力。
- 微盘 skill 明确支持 `upload`（本地文件直接传）和 `download`（按 file_id 拿回本地）——正好构成「文件中转站」。
- 权限链路干净：所有机器通过同一机器人身份调 wecom-cli，上传文件 owner 就是机器人，之后谁都能下载。

### 3.3 为什么现阶段不选 B / C

- 云服务 / 自租服务器，只有两种情况下才值得上：① 微盘实测踩坑（上传体积 / 权限有问题）；② 想要「报告点链接直接在线看」这种公网体验。
- 现阶段没必要：微盘是同一体系里唯一**零成本、零新依赖**的文件通道。

## 4. 已拍板的 4 个决策（用户已逐条确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | **审核挂载层级** | **挂在「版本」上**——每个版本（V1/V2/V3）独立提交审核，审核状态跟版本走；退回后出新版本再交，旧版本及每次意见留痕 |
| 2 | **审核人** | **一人审**（= 用户本人），设计师只负责交，不搞多级会签 / 互相审 |
| 3 | **退回流转** | **退回后出新版本**（V+1）再交，旧版本 + 历史审核意见都保留可查 |
| 4 | **AI 审稿触发** | **WorkBuddy 手动审**——切到 WorkBuddy 说「审一下这张图」，我读图出 HTML 报告存本地；回软件点「返回意见」选报告 + 填评语。零额外开发、最灵活 |

> 审核状态建议跟「版本」走：每个版本可「提交审核」，状态机大致为 `待提交 → 待审核 → 通过 / 需修改`；退回后设计师出新版本再交，旧版本的状态和意见留痕。

## 5. 完整数据流（一圈）

1. **设计师端**：版本详情点「提交审核」→ 软件取该版本第一张图做缩略图（可手动换主图）→ 传微盘 → 在企微表写一条审核记录（版本、提交人、图 ID、说明）→ 机器人通知审核人。
2. **审核人端**：顶栏出现「待审核」徽标 + 通知 → 进审核视图 → 详情里看图（软件按图 ID 从微盘下载到本地缓存）→ 切到 WorkBuddy 说「审这张图」→ 出 HTML 报告存本地。
3. **审核人回软件**：点「返回意见」→ 选刚才那份 HTML 报告 + 手敲评语 → 报告传微盘 → 写回企微表 → 状态置「通过 / 需修改」→ 通知设计师。
4. **设计师端**：同步 → 看结果 + 下载报告 + 读评语 → 需修改就出新版本（V+1）再提交，旧版本和每次意见都留痕。

## 6. 骨架复用 vs 新增

**大量复用现有工单模块骨架**（企微表同步 + 本地 SQLite + 机器人通知 + 列表/详情 UI + 状态机）。

**新增两块**：
1. **微盘上传 / 下载**（文件通道，包一层 `upload` / `download`）。
2. **缩略图 / 报告展示**（详情里的成品图、HTML 报告的查看 / 下载）。

## 9. 刻意不做（当前讨论范围）

- 不做「软件内一键 AI 审」（自动触发 WorkBuddy / 内嵌模型 API）——先按手动审跑通，以后可升级。
- 不做多级会签 / 设计师互相审（审核人 = 一人）。
- 不做公网在线预览报告（那是走路线 B / C 才考虑的事）。
- 版本号、迁移号、落库表结构：留待正式施工方案再定（本稿只锁方向，不锁实现细节）。
