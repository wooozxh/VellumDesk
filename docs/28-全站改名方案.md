# 全站改名方案（VellumDesk / Vellum工作台）

> 用户要把"库名、分支名、软件名、安装包名、安装包文件夹名、路径名、软件内显示名"全部规范化。
> 本文是执行蓝图：列出**旧 → 新**对照、逐文件改动点、Git/GitHub 操作、执行顺序、风险与验收。
> 所有名字已由用户拍板，本文确认后即可按阶段执行。

## 一、最终命名对照表

| 维度 | 旧值 | 新值 |
| --- | --- | --- |
| 产品中文名（界面/窗口/快捷方式/卸载/安装目录） | 营销中心-素材库 | **Vellum工作台** |
| 英文标识（exe 名） | MediaButler | **VellumDesk** |
| appId | com.mediabutler | **com.vellumdesk** |
| 安装包文件名 | 营销中心-素材库-{v}-安装包.exe | **VellumDesk-{v}-Setup.exe** |

## 二、代码改动点（逐个文件）

| 文件 | 改什么 |
| --- | --- |
| `package.json` | `productName` → Vellum工作台；`build.appId` → com.vellumdesk；`win.executableName` → VellumDesk；`nsis.shortcutName` / `uninstallDisplayName` → Vellum工作台；`nsis.artifactName` → `VellumDesk-${version}-Setup.${ext}`。**只动 build 字段，不动 dependencies / scripts，package-lock.json 不动。** |
| `src/shared/copy.ts` | `COPY.app.name`：'营销中心-素材库' → 'Vellum工作台'（窗口标题 / 顶栏 logo / 异常弹窗标题的唯一来源）。其余「素材工作区」等功能文案**保持**（是功能概念，非品牌名）。 |
| `src/renderer/index.html` | `<title>` → Vellum工作台（兜底，实际会被窗口标题逻辑覆盖）。 |
| `src/main/index.ts` | `setAppUserModelId('com.mediabutler')` → 'com.vellumdesk'；`userData` 目录 'proj_media' → 'vellumdesk_project'；相关注释同步。 |
| `src/main/workspace.ts` | `DEFAULT_WORKSPACE` → `'D:\\vellum_workspace'`；`FALLBACK_FOLDER_NAME` → 'vellum_workspace'；注释同步。 |

> 磁盘内部目录名（`01-成品` / `_回收站` / 数据库状态值等）**一律不动**——它们是数据约定，改了软件会找不到文件（copy.ts 头注释已明确）。

## 三、Git / GitHub 操作

1. **合并主线**：`main` 当前停在 1.1.0，落后 37 个提交；`feature/wecom-bundle` 是它的严格超集。
   → `git checkout main && git merge --ff-only feature/wecom-bundle`，main 直接前进到最新（1.8.1）。
2. **删废弃分支**（本地 + 远程）：`TM`、`feature/export-report`、`feature/multi-designer`、`feature/purge-disabled-sheet`、`feature/incr`、`feature/wecom-bundle`（合并后删）。
   均已合进主线，删了不丢任何提交。
3. **仓库重命名**：`media-lib_zxh` → `VellumDesk`（GitHub API `PATCH /repos` 改 `name`；旧链接会自动 301 重定向）。
4. **更新本地 remote**：`git remote set-url origin https://github.com/wooozxh/VellumDesk.git`。
5. **默认分支**：确认仍是 `main`（`origin/HEAD -> main` 已满足）。

## 四、执行顺序（四阶段，每阶段独立可回退）

- **阶段 1 · 代码改名**（纯本地，未提交前随时回退）：改上面 5 个文件 → `npm run typecheck` 0 错。
- **阶段 2 · 出包验证**：出包，核对 `VellumDesk.exe`、`VellumDesk-1.8.1-Setup.exe`、快捷方式/安装目录 = Vellum工作台 → 裸启动冒烟。
- **阶段 3 · 提交 + 分支整理**：commit 改名 → 合并 wecom-bundle 进 main（ff）→ 删废弃分支 → push main。
- **阶段 4 · 仓库重命名 + 文档**：GitHub 重命名 VellumDesk → 更新本地 remote → 更新 README / NEXT / docs/25 / docs/27 等活跃文档里的软件名 → commit + push。

## 五、风险与副作用（老用户）

| 项 | 影响 | 对策 |
| --- | --- | --- |
| userData 目录 proj_media → vellumdesk_project | 老用户升级后工作区配置"看似丢了"，需重选一次工作区位置（**数据不丢**） | 装机面小（本机 + 同事测试机），代价可控；README 里写一句升级提示 |
| appId com.mediabutler → com.vellumdesk | 老用户任务栏图标分组可能"分裂"、通知归属变 | 装机面小，可接受 |
| 仓库重命名 | 第三方引用旧 URL 会 301 重定向，基本无感 | 更新本地 remote 与文档链接 |
