# 第 52 批：物料分级改名（S/A/B/C → S-核心 / A-重要 / B-常规 / C-待办）方案

## 1. 需求

用户 2026-10-08 提出：把第 49 批落地的物料分级 `S` / `A` / `B` / `C`
改成**带中文含义**的名字，减少"光看字母不知道啥意思"的沟通成本：

| 旧 | 新 |
|---|---|
| `S` | `S-核心` |
| `A` | `A-重要` |
| `B` | `B-常规` |
| `C` | `C-待办` |

> 用户原话写的是「C-代办」，经确认是笔误，**应为「C-待办」**。

## 2. 为什么不能只改文案常量（关键）

分级的名字在库里**有两处**，只改种子常量只能影响**新库**：

| 位置 | 说明 |
|---|---|
| `tags.name`（`dimension='grade'`） | 分级标签本身的行 |
| **`packs.grade`** | **存的是标签名字符串，不是外键！** |

第 49 批的设计是 `packs.grade TEXT NOT NULL DEFAULT '未分级'` ——
**直接存名字**（与 `category` / `channel` 同款做法）。

第 49 批的补灌门槛是「该维度一条标签都没有」，所以：
**老库既不会重新灌种，也不会自动改名** —— 不改迁移的话，
老库里标签仍叫 `S`，而新代码的种子叫 `S-核心`，两边对不上。

**已核实用户真库现状**（`D:\vellum_workspace`）：

```
tags(dimension='grade')  →  (20,'S') (21,'A') (22,'B') (23,'C')
packs.grade              →  'B' × 1     ← 真实数据，必须一起迁
```

## 3. 做什么

### 3.1 种子常量（影响新库）

`src/shared/copy.ts` 的 `seed.gradeS/A/B/C` 改成新名。
`TAG_DIMENSIONS` 的 grade `presets` 引用这几个常量，自动跟着变（不用改）。

### 3.2 迁移 20：老库改名（**幂等 + 防越界 + 防撞名**）

一条迁移同时处理两处：

1. `tags`：`S`→`S-核心`、`A`→`A-重要`、`B`→`B-常规`、`C`→`C-待办`（限 `dimension='grade'`）
2. `packs`：`grade` 列里同样的四个值一起改

三条硬约束：

- **只认精确旧名**：只改名字**恰好等于** `S`/`A`/`B`/`C` 的行。
  用户若已自己改成 `S-紧急` 之类，**一个字节都不动**（沿用第 49 批"不覆盖用户改动"的口径）。
- **防撞名**：`tags` 有 `UNIQUE(dimension, name)`。若目标名**已存在**
  （理论上不该有，但不做假设）→ **跳过这一条**，否则 UPDATE 会抛唯一约束错误，
  整个迁移连带失败。
- **幂等**：跑第二遍时旧名已不存在 → 匹配 0 行 → 无副作用。

### 3.3 不做

- 不改 `UNGRADED`（`'未分级'`）—— 它本来就有中文，语义也对
- 不改 `category` / `channel` 的任何标签名
- 不改分级的**颜色**（`#f0603f` / `#e8a33d` / `#4f8cff` / `#6b7280` 照旧）
- 不碰 `assets` / `asset_tags` —— 它们按 **tag_id** 关联，改名不影响

## 4. 验收口径

**accept**

- 新库：4 个预制分级标签的名字 = 新名（断言改为引用 `COPY.seed.gradeX`，**不再硬编码**）
- **迁移**：布景一个"老库"（标签名是旧的 `S/A/B/C` + 一个包 `grade='B'`）→ 跑迁移 →
  - 标签名变成新名
  - **`packs.grade` 从 `'B'` 变成 `'B-常规'`**（这是最容易漏的一处）
- **幂等**：再跑一次 → 无变化
- **不越界**：用户自己改过的名字（如 `S-紧急`）不被覆盖
- **防撞名**：已存在目标名时不抛异常、跳过该条
- 建包/改包仍能正常按新名存取 (`packs.grade === 'S-核心'`)

**界面场景**

- 左栏「物料分级」4 个标签显示为新名
- 建/编辑任务弹窗的分级下拉里是新名
