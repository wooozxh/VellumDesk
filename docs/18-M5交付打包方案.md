# 18 · M5 交付打包方案

> 需求来源：用户 2026-10-01 口述 + 需求文档 5.5 M5 交付打包
> 状态：**已定稿，进入开发**
> 对应 `PROJECT.md` 铁律第 ③ 步产物

---

## §0 一句话

设计师做完一项任务后，在任务详情里点「打包交付」，按**版本 + 分组 + 文件**三级的粒度选择要交付的内容，软件把它打成一个按规则命名的 zip 压缩包，存在用户指定的位置，同时留下一条**交付记录**。

---

## §1 给谁用、解决什么问题

| 角色 | 场景 | 痛点 |
|---|---|---|
| 设计师 | 海报/折页定稿后发给印厂 | 手动从 `01-成品` 里挑文件、改文件名、拖进压缩包，容易漏带源文件或带错旧版 |
| 设计师 | 把一稿成果交给运营/领导 | 不知道当前该交哪一版，命名混乱 |
| 接收方（印厂/领导/同事） | 打开压缩包 | 希望一眼看到「这是哪个项目、哪个任务、哪一稿」 |

目标：**减少人工挑选和命名出错，让「交付哪一稿、交哪些文件」在软件里点几下就确定。**

---

## §2 入口与触发

在**包详情弹窗**（`PackDetailModal`）顶部操作区增加一个「**打包交付**」按钮，与现有「编辑任务信息」「打开文件夹」并列。

```
┌─────────────────────────────────────────────────────────────┐
│  海南招生海报-2026秋季                                        │
│  所属项目：海南升学规划中心    类别：海报                       │
│  共 12 个文件 · 86 MB    · 创建于 2026-09-30 14:32            │
│                                            [编辑] [打开文件夹] [打包交付]
└─────────────────────────────────────────────────────────────┘
```

为什么不放在包卡片上：
- 打包前用户必须确认**版本、分组、具体文件**，这些细节在卡片层展不开；
- 包详情已经是版本管理的主战场，打包面板从这儿进入最自然。

## §3 打包面板（PackExportModal）

弹窗标题：**打包交付 —— 任务名**

面板分四块：

### 3.1 版本选择

| 选项 | 说明 |
|---|---|
| **当前版本（默认）** | 这个任务的 `is_current = 1` 的那一稿；老包无版本时此选项不可用 |
| **指定版本** | 下拉列出该任务所有稿（V3 / V2 / V1 / 未分版本），按 seq 倒序 |
| **全部版本** | 把整个任务所有稿都打进包 |

> 老包（无版本记录）→ 默认选中「未分版本」，等价于只打包包根三组。

### 3.2 分组选择

四个复选框：

- [x] 成品（`01-成品`）
- [x] 素材（`02-素材`）
- [x] 工程文件（`03-工程`）
- [ ] 未归属的文件

**默认前三项全勾，未归属不勾。** 理由：交付给印厂通常只要成品 + 工程源文件 + 参考素材；未归属文件是用户还没整理好的，不该默认交付。

至少勾一个分组，否则「打包」按钮禁用。

### 3.3 文件明细

根据上面两维选择，实时列出会打进包里的文件清单：

```
成品（3 个文件 · 24 MB）
  □ 海南招生海报-最终稿.jpg
  □ 海南招生海报-竖版.jpg
  □ 海南招生海报-横版.jpg
素材（2 个文件 · 8 MB）
  □ 参考图-清华校门.jpg
  □ 字体-思源黑体.otf
工程文件（1 个文件 · 156 MB）
  □ 海南招生海报-最终稿.psd
```

- 默认**全勾**；
- 用户可取消某一条；
- 分组标题上的复选框可**全选/取消全选**该分组；
- 已丢失的文件（`missing_at IS NOT NULL`）**列出但默认不勾、置灰**，旁边提示「文件已丢失」。

### 3.4 输出设置

| 项 | 默认值 | 可改 |
|---|---|---|
| **压缩包名称** | 见 §4.1 命名规则 | 是，文本框 |
| **保存位置** | **任务包所在目录**（该 pack 的物理根目录） | 是，点「浏览」选其他目录 |
| **尺寸** | 从当前版本文件元数据自动抓取（如首张成品的宽×高） | 是，可手动输入 / 覆盖 |
| **保留原文件名** | 勾选 | 是，复选框 |
| **包内顶层文件夹** | 压缩包同名文件夹 | 是，可改为无顶层文件夹 |

底部显示：**预计 {n} 个文件 · {size} MB · 输出到 {路径}**

> **尺寸字段**：优先从当前版本文件里读（图片/PSD 的宽高）。如果当前版本没有可读尺寸的文件，或读出来不一致，面板里显示输入框让用户填，用于生成 zip 名和内部文件名。

> 默认放在任务包目录，是因为设计师打包后通常就地审一下、再复制给印厂/领导，符合"软件里看到的 = 硬盘上真实的"这条铁律。

## §4 命名规则

### 4.1 压缩包默认名

```
{项目名}-{任务名}-{尺寸}-{打包日期}-{版本}.zip
```

示例：`海南升学规划中心-海南招生海报-2026秋季-1920x1080-20261001-V3.zip`

规则细节：
- `{项目名}`：任务所属项目名；无项目（待归类）时省略该段及后面的 `-`；
- `{任务名}`：包的 `name`；
- `{尺寸}`：用户指定或自动抓取的尺寸，如 `1920x1080`；无法确定时显示 `未知尺寸`；
- `{打包日期}`：`YYYYMMDD` 格式本地日期；
- `{版本}`：
  - 当前版本 / 指定某一版本 → `V3`；
  - 未分版本 → `未分版本`；
  - 全部版本 → `全版本`；
- 非法文件名字符（`\\/:*?"<>|`）替换为 `_`；
- 如果生成名与目标目录已有文件重名，末尾加 ` (1)`、` (2)` 递增，**不覆盖**。

### 4.2 压缩包内文件路径

包内保持一层与压缩包同名的根目录，其下只生成被勾选的分组文件夹：

```
海南升学规划中心-海南招生海报-2026秋季-1920x1080-20261001-V3/
├─ 成品/                              ← 仅勾选了「成品」才生成
│  └─ 海南招生海报-2026秋季-1920x1080-V3-最终稿20261001.jpg
└─ 素材/                              ← 仅勾选了「素材」才生成
   └─ 海南招生海报-2026秋季-1920x1080-V3-参考图20261001.jpg
```

- 单版本 / 未分版本打包 → 根目录下直接是「成品」「素材」「工程」文件夹；
- 全部版本打包 → 根目录下先按版本分 `V1/`、`V2/`、`V3/`、`未分版本/`，版本内再按分组放；
- 只勾选哪些分组，就只生成哪些文件夹。

### 4.3 包内文件重命名规则

默认规则：

```
{任务名}-{尺寸}-V{n}-{原文件名主干}{打包日期}.{扩展名}
```

示例：`海南招生海报-2026秋季-1920x1080-V3-最终稿20261001.jpg`

规则细节：
- `{任务名}`：包的 `name`；
- `{尺寸}`：用户指定或自动抓取的尺寸；
- `-V{n}`：
  - 当前版本 / 指定某一版本 → `-V3`；
  - 未分版本 → 省略 `-V{n}`；
  - 全部版本 → 文件放在对应版本文件夹下，命名里仍用该文件所属版本号；
- `{原文件名主干}`：原文件名去掉扩展名；
- `{打包日期}`：`YYYYMMDD`；
- **保留原文件名** 复选框：
  - **勾选（默认）**：使用上述规则，保留原文件名主干；
  - **不勾选**：使用 `{任务名}-{尺寸}-V{n}-{序号}{打包日期}.{扩展名}`，序号从 `01` 开始；
- **自定义文件名**：面板允许用户为整个包输入一个自定义文件名模板，覆盖默认规则，用于特殊交付场景；
- 非法文件名字符（`\\/:*?"<>|`）替换为 `_`；
- 扩展名保留原样；
- 同名冲突自动加 `(1)`、`(2)`，不覆盖；
- 若原文件名为空，用 `未命名` 作为主干。

## §5 打包流程

1. 用户点「打包交付」→ 弹出 `PackExportModal`；
2. 界面用 `packDetail` 拿数据，本地渲染可选范围；
3. 用户确认选择 → 点「开始打包」；
4. 主进程执行 `pack:export`：
   - 校验目标目录可写；
   - 校验至少选一个文件；
   - 检查所选文件是否全部存在（丢失的不允许勾选，所以这里只是防御性校验）；
   - 如用户未手动指定尺寸，尝试从所选图片/PSD 文件读取尺寸作为默认值；
   - 按 §4.1 / §4.3 规则生成 zip 名和内部文件名（支持用户自定义模板覆盖）；
   - 用 `archiver` 创建 zip，按 §4.2 组织目录结构，文件重命名后追加；
   - 生成压缩包；
   - 写入交付记录（§6）；
5. 返回 `{ ok, outputPath, fileCount, totalSize }`；
6. 界面 toast「已打包到 {路径}」，并给「打开文件夹」「打开压缩包」两个按钮。

## §6 交付记录（M6-07 的第一步）

第 9 批版本管理已在 `pack_versions` 表预留 `delivered_at` 字段。本批把它用起来。

新增表 `delivery_records`：

```sql
CREATE TABLE IF NOT EXISTS delivery_records (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  pack_id       INTEGER NOT NULL REFERENCES packs(id) ON DELETE CASCADE,
  version_id    INTEGER REFERENCES pack_versions(id) ON DELETE SET NULL,
  -- 打包范围：JSON 数组 ["成品","素材","工程"]
  scope_json    TEXT    NOT NULL,
  -- 实际打包的文件清单（相对路径数组），用于以后对账
  files_json    TEXT    NOT NULL,
  output_path   TEXT    NOT NULL,
  output_size   INTEGER NOT NULL DEFAULT 0,
  file_count    INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT    NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_delivery_records_pack ON delivery_records(pack_id);
```

同时更新对应 `pack_versions.delivered_at`（最新一次交付时间），用于：
- 包卡片上给已交付版本挂绿标（第 9 批已留口）；
- 版本条上显示「已交付」标记。

> 不写入 `packs` 表任何字段，因为交付是「针对某一稿」的动作。

## §8 边界情况

| 情况 | 处理 |
|---|---|
| 任务没有任何文件 | 「打包交付」按钮可用，但面板里文件列表为空，打包按钮禁用，提示「这个任务里还没有文件可打包」 |
| 任务只有未归属文件 | 默认分组前三项无文件，未归属复选框可勾；用户可只打包未归属 |
| 当前版本被解绑 / 文件夹已不在 | 版本下拉里仍显示但标灰；选择它时提示「该稿文件夹已不在磁盘上，无法打包」 |
| 所选文件在打包前被删除 | 校验阶段发现缺失 → 返回错误，不生成半成品压缩包 |
| 目标目录不可写 | 返回明确错误 |
| 目标文件名已存在 | 自动加 `(1)` 递增，不覆盖 |
| 打包过程中用户关闭软件 | 不保证完整性，但 zip 流关闭时会生成可识别的未完成文件；下次用户可手动删除 |
| 全部版本打包但某些稿文件夹已不在 | 跳过该稿并提示；其余正常打包 |
| 单文件大小超过 zip 限制 | archiver 使用 store/zip64 默认支持大文件；出错时返回错误 |
