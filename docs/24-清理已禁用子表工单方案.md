## 0. 一句话

工单设置里关掉某个子表后，**"以后不再从这个子表同步"** 是生效的，但**已经同步进本地的工单不会被清掉**——列表里仍旧混着它们，而且全项目**没有任何入口能清**。本批补一个"清理已禁用子表工单"的能力：在工单设置里一键把**已关闭子表**同步进来的工单从本地库移除（先留痕备份、有任务包的跳过不删）。

## 1. 需求源头（用户反馈 + 排查结论，2026-10-04）

> 我在工单同步设置里把生产数据的两个子表都关掉了，只留了工单测试子表。但同步工单之后还是出现了 200 多条工单数据——是我哪里没操作好，还是业务逻辑写的不对，还是软件有 bug？

排查结论（读真实库 + 读代码，均已实证）：

| 疑问 | 结论 |
|---|---|
| 设置保存了吗 | ✅ 已保存且生效：配置里两个生产子表 `enabled=false`、测试子表 `enabled=true` |
| 筛选逻辑对吗 | ✅ 对：`detectStructure` 里 `if (!cfg.enabled) continue` 正确跳过禁用子表 |
| 最近一轮同步拉了吗 | ✅ 只拉了测试子表：两个生产子表所有行的 `last_sync_at` 停在上一轮时间，测试子表的 10 条刷新到最近一轮 |
| 那 259 条为什么还在 | ❌ **因为同步"只增不删"**——旧工单永久留在本地库，列表照常显示（合计 269 条） |
| 是 bug 吗 | 严格说**不是 bug，是设计缺口**：关闭子表的语义没有和"清空该子表的本地数据"分开，也没有任何清理入口 |

两条根因（代码位置）：

1. **同步不做全库对账**：`applySync` 只处理本轮 payload 里的记录，禁用子表不参与本轮。
2. **删行检测有范围限制**：那段"record_id 消失就标 `row_gone`"的逻辑，只在**本轮拉取过的子表**范围内跑（`liveSheetIds`）；禁用子表不在范围里 → 它的工单既不删也不标失效。

用户拍板：**加「清理已禁用子表工单」功能**（不是手动删一次），一劳永逸，以后随时能切干净 / 切回来。

## 2. 方案设计

### 2.1 数据：迁移 16 —— `tickets.sheet_title`

**问题**：`tickets` 表只有 `sheet_id`（出生地指纹），而用户在设置里勾选/取消的粒度是**子表标题**。且 `sheet_id` 在子表重建后会漂移（`detectStructure` 每轮回写新指纹）——拿它做清理匹配不稳。

**做法**：

- `ALTER TABLE tickets ADD COLUMN sheet_title TEXT`（缺列才加，幂等，沿用迁移 8/9/13/15 范式）。
- **一次性回填**：用当前配置里「`sheet_id` → 标题」的映射，把历史行的 `sheet_title` 补上（只回填 `sheet_title IS NULL` 的行，重复启动不重跑）。
- **新增写入点**：`applySync` 的 insert / update 语句带上 `sheet_title`（`SheetPayload` 里本来就有 `title`，零额外请求）。

> 回填是"尽力而为"：如果某个历史工单的 `sheet_id` 在当前配置里已经找不到（子表被删过且没同步过），它的 `sheet_title` 留空 → 清理时**不匹配、不删**（宁可留着，不可误删）。

### 2.2 引擎：`purgeDisabledSheetTickets()`（纯逻辑，不碰网络）

放在 `tickets.ts`，与同步引擎同层：

```
输入：workspaceRoot
① 读配置 cfg.sheets → disabledTitles = 所有 enabled=false 的标题
② disabledTitles 为空 → 直接返回 {removed:0, ...}（不建备份文件）
③ 选出候选：SELECT * FROM tickets WHERE sheet_title IN (disabledTitles)
④ 分流：
   - pack_id IS NULL  → 待删
   - pack_id 非空     → **跳过**（计入 skippedPacked）
⑤ 留痕：把待删工单的完整行 + 关联的设计师子表 / 本地扩展字段
        写成 _system/backup/tickets-<时间戳>.json（照 backupPackRecords 路数）
⑥ 单事务删除：tickets（级联带走设计师子表）+ 手动清本地扩展字段
⑦ 返回 { removed, skippedPacked, sheets: disabledTitles, backupPath }
```

**为什么有任务包的跳过**：`tickets.pack_id` 是 `ON DELETE SET NULL`——删工单会把任务包的关联抹掉，而任务包本身还在磁盘上（软件的"永远不悄悄扔掉用户放的东西"原则）。跳过 + 明确告知，比静默断链稳。

### 2.3 IPC 两个口

| 通道 | 作用 |
|---|---|
| `ticket:purgePreview` | 只算不删：返回 `{ removable, packedSkipped, sheets[] }`——给二次确认弹窗用 |
| `ticket:purgeDisabled` | 真删：走引擎，返回 `{ removed, skippedPacked, backupPath }` |

### 2.4 界面：工单设置弹窗底部「危险操作」区

- 一行说明：**已关闭的子表**：印刷物料、电子物料（按**已保存的**配置算，不按弹窗里未保存的草稿）。
- 一行计数：其中 N 条工单会被清理、M 条有任务包会跳过。
- 按钮「清理这些工单」→ 先 `purgePreview` → 二次确认弹窗（列出将删条数 / 跳过条数 / 涉及子表）→ 确认才执行 → 结果提示（已清理 N 条，备份在 `_system/backup/…`）。
- 草稿与已保存配置不一致时，按钮置灰并提示「请先保存子表设置」。

### 2.5 安全边界（硬规矩）

| 边界 | 处理 |
|---|---|
| 备份 | 删前必写 `_system/backup/tickets-<时间戳>.json`（完整行 + 关联子表），**永不自动删除** |
| 有任务包 | **跳过不删**，计数回报，绝不悄悄断链 |
| 已启用子表 | **绝不碰**（只清 `enabled=false` 的标题） |
| 标题匹配不上 | `sheet_title` 为空的历史行 → 不删（宁可留着） |
| 无禁用子表 | 返回 0，不建备份文件、不弹确认 |
| 磁盘文件 | 全程不碰（工单是本地镜像，没有对应文件） |

## 3. 本批不做

- **改同步引擎的"只增不删"语义**（本轮不做；是否要让"子表里删了行"自动清本地，属另一议题）。
- **界面上显示工单来自哪个子表 / 按子表筛选列表**（顺手能加，但不在本批范围）。
- **清理已启用子表的工单**（危险且无需求）。
- **有任务包的工单怎么清**（本批跳过；如将来要做，需先定"包要不要一起走"）。

## 4. 验收计划（铁律三件套）

- **accept 断言**（新增一段，纯逻辑喂假数据）：
  - 迁移 16：`sheet_title` 列存在 + 历史行回填正确（按配置映射）+ 幂等（重跑不重复）。
  - `purgeDisabledSheetTickets`：
    - 禁用子表无包 → 删掉、计数对；
    - 禁用子表**有包** → 跳过、`skippedPacked` 计数对、行还在；
    - **启用**子表的工单 → 一条不动；
    - `sheet_title` 为空的历史行 → 不删；
    - 无禁用子表 → 返回 0 且不生成备份文件；
    - 备份 JSON 生成且内容完整（含完整行 + 设计师子表 + 本地扩展字段）；
    - 级联：设计师子表随工单一起消失、本地扩展字段一起清；
  - 断言**只增不减**（现有断言一条不许少）。
- **界面场景**（`_shotapp`）：工单设置弹窗出现「危险操作 / 清理」区块与按钮，形态断言。
- **typecheck 0 错** + 三个 bundle 重打。

## 5. 待用户拍板的点

1. **有任务包的工单**：本方案是"跳过不删"。若你希望"连任务包关联一起清（工单删、包留但变成无单状态）"，说一声，我改成删。
2. **入口位置**：放「工单设置」弹窗底部（本方案），还是放工单面板顶栏（和「导出报表」并列）？
3. **工单编号**：是否需要"保留测试单"开关（比如按编号前缀排除）？目前不做，全部按子表来源判定。
