## 一、这一版的目标：能汇报的原型，不是能用的软件

**用户明确表态（2026-09-24）**：要先快速拿到一个**能向领导讲清楚整个逻辑**的原型，不是先要一个扛得住量产的工具。

因此第 1 批的范围判断标准只有一条：**这条功能能不能在演示里被指着讲出来？**

- 能讲出来 → 做
- 讲不出来（性能、异常、批量）→ 不做

## 二、核心概念修订：包（任务包）

### 2.1 包的定位

**这是本次方案最大的改动，也是用户主动提出的业务要求。**

需求文档第四章把「素材」和「物料」定为并列两个概念。本方案在其上增加一个**容器**：

> **包（任务包）= 一次工作任务的容器。** 一个包对应硬盘上一个文件夹，里面装着这次任务用到的全部文件。

**包的设计初衷是"管住同事"**：新任务开工时，先在软件里建一个包，软件随即在硬盘上建好文件夹；之后所有产出都往这个文件夹里丢。**规矩由目录结构承载，不靠培训。**

### 2.2 包从哪来：先建包，不是扫出来

| | 旧路径（需求文档 M1 隐含） | 新路径（本方案） |
|---|---|---|
| 起点 | 硬盘上已有文件 | 软件里先建包 |
| 过程 | 扫描 → 平铺 → 事后按规则分组 | 建包 → 长出文件夹 → 往里丢 |
| 包的可靠性 | 靠猜，容易猜错 | 目录结构本身就是规矩，不用猜 |

### 2.3 包内的三组

包文件夹下自动创建三个子文件夹，**由软件在建包时自动创建，同事不需要自己建**：

| 子文件夹 | 装什么 | 自动归类规则 |
|---|---|---|
| `01-成品` | 可对外交付的成片 / 成图 | 放进这里的即成品 |
| `02-素材` | 做它用到的参考图、字体、图标 | 放进这里的即素材 |
| `03-工程` | 可编辑源文件 | 放进这里的即工程文件 |

**归类规则的关键决定：按"放在哪个子文件夹"判定，不按文件后缀猜。**
理由：后缀猜错率高（`.psd` 可能只是参考图），而"放在哪"是人的明确表达，零歧义。**后缀仅用于兜底**——若用户把 `.psd` 丢进 `01-成品`，仍按所在文件夹归类。

### 2.4 未归属池

**这是"同事不按培训做"的解药。**

- 素材工作区根目录下、未放进任何包文件夹的文件 → 全部进「**未归属**」
- 不报错、不丢弃，只是**待整理清单变长**
- 在文件视图里可以**选中若干 → 一键认领进某个包**

> 设计原则：**软件永远不悄悄扔掉用户放的东西。** 偷懒的最坏结果是多一条待办，不是数据脏掉。

### 2.5 一个包允许多个成品

一个项目常同时交"横版海报 + 竖版海报"，硬卡一个成品会很难用。**允许多个，不做数量限制。**

## 三、主界面：双面板

### 3.1 两个面板，两种问法

| 面板 | 回答的问题 | 对应需求文档 3.2 节 |
|---|---|---|
| **包视图** | "海南那个海报改完没？" | 交得出、追得回 |
| **文件视图** | "那张蓝色背景图在哪？" | 找得到 |

**两个面板不是两套数据**：包视图里的「12 个文件」，就是文件视图里归在该包名下的那 12 个。改一边，另一边立即同步。

### 3.2 界面结构

```
┌──────────────────────────────────────────────────────┐
│  [搜索文件名…]        [包视图 / 文件视图]  [＋ 新建任务包] │
├────────────┬─────────────────────────────────────────┤
│ 所属项目    │   主面板                                 │
│  全部       │   ┌────────┐ ┌────────┐ ┌────────┐      │
│  规划中心   │   │ 包卡片  │ │ 包卡片  │ │ 未归属  │      │
│  集训营     │   └────────┘ └────────┘ └────────┘      │
│  集团通用   │                                         │
├────────────┴─────────────────────────────────────────┤
│  共 N 个包 / N 条素材 · 共 X GB      按更新时间 ↓      │
└──────────────────────────────────────────────────────┘
```

### 3.3 包卡片长什么样

```
┌──────────────────────┐
│   [封面缩略图]        │  ← 取包内第一个成品的缩略图
│   海南招生海报 v3      │
│   12 个文件 · 86 MB   │
│   规划中心 · 海报      │  ← 项目标签 · 类别标签
└──────────────────────┘
```

### 3.4 点开一个包

面板右侧滑出详情（或进入整页），结构：

```
海南招生海报 v3
─ 所属项目：海南升学规划中心      类别：海报
─ 成品（1）     ← 缩略图列表
─ 工程文件（2）  ← 文件列表
─ 素材（9）      ← 缩略图列表
─ 未归属的文件（0）
```

**「未归属的文件」是本包内的一层保险**：直接丢在包文件夹根目录、没进三个子文件夹的文件，显示在这里，可一键移动进对应组。

## 四、建包流程

| 步骤 | 用户动作 | 软件动作 |
|---|---|---|
| ① | 点「＋ 新建任务包」 | 弹窗 |
| ② | 填包名称、选所属项目、选物料类别 | — |
| ③ | 点「创建」 | **在素材工作区下创建文件夹**，并自动建 `01-成品` / `02-素材` / `03-工程` 三个子文件夹 |
| ④ | — | 弹出提示"文件夹已建好，点这里打开" |
| ⑤ | 同事往三个子文件夹里丢文件 | — |
| ⑥ | — | 丢进去的文件**自动归位**到对应组（靠 M1-09 监控文件夹） |

**第 1 批的简化处理**：监控文件夹（M1-09，需求文档标 P1）在第 1 批用**手动「刷新扫描」按钮**代替自动监控。
理由：自动监控要引入 `chokidar` 并处理文件占用、写入未完成等大量异常；而汇报演示时点一下"刷新"完全不掉份。**自动监控挪到第 3 批。**

## 五、第 1 批：做什么、不做什么

### 5.1 做

| 编号 | 内容 |
|---|---|
| A-01 | 新建任务包（名称 + 项目 + 类别）→ 自动建文件夹结构 |
| A-02 | 素材工作区目录的首次初始化 |
| A-03 | 扫描包文件夹，按所在子文件夹归入三组 |
| A-04 | 采集文件基础信息：文件名、扩展名、体积、创建/修改时间 |
| A-05 | 图片缩略图生成（`sharp`） |
| A-06 | 包视图：包卡片列表 + 条数 + 总容量 |
| A-07 | 文件视图：全部文件平铺 + 「未归属」池 |
| A-08 | 点开包 → 三组展开 |
| A-09 | 文件视图里选中若干 → 一键认领进包 |
| A-10 | 手动「刷新扫描」按钮 |
| A-11 | 双击文件 → 调用系统默认程序打开（成本极低，顺手带上） |

### 5.2 不做（明确记录，避免后面反复讨论）

| 推迟项 | 原因 | 挪到 |
|---|---|---|
| 大批量性能（500 张 / 60 秒） | 汇报原型不需要 | 第 4 批 |
| 拖拽入库（M1-01） | 选文件夹足够演示 | 第 3 批 |
| 进度条 / 中途取消（M1-08） | 同上 | 第 4 批 |
| 视频缩略图（M1-06 视频部分） | **本机 FFmpeg 未安装** | 装完 FFmpeg 后 |
| PDF / PSD 缩略图 | 同上，解析库需额外引入 | 第 2 批 |
| 内容指纹去重（M6-08） | 属第二步 | 第二步 |
| 索引 / 托管双模式（M1-03） | **本方案默认全是托管模式**（文件在包文件夹里），索引模式已无必要 | 视需要再议 |
| 标签体系完整体（M2 五维度） | 第 1 批只落「项目 + 类别」两维 | 标签专项 |
| 版本管理（M6） | 第二步 | 第二步 |
| 打包交付（M5） | 第二步 | 第二步 |
| 自动监控（M1-09） | 用「刷新扫描」代替 | 第 3 批 |

### 5.3 验收标准（**替换掉需求文档 5.1 节原标准**）

> 跑通完整主线：**新建任务包 → 硬盘自动长出三个子文件夹 → 往里面丢文件 → 点刷新 → 软件自动归位 → 包视图摆出包卡片 → 点开看到成品/素材/工程三组 → 往工作区根目录丢一个散文件，它出现在「未归属」→ 选中它认领进包**。
>
> 全程不报错，可用鼠标指着逐屏讲解。

**原标准（拖 500 张 / 60 秒 / 缩略图 100%）作废**，挪至第 4 批验收。

## 六、技术要点（给开发看）

### 6.0 已确认的配置项（2026-09-24 用户拍板）

| 项 | 值 | 说明 |
|---|---|---|
| **素材工作区根目录** | `D:\素材工作区` | **固定此路径**。与项目代码目录 `D:\proj_media` 分开，将来整个文件夹拷走即带走全部素材 |
| **包名称命名约定** | **不定死，不做模板校验** | 用户明确选择。理由：模板会逼人瞎填，反而不如让同事自然命名 |

> 包名称虽不做强制模板，但**建议在新建包弹窗的输入框里放一行灰色提示例子**（如 `例：海南招生海报-2026秋季`），只作引导，不校验、不拦截。**输入框留空也要允许创建**（软件兜底取名 `未命名任务-20260924-1037`）。

### 6.1 其他技术要点

| 项 | 决定 |
|---|---|
| 数据库 | SQLite（`better-sqlite3`），沿用 7.4 节表设计，**新增 `packs` 表** |
| 新表 `packs` | 编号、包名、所属项目、物料类别、文件夹路径、创建时间、更新时间 |
| 文件归属 | `assets` 表增加 `pack_id` 字段 + `role` 字段（成品/素材/工程） |
| 缩略图 | `sharp`，统一存到库文件夹 `_thumbs/` 下 |
| 缩略图命名 | 按内容指纹前 16 位命名，便于后续去重复用 |
| 打开文件 | `shell.openPath()` |
| 打开文件夹 | `shell.showItemInFolder()` |
| 主进程 / 界面通信 | `ipcMain.handle` + `contextBridge` 暴露，**不用 `ipcRenderer.send`** |
| 界面样式 | 手写 CSS，**不装 Tailwind / shadcn**（见 `DECISIONS.md` 2026-09-24） |
| 工作区路径存储 | 记在本地配置文件，**不写进数据库**（数据库本身放在工作区内，避免鸡生蛋问题） |

### 6.2 待处理的已知阻塞

| 问题 | 状态 |
|---|---|
| `better-sqlite3` 是原生模块，Electron 下需重编译 | **未处理**，第 1 批开工第一件事：`npx electron-rebuild` |
| FFmpeg 未安装 | 不影响第 1 批（不做视频缩略图） |
