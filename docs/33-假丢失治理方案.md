# 33 · 假丢失治理：丢失记录可忽略 + 临时文件默认不扫描

> 日期：2026-10-08　性质：**补第 8 批欠下的口子 + 扫描策略新增**　分支：`main`  
> 状态：**待用户确认**（确认后才动代码）  
> 起因：用户实测 —— 设计软件在工作目录里生成 `~S<原文件名>.pptx` 这类临时文件，扫描时它还在 →  
> 被登记成素材；软件关闭后临时文件自行消失 → 下次扫描判「文件已丢失」→ 左栏「⚠️ 文件已丢失」+1、  
> 任务面板挂 `⚠ N`。**这是假警报**：那个文件本来就不该存在，不是丢了。

## 0. 一句话

给「文件已丢失」补两条出路：

1. **能忽略** —— 记录和标签都留着，只是不再当"丢失"报警，可随时撤销；
2. **临时文件默认不进库** —— `~$` / `~S` / `*.tmp` 这类文件扫描时直接跳过；某个任务确实要管临时文件时，  
   在「编辑任务信息」里勾一个开关。

## 1. 需求源头（用户原话，2026-10-08）

> 有时候 PS 软件会生成临时文件在"工程文件夹"内，软件关闭后文件被清除，然后在 VellumDesk 中会产生  
> "文件已丢失"的筛选条目，同时在任务面板中也会出现叹号警告。但这种情况下的文件丢失并不是真的丢失  
> 而是临时文件被删除。所以应当在定位丢失文件时添加一个"忽略"按钮（或者其他合适的称呼），点击后就会  
> 忽略本文件的丢失，另外当多选文件时也应当能够批量忽略。

第 4 点（临时文件策略）用户补的设计：

> 我觉的可以做，怕出现漏扫描，可以在**编辑任务信息**中添加"**是否扫描临时文件**"的复选框，  
> 勾选后点击刷新/扫描即可将该任务的临时文件加入任务包。

## 2. 现状与缺口

### 2.1 这个口子第 8 批就自己留了话

`docs/10` §7.1 原话：

> **记录会堆积**：用户真的不要某个文件了（不打算找回来），记录会一直留着打"丢失"标记。  
> **本批不做"删除记录"入口**（那又是一套确认流程），先看实际使用情况；**真需要时下一批加**。

现在就是"真需要时"。

### 2.2 代码现状（三处事实）

| 位置                                   | 事实                                                                   |
| ------------------------------------ | -------------------------------------------------------------------- |
| `workspace.ts` `markMissingAssets()` | 四道门判丢失：根可读 / 文件真不在 / 素材可见 / 包文件夹还在。**只写 `missing_at`，无任何"我不认这条"的出口** |
| `RelocateModal.tsx`                  | **只有批量模式**（先选一个目录 → 按 `rel_path` 逐级降级匹配 → 勾选落库）。没有单条入口，更没有"忽略"       |
| `FileRow.tsx`                        | 丢失行只给一个 🔍「重新定位」按钮                                                   |

### 2.3 根因链

```
设计软件在工作目录生成 ~S<原名>.pptx（软件开着时它在）
   ↓ 用户点「刷新/扫描」——此刻文件还在 → 登记成一条素材记录
设计软件关闭 → 它自己把临时文件删掉
   ↓ 下次扫描 → 文件不在 → 打 missing_at
左栏「⚠️ 文件已丢失」+1 · 文件视图冒出一条丢失行 · 任务面板挂 ⚠ N
   ↓ 这个文件用户压根不想要 → 「重新定位」无从点起
假警报**永久赖在界面上**，无解
```

**一句话**：不是扫描算错，是"丢失"这个状态**只有一条出路（找回来）**，缺"我不要它了"的出口。

## 3. 术语定义

### 3.1 「忽略」（针对丢失记录）

- **语义**：这条记录我不打算找回了，**别再当"丢失"提醒我**
- **不删除**：记录、标签关联、在包内的位置全部保留（守铁律①：永不静默丢弃用户数据）
- **可撤销**：随时能恢复成"丢失待处理"
- **不是**"删除记录"、**不是**"把文件从磁盘删掉"

### 3.2 「临时文件」（针对扫描策略）

扫描时**默认跳过**的文件，判定规则（规则克制，只收"确定的临时/系统文件"，避免误伤真实素材）：

| # | 规则                                                         | 命中例子                                   | 覆盖谁                             |
| - | ---------------------------------------------------------- | -------------------------------------- | ------------------------------- |
| 1 | 文件名以 `~` 开头                                                | `~S设计稿.psd`、`~$报告.docx`、`~WRL0001.tmp` | 设计软件暂存 / Office 锁文件 / Word 恢复文件 |
| 2 | 文件名以 `~` 结尾                                                | `方案.pptx~`                             | 编辑器的备份文件                        |
| 3 | 扩展名 ∈ { `tmp` `temp` `crdownload` `part` `partial` `!ut` } | `a.tmp`、`b.crdownload`                 | 通用临时 / 浏览器下载中 / 下载工具未完成         |
| 4 | 文件名 ∈ { `Thumbs.db` `desktop.ini` }                        |                                        | 系统自动生成的元数据文件                    |

> 注：`.` 开头（`.DS_Store` 等）和 `_` 开头**已经被现有扫描跳过**（`collectFiles` / `filesDirectlyIn` 里  
> 那句 `name.startsWith('_') || name.startsWith('.')`），本批不用重复处理。  
> 匹配一律**先转小写**（Windows 不区分大小写）。

## 4. 设计 A：丢失记录可忽略

### 4.1 数据模型（迁移 18）

```sql
ALTER TABLE assets ADD COLUMN missing_ignored_at TEXT;   -- NULL = 正常；有值 = 用户在这个时刻忽略了它的丢失
```

与 `missing_at` 完全对称（时间戳而非布尔：界面能显示"什么时候忽略的"）。

### 4.2 口径变化（一句话：**两条都要满足才算"丢失"**）

| 场景                  | 旧口径                      | 新口径                                                     |
| ------------------- | ------------------------ | ------------------------------------------------------- |
| 左栏「文件已丢失 N」计数       | `missing_at IS NOT NULL` | `missing_at IS NOT NULL AND missing_ignored_at IS NULL` |
| 文件视图「只看丢失」筛选        | 同上                       | 同上                                                      |
| 任务卡片 `⚠ N`（任务面板的叹号） | 同上                       | 同上                                                      |
| **新增** 左栏「已忽略 N」    | —                        | `missing_ignored_at IS NOT NULL`                        |

### 4.3 状态流转

```
正常 ──扫描发现文件没了──→ 丢失 ──用户点「忽略」──→ 已忽略（界面不再报警）
 ↑                        │                            │
 └───扫描发现文件回来了────┴────扫描发现文件回来了──────┘
      （两个标记一起清，记录自动恢复正常）
```

三个细节：

1. **已忽略的记录，扫描时不再重复标记** —— 本来就不会（现有逻辑只在 `missing_at === null` 时写），无需改动；
2. **已忽略 + 文件一直不在** → 保持忽略状态，不打扰用户；
3. **已忽略 + 文件又回来了**（比如用户把文件放回原处）→ **两个标记一起清**，记录恢复常规  
   （与现有"文件回来自动清丢失标记"同一条规矩，不新增分支）。

### 4.4 动作（两个新动作）

| 动作           | 行为                                                                    |
| ------------ | --------------------------------------------------------------------- |
| **忽略**       | `UPDATE assets SET missing_ignored_at = <now> WHERE id IN (…)`，可一次传多条 |
| **恢复**（撤销忽略） | `UPDATE assets SET missing_ignored_at = NULL WHERE id IN (…)`         |

两条都是**纯数据操作，一个字节都不碰磁盘**。

### 4.5 界面（三个入口）

| 位置            | 长什么样                                               | 行为                                      |
| ------------- | -------------------------------------------------- | --------------------------------------- |
| **工具栏**（文件视图） | 选中含丢失行时，与「批量重新定位」并排出&#x73B0;**「忽略丢失 (N)」**         | 忽略选中的那些丢失行 —— **这里是批量入口**（用户要的"多选批量忽略"） |
| **文件行行尾**     | 🔍 旁边加一个「忽略」图标按钮（仅丢失行显示）                           | 单条忽略，一步到位                               |
| **左栏筛选区**     | 「⚠️ 文件已丢失 N」下面加一&#x884C;**「🚫 已忽略 N」**（N > 0 时才出现） | 点开只看已忽略的；这些行行尾按钮变成「恢复」                  |

> 设计取舍：**不放重新定位弹窗里**。那个弹窗的流程是"先选一个目录再去匹配文件"，忽略跟它无关  
> （忽略不需要任何目录）；塞进去反而要先走完"选目录"才能操作，别扭。

### 4.6 边界（明确写死）

| 情况                | 结果                               |
| ----------------- | -------------------------------- |
| 忽略一条**文件其实还在**的记录 | 界面不给这个入口（只有丢失行才有"忽略"）；不可达        |
| 忽略后**再扫描**        | 保持忽略，不重复标记                       |
| 忽略后**文件回来了**      | 两个标记一起清，恢复正常记录                   |
| 忽略后**包文件夹整个被删**   | 走第 6 步包清理（记录连同包一起摘），与忽略状态无关      |
| 忽略后**项目被解绑**      | 照旧隐身（`VISIBLE_PACK_SQL`），与忽略状态无关 |

## 5. 设计 B：临时文件默认不扫描

### 5.1 数据模型（迁移 18，同一个迁移号）

```sql
ALTER TABLE packs ADD COLUMN scan_temp INTEGER NOT NULL DEFAULT 0;   -- 0 = 不扫临时文件（默认）；1 = 扫
```

**默认关** = 全局默认跳过临时文件。这就是"从根上不产生假丢失"。

### 5.2 扫描逻辑改动（只有一处）

`scanAll` 第 3 步现在是：

```ts
const allFiles: string[] = []
for (const p of packPlan) collectFiles(p.dir, allFiles)      // ← 这里
```

改成：**先取每个包的 `scan_temp`**，`collectFiles` 多接一个 `skipTemp: boolean` 参数：

```ts
for (const p of packPlan) collectFiles(p.dir, allFiles, /* skipTemp */ p.scanTemp !== 1)
```

未归属散文件（`filesDirectlyIn` 收集的）**永远跳过临时文件** —— 它们不属于任何任务，  
没有地方挂"例外开关"。

`collectFiles` 内部在 `else if (st.isFile()) out.push(full)` 之前加一句判定：

```ts
const base = basename(full)
if (skipTemp && isTempFile(base)) continue
```

`isTempFile(name)` 是新的**纯函数**（放 `workspace.ts` 导出，accept 能直接断言），按 §3.2 四条规则判定。

### 5.3 界面：编辑任务信息加复选框

`EditPackModal`（包卡片右键 ✎ / 待归类包 📥 打开的那个）在「物料类别 / 使用场景」两个下拉**下方**加一块：

```
☐ 扫描临时文件
   勾选后，刷新/扫描会把本任务下的临时文件（~$ / ~S / *.tmp 等）也收进任务包。
   默认不扫描 —— 这类文件多是软件生成的中间产物，扫描后很快就会消失，会被误报"文件已丢失"。
```

- 与现有字段同一套「保存」按钮提交（走 `UpdatePackPatch`）
- 改动**不碰磁盘**（与"只改类别"同一条路径）

### 5.4 边界（明确写死）

| 情况                            | 结果                                                                    |
| ----------------------------- | --------------------------------------------------------------------- |
| 勾选后点「刷新/扫描」                   | 该任务下的临时文件正常入包，成为普通素材（用户要的）                                            |
| **取消勾选后**，之前已入包的临时文件          | **记录保持不动**（软件永不悄悄扔东西）。要清掉：在资源管理器删掉该文件 → 扫描 → 它会变成"丢失" → 用「忽略」忽略（链路闭环） |
| 升级上来的老库                       | `scan_temp` 默认 0 → **以后**扫描不再收临时文件；**已有的记录不动**（包括用户现在这条假丢失 → 用「忽略」清掉） |
| 未归属的临时文件                      | 永远跳过，无例外                                                              |
| 临时文件在**版本文件夹**（`V1/03-工程/…`）里 | 同样按包的 `scan_temp` 判定（判定发生在文件收集阶段，与层级无关）                               |

## 9. 验收标准

### 9.1 accept（871 → 只增不减）

**忽略（`[34]` 段）**

- 忽略一条丢失记录 → `missing_ignored_at` 有值、`countMissing()` 减 1、`countIgnoredMissing()` 加 1
- 「只看丢失」筛不出它；「只看已忽略」筛得出它
- 批量忽略 3 条 → 三条都生效（一次调用）
- 恢复 → 回到"丢失待处理"，计数对
- 已忽略 + 再扫描 → **不重复标记、不自动取消忽略**
- 已忽略 + 文件放回来 → 扫描后**两个标记一起清**，`countMissing` / `countIgnoredMissing` 都归零
- 任务卡片 `missingCount` 不含已忽略的
- 幂等：忽略两次 → 时间戳不刷新（或无害），计数不重复减

**临时文件（`[35]` 段）**

- `isTempFile()` 四条规则各命中若干 + **不误伤**（`~` 不在开头的不拦、`tmp` 不在扩展名位置的不拦、正常 `.pptx` / `.psd` 不拦、大小写混写要拦）
- 包 `scan_temp = 0`（默认）→ 扫描后临时文件**不进库**；真实文件照常进
- 包 `scan_temp = 1` → 临时文件正常进库、`role` 判定正确
- 未归属目录下的临时文件 → 永远跳过（即使有包勾了开关）
- 取消勾选后重新扫描 → **已入包的临时文件记录不动**（钉住"不悄悄扔"这条）

### 9.2 界面

`missing` 场景扩断言（忽略 / 恢复 / 已忽略入口存在与计数一致 / 编辑任务弹窗的复选框存在且能保存）。  
收尾跑全量 **12 个场景**，全部绿、控制台零报错。

### 9.3 人工验收（真机）

1. 找一个含临时文件的任务 → 扫描 → 临时文件**不再进库**
2. 该任务勾选「扫描临时文件」→ 再扫描 → 临时文件**进来了**
3. 手动删掉一个真实文件 → 扫描 → 标丢失 → 点「忽略」/ 选中批量「忽略丢失」→ **左栏计数减、任务面板叹号消失**
4. 左栏「已忽略」入口能看见它 → 点「恢复」→ 回到丢失列表
5. 把那个文件放回原位 → 扫描 → 记录自动恢复正常

| 风险                                         | 对策                                                                            |
| ------------------------------------------ | ----------------------------------------------------------------------------- |
| `isTempFile` 误伤真实素材（比如用户真有个 `~设计稿.psd` 想管） | 规则只收"确定的临时/系统文件"；真中招的走"勾选该任务的扫描临时文件开关"这条路（本批就是为它设计的）；判定函数是纯函数，accept 有专门的反向断言 |
| 老库升级后，已有的假丢失记录仍在                           | 不自动清理（铁律①）。用「忽略」一键清，验收清单第 3 条就是它                                              |
| 口径改了，老断言（计数类）可能变数字                         | 施工第 1 步就跑全量 accept，**逐条核对**（第 8 批 `assetTotals` 口径变化时踩过同类坑）                   |
| 已忽略的记录在库里越积越多                              | 接受。这是"用户主动点的"，且左栏「已忽略」入口随时能看能撤销                                               |
| 「忽略」被误当成"删除"                               | 文案写清（`ignoreTip`：忽略只是不再提醒，记录和标签都还在，随时可恢复）；不做硬删除                               |

---

## 11. 刻意不做

- **不做"删除丢失记录"**（硬删除）—— 忽略 + 可撤销已经够用，硬删除违背铁律①
- **不做"文件真的丢了就自动忘掉"**（按时间自动清理）—— 软件不替用户做决定
- **不做全局的"扫描临时文件"总开关**（只做任务级例外）—— 用户明确要的是"编辑任务信息里勾"，  
  全局默认就是跳过；加全局开关会把决策复杂度翻倍
- **不改 `RelocateModal` 的交互**（它仍然是"整个文件夹被搬走"的批量救援工具，职责不变）
- **不做文件类型白名单**（比如"只扫图片视频"）—— 是另一件事，需要单独议
