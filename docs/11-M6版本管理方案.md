## §0 一句话

**版本 = 包文件夹下的一个文件夹。** 软件建的就是 `V1 / V2 / V3`；用户自己在资源管理器里建好的文件夹（名字随便叫），在软件里「绑定」一下也能成为某一稿。

## §1 为什么这么做

### 1.1 需求文档原话（5.6）

> 轻量做法：不引入 Git 那套复杂概念，只做"一个物料挂多个版本"。

| 编号 | 需求 | 优先级 |
|---|---|---|
| M6-01 | 一个物料可挂多个版本，版本号自动递增 v1、v2、v3 | P0 |
| M6-02 | 每个版本记录文件、缩略图、版本说明（改了什么）、创建时间、创建人 | P0 |
| M6-03 | 可标记"当前版本"与"已交付版本"，列表里高亮显示 | P0 |
| M6-04 | 物料详情页以时间线形式列出所有版本，一眼看清迭代过程 | P0 |
| M6-05 | 支持给旧版本一键"设为当前版本"，相当于回滚 | P1 |
| M6-06 | 版本对比：两个版本并排显示，图片并排看，视频双窗同步播放 | P1 |
| M6-07 | 交付记录与版本绑定，点交付记录可直接定位到当时交付的那一版 | P1 |
| M6-08 | 存储优化：内容完全相同的文件只存一份，多条记录指向同一个文件（按内容指纹去重） | P2 |

### 1.2 两种读法

"一个物料挂多个版本"这句话有两种落法，差别极大：

| | 读法甲：物料级（一个文件一个版本） | 读法乙：包级（一稿一个文件夹） |
|---|---|---|
| 磁盘 | `01-成品\海报.png`、`01-成品\海报-v2.png` 平铺 | `包\V1\01-成品\海报.png`、`包\V2\01-成品\海报.png` |
| "物料" | = 一张海报 | = 一次任务（这个包） |
| "版本" | = 这张海报的第几稿 | = 这次任务的第几稿 |
| 资源管理器里 | 看不出哪版是哪版 | 一眼看出"这是第二稿" |
| 改稿时 | 要自己另存新文件名 | 整稿一套放一起，上一稿原样留着 |
| 交付时 | 得挑文件 | 直接说"交付 V2" |

**AI 第一轮提的是读法甲，被用户否掉；定稿走读法乙。** 记录在案，免得以后有人翻回来问"当初为什么不按物料做"。

### 1.3 走读法乙的三个理由

1. **符合第 6 批埋的种子**。`DECISIONS.md` 2026-09-25 那条写得很明白：*"包归属判定必须深度无关……将来在包和三组之间插版本层（V1/V2）不用改代码"*。`locateFile()` 现在就是"在相对包文件夹的子树里找第一个匹配三组名的段"，`包\V2\01-成品\a.png` 已经能正确归「成品」。**这一批把那个"将来"兑现了，扫描核心一行不用改。**
2. **符合第 6 批的立身之本**：*"软件里看到什么，硬盘上就是什么"*。物料级版本在硬盘上是隐形的（两版就是两个平铺文件），和这条信条冲突。
3. **给 M5 打包交付铺好了路**。M6-07 要"交付记录与版本绑定"——版本本来就是文件夹，"交付 V2"就是把 V2 这个文件夹打包，天然对接。物料级模型下这件事要绕一大圈。

### 1.4 与"包快照"的区别（一处措辞要小心）

第 6 批蓝图里的 V1/V2 原意偏"**包快照**"（每次存档一套完整文件）。本批落地的语义是"**稿件**"：

- 一稿里放的是**这一稿的东西**，不是"把上一稿原样再存一份"；
- 上一稿不会被动过（软件不删不改），所以历史照样在，等于顺带实现了快照的效果；
- 区别只在**新建一稿时默认是空的**（可勾选"把上一版复制进来"，见 §6.2）。

## §3 磁盘结构

```
D:\素材工作区\
└─ 海南升学规划中心\                 ← 项目
   └─ 海南招生海报-2026秋季\          ← 包
      ├─ V1\
      │  ├─ 01-成品\  02-素材\  03-工程\
      ├─ V2\
      │  ├─ 01-成品\  02-素材\  03-工程\
      ├─ V3\
      │  ├─ 01-成品\  02-素材\  03-工程\
      ├─ 最终版-客户确认\             ← 用户手工建、在软件里绑成 V4
      │  ├─ 01-成品\ ...
      └─ V5\                          ← 软件建
```

规矩：

- 版本文件夹**是包文件夹的直接子级**，里面照旧长 `01-成品 / 02-素材 / 03-工程`（新建时软件自动建这三组）
- 版本文件夹**不参与"包 / 项目"的判定**：`listTopDirs` 判包靠"直接子级是否含三组名"，`包\V1\` 的直接子级是三组，看着像包 —— 但它位于某个包**内部**，而根目录第一层和项目文件夹的直接子级才是判定的范围，所以不会被误判成包
- 版本文件夹下**不允许再嵌套版本**（只认第一层），`V2\V3\...` 里的 `V3` 会被当普通文件夹
- 版本文件夹改名：软件按**绑定记录里的文件夹名**找，改名后那一稿会被标成"文件夹已不在"（不会误吞别人的文件夹）；想恢复就重新绑定

## §4 数据表（迁移 9）

### 4.1 新表 `pack_versions`

```sql
CREATE TABLE IF NOT EXISTS pack_versions (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  pack_id      INTEGER NOT NULL REFERENCES packs(id) ON DELETE CASCADE,
  seq          INTEGER NOT NULL,                    -- 1 / 2 / 3 → 显示为 V1 / V2 / V3
  folder_name  TEXT    NOT NULL,                    -- 磁盘上的文件夹名（可能不是"V2"）
  note         TEXT    NOT NULL DEFAULT '',         -- 版本说明：这一稿改了什么
  is_current   INTEGER NOT NULL DEFAULT 0,          -- 当前版本（0/1）
  delivered_at TEXT,                                -- M6-07 用，本批只留字段
  created_at   TEXT    NOT NULL,
  UNIQUE(pack_id, seq),
  UNIQUE(pack_id, folder_name)
);
CREATE INDEX IF NOT EXISTS idx_pack_versions_pack ON pack_versions(pack_id);
```

### 4.2 `assets` 加一列

```sql
ALTER TABLE assets ADD COLUMN version_id INTEGER   -- NULL = 未分版本（老包 / 包根散文件）
```

**索引必须放在迁移里 ALTER 之后建**（第 8 批踩过：老库的表已存在，建表段里那句 `CREATE INDEX` 跑的时候列还没补上 → `no such column`）。

```sql
CREATE INDEX IF NOT EXISTS idx_assets_version ON assets(version_id);
```

### 4.3 为什么"当前版本"用 `is_current` 而不是建外键指向 assets

"当前版本"指的是**这一稿**，不是一个文件 —— 一稿里可能十几个文件。用 `pack_versions.is_current` 表示，语义干净，也不用去 assets 表里挑"哪个算代表"。

约束：**一个包内最多一个 `is_current = 1`**（写入时先把同包其他稿清零）。

### 4.4 老库升级

不搬任何数据。老包的所有素材 `version_id = NULL`，界面归「未分版本」，行为与升级前完全一致。

## §5 扫描怎么认版本（`scanAll`）

给每个文件算 `version_id`，两条规则，**先精确、后猜名**：

| 顺序 | 情况 | 处理 |
|---|---|---|
| 1 | 文件路径落在某个**已知版本文件夹**下（按 `pack_versions.folder_name` 拼出的路径） | 认，`version_id = 那一稿` |
| 2 | 没匹配上，但相对包文件夹的某个路径段名字符合 `^[Vv](\d+)$`，且该包 `seq = 数字` 未被占用 | **自动建一稿**（`folder_name` 取磁盘上的真实名字，`seq` 取数字），文件认给它 |
| 3 | 名字符合规则但 `seq` 被占用（已被绑定给别的文件夹） | **不认**，`version_id = NULL`，往 `ScanResult.versionConflicts` 塞一条提示，界面 toast 告知 |
| 4 | 其余 | `version_id = NULL`（未分版本） |

要点：

- **只认第一层**：取的是"相对包文件夹的路径段"，但只在**前两段**里找（`V2\...` 或 `...\V2\...` 都行，避免深层同名目录误伤）。实现上：找**第一个**符合规则的段就认，找到即止。
- **磁盘永远是唯一真相**：文件夹没了 → 那一稿在界面上标"文件夹已不在"（记录留着，说明和时间还在，用户可以选择解绑或重新绑定）；文件夹还在 → 记录照旧。
- 手工把 `V3` 改成 `V4`：扫描按新名字自动建 V4（如果 4 没被占），老记录 V3 变成"文件夹已不在"。用户如果嫌乱，解绑 V3 即可。

## §6 用户操作

### 6.1 软件建（主流）

包详情 → 版本条右侧「＋ 新建版本」：

1. 弹窗显示：将要建的编号（自动算 = 现有最大 seq + 1）、**版本说明**输入框（"客户反馈：主标题太小"）
2. 勾选项：
   - 「把包里现有文件收进这一稿」——**仅在"该包还没有任何版本"且"三组里确实有文件"时出现，默认勾上**
   - 「把上一版（Vn）的文件复制一份进来」——**仅有上一版时出现，默认不勾**
3. 确认 → 建 `V<n>\` + 三组空文件夹 → （按勾选）搬/复制文件 → 写记录 + 设为当前
4. 搬文件用 `renameSync` + **在原记录上重写路径**（`reprefixPaths` 那一套，铁律：不能"删旧建新"，否则 `asset.id` 一变标签就没了）

### 6.2 收编的边界

"把包里现有文件收进这一稿"只搬**已经躺在三组里的文件**（role = 成品 / 素材 / 工程），按 role 搬进对应的子组。

**包根目录下的散文件（role = 未归属）不动。** 它们本来就没归类，悄悄挪进某个组等于替用户做主 —— 保留在原地，用户可以在「未分组」里用现成的"移动到"面板处理。

### 6.3 绑定已有文件夹（用户建好、软件认不出）

版本条右侧「📎 绑定文件夹」：

1. 弹窗列出**这个包文件夹下还没被认领的所有子文件夹**（软件扫出来的，点一下即可，不用翻路径）
2. 选一个 → 软件推一个编号：文件夹名符合 `V\d+` 就用那个数字（没被占的话），否则填"下一个可用编号"。**用户可改**，填到已被占用的编号会被拦下并提示
3. 填版本说明（可空）
4. 确认 → 写记录；**该文件夹下的文件下一次刷新扫描时自动挂上这一稿**（也顺手当场刷一次，用户立刻看到）
5. 界面显示：`V4（文件夹名：最终版-客户确认）` —— 编号归软件的规矩，名字随用户的习惯

限制：

- 只能绑定**包文件夹里面**的文件夹（含包根下的任意子文件夹）。包外面选的，提示先手工拖进包文件夹 —— 工作区外的东西软件管不着。
- 已经绑过的文件夹不再出现在候选列表里。
- 绑定的文件夹里如果没有三组（文件直接躺在里面），照样能绑；那些文件在版本视图里列在「未分组」。
- **绑定不自动改"当前版本"**（补绑历史稿是常见场景，不该悄悄把指针挪走）。想设当前，在版本条上点一下。

### 6.4 解绑

版本条上某稿 → 悬停出「解绑」：

- 删掉 `pack_versions` 记录；该稿下文件的 `version_id` 清空（回到「未分版本」）
- **文件夹和文件一个都不动**（铁则：软件永远不悄悄扔掉用户放的东西）
- 如果解绑的正是"当前版本" → 当前版本顺延给剩下 seq 最大的那一稿；一稿都不剩就置空

### 6.5 设为当前版本（= M6-05 回滚）

版本条上某稿 → 「设为当前」：同包其他稿 `is_current = 0`，它置 1。**纯库操作，磁盘零改动。** 回滚的语义是"现在按这一稿算"，不是"把后面的抹掉"。

## §7 界面

### 7.1 包详情弹窗（主战场）

顶部加一条**版本条**，每个版本一格：

```
┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐  ＋新建版本  📎绑定文件夹
│ V3 当前  │ │ V2       │ │ V1       │ │ 未分版本 │
│ 客户反馈…│ │ 初稿     │ │ —        │ │ 3 个文件 │
│ 8 个文件 │ │ 8 个文件 │ │ 8 个文件 │ │          │
│ 09-30    │ │ 09-28    │ │ 09-28    │ │          │
└──────────┘ └──────────┘ └──────────┘ └──────────┘
     ↑ 当前版本高亮实色边框；hover 出「设为当前」「解绑」
```

- 点哪一格，下面三组（成品 / 素材 / 工程）就只显示那一稿的文件
- 默认选中**当前版本**；老包（无版本）默认选中「未分版本」
- 「未分版本」格只在包里确实有这类文件时出现
- 每格右下角标注这一稿的占用体积（**历史稿也占硬盘**，得让用户看见）

### 7.2 包卡片

有版本时显示一行：`V3 当前 · 共 3 稿`；已交付版本挂绿标（M5 之后自动写，本批留字段）。
没有版本的包（老包）不显示这行，跟现在一样。

### 7.3 文件行（FileRow）

每条素材行加版本徽标：当前稿实色 `V3`、历史稿灰色 `V2`、未分版本不显示。

### 7.4 工具栏开关「只看当前稿」

文件视图（全局平铺）默认**全部显示**（铁则：不悄悄藏东西），每行带版本徽标；工具栏给一个「只看当前稿」开关，打开后只列当前版本的文件，旁边标注"另有 N 个历史版本文件"。

### 7.5 新建 / 绑定弹窗

`VersionModal` 一个组件两副面孔（tab 切换）：**新建** / **绑定已有文件夹**。绑定那一半列出候选文件夹 + 编号 + 说明。

## §8 统计口径

| 位置 | 口径 |
|---|---|
| 包卡片文件数 / 容量 | **算全部版本**（历史稿也占硬盘，容量藏不住；文件数跟着容量走，口径一致不烧脑） |
| 包详情某一稿 | 那一稿自己的文件数与占用 |
| 顶栏「共 N 条素材」 | 算全部（含历史稿与未分版本） |
| 第 8 批的「文件已丢失」 | 口径不变，丢失的文件照样算条数、不算容量 |

## §14 施工中的实际落地与发现

### 14.1 解绑必须配「忽略名单」，否则解绑等于白点（本批最重要的发现）

- **现象**：accept 断言暴露——解绑 V1 之后，磁盘上文件夹还在、名字还叫 `V1`，下一轮扫描按 §5 的自动认规则**又把它认成第 1 稿**（库里 3 稿 ≠ 预期 2 稿）。用户点了「解绑」等于没点
- **修法**：新表 `pack_version_ignores(pack_id, folder_name COLLATE NOCASE)`。解绑时登记（仅名字符合 `^[Vv]\d+$` 的需要——不规范名本来就不会被自动认）；扫描自动认跳过名单里的名字；用户点「绑定」或软件重建同名文件夹时清除记录
- **为什么不改文件夹名**：违反铁则"软件永远不悄悄动用户磁盘上的东西"
- **回归钉子**：accept `[28]` 补"解绑 → 刷新扫描 → 仍是 2 稿、编号空着、候选里还能看到它"三连断言

### 14.3 验收后补丁（用户实测反馈）：新建包自带第一稿 V1

- **反馈**：用户实测后发现"建包后是空的，还要再手动建第 1 稿"没必要——**"所有新建的包都是从 V1 开始的"**，拍板建包即带一个空的 V1
- **改动**：
  - `createPack`：磁盘直接长成 `包\V1\三组`，包根**不再放三组**（否则资源管理器里多 3 个永远空着的文件夹）；库里插 `seq=1 / folder_name='V1' / is_current=1`，且**必须在 `scanAll` 之前**（否则扫描把这个 V1 当手工建的稿再认一遍）
  - `claimFiles` 的 `versionId` 扩为三态：数字 = 那一稿 / `null` = 明确落包根三组（「未分版本」逃生口，界面停在那一格时用）/ **不传 = 自动落当前版本**（新包认领直接进 V1，不产生"未分版本孤儿"）
  - **已有老包不动**：包根三组照旧、归「未分版本」；扫描不给他们补 V1（悄悄改人家磁盘结构比不做更糟）
- **accept 的处理**：新增 `mkPack` 辅助函数（createPack 后抹掉自带 V1、补回包根三组）并替换 1~8 批全部建包调用——老断言**零改动**地继续考老结构兼容路径；`[28]` 段末尾新增 (15) 节 13 项断言（新建即带稿 / 磁盘结构 / 卡片口径 / 认领落 V1 / 显式 null / 编号接 V2）
- **教训**：改"建包"这种行为级默认值时，先问一句"已有的包要不要跟着变"——答案几乎总是不要。测试基建（`mkPack`）把两代结构都钉住，以后再改默认值也有参照
