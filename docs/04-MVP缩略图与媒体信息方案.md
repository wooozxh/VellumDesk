## 一、这一批要解决什么

第 1 批做完后，软件里所有非图片文件都是一张白板图标 —— **演示时讲不出"这是什么东西"**。

这一批把「**一眼认出这是什么**」补齐，让包卡片和文件列表能真正被指着讲：

| 编号 | 内容 | 用户看到的效果 |
|---|---|---|
| B-01 | **图片尺寸与色彩模式** | 文件列表里图片显示「1920×1080 · RGB · 2.3 MB」 |
| B-02 | **PDF 首页缩略图** | PDF 显示第一页的渲染小图 |
| B-03 | **PSD 缩略图** | PSD 显示内嵌预览图 |
| B-04 | **视频缩略图** | 视频显示首帧画面 |
| B-05 | **视频媒体信息** | 视频显示「00:01:23 · 1920×1080 · H.264」 |

## 二、用户的三个拍板（2026-09-24）

### 2.1 FFmpeg 随软件打包，不做"让用户自己装"

- **决定**：把 FFmpeg 静态构建放进项目，随安装包一起分发。同事拿到软件**零配置**即可看到视频缩略图。
- **原因**：产品定位是"双击就能用"。让每台电脑自己装 FFmpeg 等于把配置成本转嫁给同事 —— 而且设计同事大概率装不明白，最后变成"这个软件视频显示不出来"的售后。
- **代价**：安装包增大约 80 MB。
- **放弃**：让用户自己装（分发不可控）、这批不做视频（用户要视频缩略图来演示）。

### 2.2 PSD 用「内嵌预览图」，不做真渲染

- **决定**：读取 PSD 文件内嵌的合成预览图（Photoshop 存盘时写入的 thumbnail resource），不做图层合成。
- **原因**：真渲染需要 Photoshop 级别的图层混合能力，开源库做不到，自己实现是无底洞。内嵌预览图是**零成本拿到"设计师看到的那个画面"**。
- **已知限制（必须写进界面文案）**：
  - 若设计师存 PSD 时**关掉了"最大兼容"**，文件里没有预览图 → 该 PSD 只能显示普通图标
  - 需要**用户提供 1–2 个真实 PSD 样本**用于验证（当前项目内无样本文件）
- **放弃**：`ag-psd` 一类库做完整图层合成（体积大、仍不保真、对本项目的演示目标无必要）。

### 2.3 媒体信息在文件列表里直接显示

- **决定**：文件列表里直接显示尺寸 / 色彩 / 时长等信息，鼠标指着就能讲。**不做**"只在悬停时弹出"。
- **原因**：这一批的目标就是"演示时指着讲得出来"。信息藏在悬停里等于没做。
- **代价**：列表行变宽，需要处理窄窗口下的截断（见 4.3）。

## 三、数据库改动

`assets` 表新增 6 列，全部走**幂等迁移**（沿用第 1 批 `PRAGMA table_info` 判断再 `ALTER TABLE` 的写法）：

| 新列 | 类型 | 用途 | 谁写 |
|---|---|---|---|
| `width` | INTEGER | 图片/视频宽 | sharp metadata / ffprobe |
| `height` | INTEGER | 图片/视频高 | 同上 |
| `color_mode` | TEXT | `RGB` / `CMYK` / `RGBA` / `灰度` 等 | sharp metadata |
| `duration_ms` | INTEGER | 视频时长（毫秒） | ffprobe |
| `video_codec` | TEXT | `H.264` / `HEVC` 等 | ffprobe |
| `probe_info` | TEXT | 其余信息的 JSON 兜底（码率等） | ffprobe |

> **设计原则**：不建新表。这些信息是"文件的属性"，一个文件一行，跟着 `assets` 走最自然。
> **幂等性**：老库（第 1 批建的）首次启动自动补列，已有缩略图记录不受影响。

## 四、界面变化

### 4.1 文件列表行（主要变化）

```
┌────────────────────────────────────────────────────────────────┐
│ [缩略图]  招生海报-横版.png                                     │
│           1920×1080 · RGB · 2.3 MB · 2026-09-24 10:32          │  ← 新增信息行
└────────────────────────────────────────────────────────────────┘
```

视频：

```
│ [首帧图]  宣传片-正片.mp4                                       │
│           00:01:23 · 1920×1080 · H.264 · 86.4 MB               │
```

### 4.2 包卡片封面

**沿用第 1 批逻辑**（取包内第一个成品），但这一批之后封面**不再只有图片能用** —— PDF / PSD / 视频都能出图，包卡片"灰白板"的比例会明显下降。

### 4.3 窄窗口下的处理

- 信息行各段之间用 ` · ` 分隔，**超宽时整行省略号截断**（不换行、不挤压缩略图）
- 宽度优先级：文件名 > 尺寸 > 体积 > 时间（`flex-shrink` 分级）
- **不做**信息行的自定义开关（简单优先，用户没提这个需求）

## 五、缩略图生成策略

### 5.1 各类型走哪条路

| 类型 | 方案 | 失败降级 |
|---|---|---|
| 图片 | sharp（**第 1 批已有**） | 白板图标 |
| PDF | 引入 PDF 渲染库，渲染第 1 页 → sharp 存 webp | 白板图标 |
| PSD | 从文件内嵌预览图提取位图 → sharp 存 webp | 白板图标 |
| 视频 | `ffmpeg -ss 1 -frames:v 1` 抽第 1 秒画面 → sharp 存 webp | 白板图标 |

### 5.2 三条硬规则（沿用第 1 批经验）

1. **缩略图失败绝不阻断入库** —— 一律 `try/catch` 返回 `null`，文件照常登记
2. **同一文件不重复生成** —— 按「路径 + 大小 + 修改时间」哈希命名，已存在直接复用
3. **生成是异步的、可中断的** —— 不阻塞扫描；扫描先登记元信息，缩略图随后补

### 5.3 性能红线（本批不追求，但要不能明显卡）

- 视频抽帧加 `-ss 1`（跳过片头黑帧）+ 超时保护（单个文件最多等 30 秒）
- PDF 只渲染第 1 页，不解析全文
- 单个文件失败重试 **不做**（保持简单，下次刷新扫描会自然重试）

## 六、技术选型（待定项，开工时定）

| 项 | 候选 | 倾向 |
|---|---|---|
| FFmpeg 来源 | 官方 static build / BtbN build | **LGPL 版**（可商用），随附 LICENSE 文本 |
| FFmpeg 存放 | `resources/ffmpeg/`（electron-builder `extraResources`） | 开发期从项目内取，打包后从 `process.resourcesPath` 取 |
| PDF 渲染 | `pdfjs-dist` + `@napi-rs/canvas` / `mupdf`(wasm) | 开工时实测体积与稳定性后定 |
| PSD 预览图提取 | 自己解析 PSD 的 `image resources` 段 / `psd` 小库 | 优先自己解析（只取内嵌图，不需完整库） |

> 本节的选型细节允许在开工时按实测调整，**但 2.1–2.3 三条用户拍板不可改**。

## 七、施工顺序

按"跑通一次就用得上"排，每步做完软件都必须能正常启动：

| 步骤 | 内容 | 前置 |
|---|---|---|
| **1** | 数据库加 6 列（幂等迁移）+ 图片尺寸色彩采集 + 列表直显 | 无（sharp 已有） |
| **2** | FFmpeg 引入项目 + 路径解析 + 视频缩略图 + 视频媒体信息 | 需先下载 FFmpeg |
| **3** | PDF 首页缩略图 | 需先定 PDF 渲染库 |
| **4** | PSD 内嵌预览图 | **需用户提供 PSD 样本** |

**步骤 1 最优先**：不依赖任何外部东西，且立刻让演示多出一条可讲的信息。

## 八、验收标准

### 8.1 自动验收（扩展 `accept.ts`）

| 断言组 | 内容 |
|---|---|
| 迁移 | 老库（无新列）首次启动后 6 列齐备，已有数据不丢 |
| 图片信息 | 造一张已知尺寸/色彩模式的图 → 扫描后 `width`/`height`/`color_mode` 与事实一致 |
| 缩略图 | 图片/PDF/视频/PSD 各生成一张缩略图文件，且文件真实存在于 `_thumbs/` |
| 复用 | 同一文件二次扫描不重复生成（缩略图文件哈希不变） |
| 降级 | 损坏文件不阻断入库，`thumb_path` 为 null，其余文件正常 |

### 8.2 界面验收（`_shotapp/`）

- 文件列表里图片/PDF/视频各显示正确的信息行
- 包卡片封面在"包内第一个成品是视频"时能显示首帧
- 控制台零报错

## 九、本批不做的

| 项 | 原因 |
|---|---|
| PSD 完整图层渲染 | 见 2.2，无底洞 |
| 视频多帧 / 时间轴预览 | 属第二步"版本"相关 |
| 缩略图尺寸自定义 | 用户没提，固定 320px 足够 |
| 历史文件的缩略图批量回填进度条 | 属第 4 批（进度条/取消） |
| FFmpeg 缺失时的用户提示界面 | 随包分发后不会缺 |
