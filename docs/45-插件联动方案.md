## 0. 一句话

把软件里的「任务库（+通用素材库）」导出成一份**只读镜像**，写进 PS 插件的数据目录；
并在插件点「插入」时，按请求把那一张**原图**投递过去。

---

## 1. 为什么 / 依据

- **契约路线 ②「镜像单写」**：插件（UXP 沙箱）读不了用户的盘（`file://` 实测被拒，契约 §9.1 第 1 条），
  但能读/写自己的 `PluginData` → 所以**由软件写进插件的目录**，插件只读。**无 HTTP、无常驻服务、无额外权限**。
- **插件侧已就绪**：读镜像并渲染（v0.2.7：库切换/分组筛选/网格/详情/每 3 秒比对 `revision`）、
  写 `req.json`、置入链路已真机跑通（S21）。**只差软件侧这两个动作**。
- **handoff 是平台约束、不是可选项**：`placeEvent` 不接受裸路径（§9.1 第 9 条），插件拿不到工作区文件的 Entry
  ⇒ 只能在插件点「插入」时，由软件把**那 1 张原图**拷进 `handoff\incoming.<ext>`。**一个都不批量搬。**

---

## 2. 范围

| 做 | 不做 |
|---|---|
| 镜像目录发现（多 PS 版本 + 手填兜底） | 不做本地 HTTP / WebSocket / 常驻服务（契约 §3.2 否掉） |
| 写 `manifest` / `task` / `brand` + 缩略图转码 | 不写 PluginData 里除契约约定之外的文件 |
| 常驻监听 `req.json` → 投原图 + 回 `res.json` | 不删插件的 `boot.log` / `report.json` 等自用文件 |
| 「同步到插件」手动按钮 + 变更自动重写 | 插件侧代码（另一半的事，不在本仓） |

## 3. 设计

### 3.1 镜像目录发现（契约 §七）

```
base = join(app.getPath('appData'), 'Adobe','UXP','PluginsStorage','PHSP')
hits = []
for d of readdir(base) if /^\d+$/.test(d):                 // 26 / 27 / 28 …
  for c of ['Developer','External','Plugins']:
    p = join(base, d, c, PLUGIN_ID, 'PluginData')
    if exists(p): hits.push({ psMajor: d, library: join(p,'library') })
if hits 为空 → 用设置里手填的 plugin_data_dir（若有）
```

- `PLUGIN_ID = 'com.vellum.toolbox'`（契约 §2.1 定稿）。**不能写死整条路径**（含 PS 大版本号）。
- **多命中 → 全部写**（§7.1 默认策略），每套 `manifest` 带 `psMajor` 便于排障。
- **手填兜底**：设置项 `plugin_data_dir`（meta）。建议**自动命中的都写 + 手填的（若存在）也一起写**，谁都不漏。（✅ 定）
- 一个目录都没找到 → 界面显示「未找到插件目录」+ 手填入口，**不报错、不影响其它功能**。

### 3.2 写什么

`library\` 下（契约 §四）：

| 文件 | 内容 | 契约 |
|---|---|---|
| `manifest.json` | 总索引：`contract` / `generatedAt` / `generator{app,version,layoutVersion}` / `workspaceRoot` / `scopes[]{id,label,file,revision,count}`（可选 `psMajor`） | §5.1 |
| `task.json` | 任务库：`projects → packs → versions → assets` | §5.2 |
| `brand.json` | 通用素材库：`groups[] → assets[]` | §5.3（见 docs/46） |
| `thumb\<file>` | 缩略图（见 §3.3） | §5.5 |
| `handoff\` | **预建空目录**（契约建议软件侧预建，别依赖插件兜底） | §四 |

- JSON 一律 **UTF-8、无 BOM、换行 `\n`**；
- 时间一律 **ISO 8601 带时区**（建议输出 `+08:00` 本地偏移，与契约示例一致）（✅ 定 `+08:00`）；
- 写文件用**原子写**（先写 `.tmp` 再 `rename`）—— 插件每 3 秒 stat 一次，**绝不能让插件读到半个文件**。
  （本项目现有 JSON 落盘都是裸 `writeFileSync`，本批**新增一个原子写 helper**，只在本模块用。）

**`revision`（单调递增）**：每库一个整数，存 meta（`plugin_rev_task` / `plugin_rev_brand`）。
生成时先算「内容签名」（对**不含** `revision` / `generatedAt` 的那份 JSON 取 sha1）：
- 与 meta 里存的签名不同 → `revision + 1`，落盘，更新签名；
- 相同 → **整文件不重写**（省 IO，也让插件的 stat/比对不抖动）。

### 3.3 缩略图转码（契约 §5.5 的修正：webp → png/jpg）

- **源**：现有 `_thumbs\<key>.webp`（图片 / PSD / PDF）或 `.jpg`（视频）；
  `key = sha1(absPath|size|⌊mtime⌋).slice(0,16)`（`thumbs.ts:113`）。
- **目标**：写进镜像 `thumb\<ns><id>.png`（webp→png，**保透明**）/ `.jpg`（视频原样）。
- ⛔ **不动 `_thumbs` 本身**（§5.5 明说：它是软件自用缓存）—— 只**读**它、转码写进镜像。
- `thumb_path` 为 null 的（还没生成缩略图）→ 先 `ensureAnyThumb`（`thumbs.ts:263`）补一次；仍失败 → `thumb: null`
  （插件按契约画占位格，不留空）。
- **命名空间**：任务库 `t<id>.png` / 通用库 `b<id>.png` —— 见 §5 契约影响 ②。

### 3.4 handoff（★ 必做项）

状态机照契约 §六：

```
插件                                软件（常驻轮询）
 │ ① 写 handoff/req.json（覆盖）        │
 ├───────────────────────────────────►│
 │                                     │ ② 查 assetId → 拷原图 → incoming.<ext> → 写 res.json
 │ ③ 轮询 handoff/res.json（~300ms）     │
 │◄───────────────────────────────────┤
 │ ④ reqId 匹配 & ok=true → 读 incoming → 置入
```

- **监听方式：轮询**（默认 ~600ms `stat` `handoff\req.json` 的 `mtime+size`，变了才处理）。
  理由：本项目**从未用过 chokidar**，为一个几 KB 的小文件引入新依赖 + 打包面不划算；
  契约提 chokidar 只是示意。（✅ 定：**轮询**，不引 chokidar）
- **多镜像目录 → 每个目录都要轮询**（`req.json` 可能来自任一 PS 版本）。
- 处理步骤：
  1. 读 `req.json`，校验 `contract` 前缀是 `vellum-link/`
  2. 用 `scope`（`task`/`brand`）决定查哪张表；id 查不到 → `ok:false, error:'not_found'`
  3. `missing_at` 非空 → `error:'missing'`
  4. 原文件在磁盘上不存在 → `error:'not_found'`
  5. 体积超阈值 → `error:'too_large'`（**300 MB**）
  6. 扩展名不支持置入 → `error:'unsupported'`（白名单：常见位图 + `psd`/`psb`）
  7. 拷贝到 `handoff\incoming.<ext>`（先 `incoming.tmp` 再 `rename`，避免半文件）
  8. 写 `res.json`（`reqId` **原样回填**、`ok` / `file` / `size` / `error` / `at`）
- **去重**：记住已处理的 `reqId`，同一个不重复拷。
- **清理**：`res.json` / `incoming.*` 超过 **10 分钟** 的删掉（契约 §六 规则 5 归软件侧）。
- 任何异常一律回 `ok:false` + error，**不抛、不崩**。

### 3.5 同步时机（手动 + 变更自动）

- **手动**：一个「同步到插件」按钮（`plugin:syncNow`），带结果（写了哪几个目录 / 多少素材 / 耗时 / 失败原因）。
- **自动**：`scheduleMirrorSync()`（防抖 ~2s）+ **内容签名短路**（没变就啥也不写）。触发点：
  1. 启动后（`initWorkspace` 之后，延迟 ~3s 首扫）
  2. 每次扫描结束（`scan:refresh` 收尾，`workspace.ts:968 scanAll`）
  3. 任务/包的增删改（建包 / 编辑 / 删除 / 认领 / 版本六动作）
  4. 通用素材库的增删改（docs/46）
  5. 工单同步自动建任务之后

### 3.6 设置项

meta 键集中定义（照 `report.ts:21-24` / `tickets.ts:91-119` 的路数）。至少：

| 键 | 含义 | 默认 |
|---|---|---|
| `plugin_data_dir` | 手填的 PluginData 目录（兜底） | 空 |
| `plugin_sync_enabled` | 变更自动同步开关 | 开 |
| `plugin_rev_task` / `plugin_rev_brand` | 各库 revision | 0 |
| `plugin_sig_task` / `plugin_sig_brand` | 各库内容签名 | 空 |

界面照 `TicketSettingsModal.tsx`（弹窗外壳 + 可手填 `input`）+ `report:saveLink`（`ipc.ts:1643`）的写法。

## 6. 验收口径

- **accept（喂假数据，不碰真 PS）**：用**临时目录造一个「假 PluginData」**跑镜像生成 →
  断言 manifest/task/brand 结构、revision 递增、**不变不重写**、thumb 是 png、
  handoff 全链路（造 `req.json` → 等 `res.json` → 校验 `reqId` 回填 / `incoming` 字节一致 / 各 error 分支）。
  —— 这就是契约 §十一 要求的"假插件目录"桩。
- **界面场景 `pluginlink`**：设置入口 / 同步按钮 / 「未找到插件目录」降级态。
- **真机验收（人工，用户做）**：装好插件 → 软件点同步 → PS 里看到任务库/通用库、图能出 → 点插入能置入。
