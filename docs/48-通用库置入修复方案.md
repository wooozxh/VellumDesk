## 1. 现象（插件侧实测）

任务库置入正常，**通用库素材一律失败**，面板显示 `✗ 取原图失败：not_found`。
同一分钟的真机读数（插件 `boot.log`）：

```
15:49:18  handoff req  assetId=85   scope=brand → res ok=false  err=not_found
15:49:22  handoff req  assetId=112  scope=task  → res ok=true   incoming.jpg 627927 B  ✓
15:49:26  handoff req  assetId=56   scope=brand → res ok=false  err=not_found
15:49:30  handoff req  assetId=59   scope=brand → res ok=false  err=not_found
```

`req.json`（插件写，`scope` 明确是 `brand`）：
```json
{ "contract": "vellum-link/1", "reqId": "r-20261011T154930-6848",
  "assetId": 59, "scope": "brand", "at": "2026-10-11T15:49:30+08:00" }
```

## 2. 根因（已定位到行）

`src/main/linkHandoff.ts` 的 `process()` 里，**Step 2 时代留下的一个桩**：

```ts
// linkHandoff.ts:211-214（现状）
if (scope === 'brand') {
  // 通用素材库（docs/46）本步尚未实现 → 当作找不到
  return this.reply(handoff, reqId, scope, assetId, false, 'not_found')
}
```

Step 2 写 handoff 时通用库还没做，于是立了这条「`brand` 一律 `not_found`」的占位；
**Step 4 把通用库（`brand_assets` 表）做出来之后，这个桩忘了拆** —— 所以通用库的置入**永远不会成功**，
与素材本身、路径、权限都无关。

> 全仓扫描确认：**主进程里只有这一处**同类桩（`linkHandoff.ts:200` 的 scope 归一化是它的入口）。

**插件侧的判断完全正确**，而且他指出「只按 id 查会**串库**」这一点**尤其重要**：
即使把桩拆掉、直接沿用现在查 `assets` 的写法，也会因为**两库 `id` 各自从 1 起**（契约 §5.5 命名空间）
而出现「brand 的 `id=59` 撞上任务库的 `id=59` → 拷回**另一张图**」——那种「置入成功但图不对」比 `not_found` 更难归因。

## 3. 修复方案

### 3.1 反查路由（核心）

把 `process()` 里那段桩，换成**按 scope 选表**：

| `req.scope` | 反查的表 | 说明 |
|---|---|---|
| `task` | `assets` | 任务库（现状不变） |
| `brand` | `brand_assets` | 通用库（本次新增） |
| 缺省 / 空 | 按 `task`（向后兼容） | 旧行为 |
| 其它字符串 | `bad_request` | 契约要求 `scope` 必填；未知值**不猜**，避免误投 |

两表相关列一致（`id` / `abs_path` / `ext` / `size` / `missing_at`），**下游校验与拷贝逻辑一行不改**：
`missing_at` → `missing`；文件不存在 → `not_found`；扩展名白名单 → `unsupported`；
体积 → `too_large`；`copyFileSync` + `rename` + `utimesSync(now)`（第 62 批的真机修复）照旧。

> 关键：**先按 scope 定表，再在该表内按 `assetId` 查** —— 从构造上消灭「串库」。

### 3.2 契约加法（§十 流程 · 不升版本）

**§六** 补一条规则（采用插件侧建议的措辞）：
> 规则 8｜`req.json` 的 `scope` **必填**；软件侧必须**在该 scope 内**按 `assetId` 反查原图。
> 不得全局只按 `id` 查 —— 两库 `asset.id` 各自从 1 起（见 §5.5 命名空间），只按 id 会**查错库**。

**§一** 拓扑里 `brand.json` 那行的 `（★ 尚未实现）` **去掉**（已于第 62 批 Step 4 写出）。

两侧 `DECISIONS.md` 各记一条（软件侧本仓；插件侧由用户转达）；`LINK-LOG.md` 追加 `[软件侧]` 回应。

### 3.3 不改的东西（明确边界）

- **镜像写入（`linkMirror.ts`）不动**：`brand.json` 已正确写出（真机读到 `scopes=[task:rev14 brand:rev33]`）。
- **不改 handoff 协议**：`req.json` / `res.json` 字段与语义不变；`res.file` 仍是 `handoff/incoming.<ext>`。
- **不做「分组同步开关 → 拒绝置入」**：插件面板只显示「已开同步」的素材，关掉的分组根本点不到 ⇒ 无需要。
- **`width`/`height` null 的兜底是插件侧的活**（docs/30 §五），本次不动。
