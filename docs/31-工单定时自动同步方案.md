## 0. 一句话

软件后台**自己按间隔拉工单**，不用再手点「同步」；工单视图头部显示「上次同步 HH:MM」，一眼看出数据新不新。

---

## 1. 先厘清：延迟到底出在哪一段（这是本方案最重要的结论）

issue 里提的方向是「软件同步前先用 wecom-cli 触发表格同步」，**这条走不通**，而且是企微产品限制、不是我们没做：

链路是 → `企微审批` →（**官方「审批自动同步」**）→ `工单智能表格` →（软件拉）→ `Vellum工作台`

| 环节 | 事实 | 依据 |
|---|---|---|
| 审批 → 智能表格 | 最小间隔 **1 小时**，**频率不可调** | 企微开发者社区答复：「智能表格同步其他表格数据的时间频率目前不支持调整」 |
| 有没有「立即同步」的接口 | **没有** | 官方答复：「暂无相关接口支持您描述的功能」；另一条：「通过企微提供的智能表格相关的 API 做不到直接同步别人创建的表格内容」 |
| CLI 侧 | 同样没有 | 核对内置 `wecom-cli 1.3.4` 命令树：`smartsheet` 下只有 `create / get / import / records / sheets / views / charts / fields / files / images`，**全是增删改查，没有任何"同步/刷新"命令** |
| 那个「立即同步数据」按钮 | **只在企微客户端里**，是给人点的 | 官方帮助文档「智能表格同步数据功能介绍」 |

**所以本方案的边界必须说清**：它能消掉「**手点软件**」这一步，**消不掉上游那 1 小时**。
上游要治只能动数据通路（webhook 接收外部数据 / API 直写，都要改造上游），另议。

## 2. 施工内容（照 docs/16 §3 原样，一处没改）

| 项 | 取值 |
|---|---|
| 启动首拉 | 软件启动后 **15 秒**（避开启动高峰，也让工作区初始化先跑完） |
| 后续间隔 | 每 **N 分钟**，默认 **30**，设置里可调 **10 ~ 1440**，可关 |
| 默认开关 | **开**（docs/16 §8 #3 的默认；老用户升级上来没有这个键 = 开） |
| 防重入 | 上一轮没跑完就到点了 → **跳过本次，不排队** |
| 失败处理 | **静默**：不弹窗，只在工单视图头部把「上次同步」标红（手动同步仍是 toast） |
| 可见性 | 工单视图头部「上次同步 HH:MM」 |
| 复用 | **复用现有同步链路**（`doTicketSync`），一字不改 —— 所以**自动同步和手动同步的行为完全一致，包括自动建任务**（2026-10-05 用户拍板：「照旧自动建（一致）」） |

## 3. 实现

| 文件 | 做了什么 |
|---|---|
| `src/main/ticketScheduler.ts`（新） | **纯调度**：排表 / 停表 / 防重入。业务动作靠注入（`run`），跑完怎么记账靠 `onDone` —— 调度不碰业务、业务不碰定时器，两边都能单独测（承接 docs/15 的架构铁律） |
| `src/main/ipc.ts` | 把 `ticket:sync` 的内联逻辑抽成 **`doTicketSync()`**（手动 / 自动共用）；新增 `ticket:autoSyncGet` / `ticket:autoSyncSet`；`registerIpc` 末尾起调度器；`will-quit` 停表 |
| `src/main/tickets.ts` | meta 键 5 个 + 读写函数（`autoSyncEnabled` / `syncIntervalMin` / `setAutoSyncEnabled` / `setSyncIntervalMin` / `readLastSync` / `writeLastSync`） |
| `src/preload/index.ts` + `src/shared/types.ts` | 三个接口打通：`ticketAutoSyncGet` / `ticketAutoSyncSet` / `onTicketSynced`（推送订阅，返回退订函数） |
| `src/renderer/.../TicketsView.tsx` | 工具栏「上次同步 HH:MM」（失败变红、点开设置）；订阅 `ticket:synced` 刷列表 —— **界面永不轮询** |
| `src/renderer/.../TicketSettingsModal.tsx` | 「自动同步」区：开关 + 间隔（与「允许指派」同一个「改动即存」模式） |
| `src/shared/copy.ts` | 新增 7 条文案（`autoSyncLabel` / `autoSyncInterval` / `autoSyncHint` / `lastSyncAt` / `lastSyncFailed` / `lastSyncNever` / `lastSyncFailedTip`） |

meta 键（跟工作区走，与一期同规矩）：

| 键 | 值 | 含义 |
|---|---|---|
| `ticket_auto_sync` | `'1'` / `'0'` | 开关（**未设 = 开**） |
| `ticket_sync_interval_min` | 数字 | 间隔分钟（读取时一律夹到 10~1440） |
| `ticket_last_sync_at` | ISO 串 | 上次同步时间 |
| `ticket_last_sync_ok` | `'1'` / `'0'` | 上次成功与否 |
| `ticket_last_sync_err` | 文本 | 失败原因（界面标红时的悬停提示） |

### 3.1 与 docs/16 §3 的两处实现差异（都是"更小更稳"取向）

1. **调度器做成独立纯模块 + 依赖注入**，而不是把 `setInterval` 直接塞进 ipc。
   好处：`clampIntervalMin` / 排表开关这些**能直接断言**（accept 里真的抓出一个 bug，见 §5）。
2. **`ran` 字段**区分"这轮真跑了"和"没配置好直接跳过"——
   没配置的机器不该反复写「上次同步」（否则界面会出现一个永远刷新的假时间）。

## 4. 施工中抓到的两个真问题

1. **`clampIntervalMin(null)` 返回 10 而不是默认 30**：
   `Number(null) === 0`、`Number('') === 0` 都是**合法数字**，会被当成"用户填的 0"夹到下限，
   默认值永远用不上。已改成先判空值 → 直接给默认值。
   **这个 bug 是 accept 断言抓出来的**（`ok(syncIntervalMin() === 30)` 直接红）。
2. **场景会被后台行为污染**：tickets 场景布景里配的是假 docid，若不关自动同步，
   软件启动 15 秒后会真去跑 `wecom-cli` 拉那张不存在的表。
   已在场景布景里**显式写 `ticket_auto_sync = '0'`**，自动同步的判定 / 记账逻辑交给 accept 断言。
