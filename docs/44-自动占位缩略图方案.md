## 0. 一句话

任务卡片目前「没成品图 → 显示一个灰图标」。改成显示一张**带项目名 / 任务名 / 标识的占位封面**，
背景同款、按项目换色 —— 让没图的任务在网格里也是「一张卡」而不是「一个洞」。

## 1. 为什么做

### 1.1 用户口述的需求

> 当检测到当前任务包内无缩略图时，自动生成一张上面写有**项目、任务名和工单号**的通用缩略图
> （缩略图背景样式相同，不同项目配色不同，**自定义项目统一一个配色**）。
> 按照每个项目一个配色，预先出个地图存在软件目录中，当检测到任务无缩略图时候将给对应背景图生成文字即可
> ——（"缩略图"到底是一张编译出来的图片还是 CSS 样式？）
> 每次刷新任务时看任务中是否有真正可用的缩略图，如果有就直接用真文件的缩略图。

用户自己把最关键的问题问出来了（图片 vs CSS）。**§2.4 专门回答它**，本批的形态决策全压在这一问上。

### 1.2 现状：封面链路只有一处出口

```
listPacks()  workspace.ts:3137-3145
  └ 封面 SQL：成品优先 → 素材 → 其他；跳过已丢失；取第一条
  └ coverPath = cover.thumb_path || cover.abs_path   ← 没图就是 null
        ↓
view:packs   ipc.ts:614-647
  └ coverPath 以 _thumbs 开头 → join(root, ...) → readAsDataUrl() → data URL
        ↓
PackCard.tsx:108-123
  └ pack.cover && imgOk  ? <img>  : <Placeholder />   ← 现在降级成一个 package 图标
```

**关键事实（本次实地核对）**：

| 事实 | 位置 | 意义 |
| --- | --- | --- |
| `pack.cover` **全渲染层只有一个消费者** | `PackCard.tsx:109` | 占位图是**纯卡片装饰** |
| 详情弹窗**不看封面** | `getPackDetail` 恒返回 `coverPath: null`（`workspace.ts:3337`） | 不用做第二处 |
| 报表导出的缩略图**不是这个** | 走企微表 `thumb_url`（`report.ts` / `reportWecom.ts`） | 与本功能无关 |
| 备份 / 导出 zip **原样打包**不注入文件 | docs/43 §3.1 | 与本功能无关 |

→ **结论：这个占位封面目前只服务任务卡片，是纯视觉补丁。**

## 2. 设计

### 2.1 触发口径

**"无真正可用的缩略图" = `pack.cover === null`。**

不额外定义一套判定 —— 现成的链路已经把该排除的都排除了：

- 封面 SQL 会**跳过 `missing_at IS NOT NULL` 的素材**（第 8 批口径：丢失的不当封面，让下一张顶上）
- 只认 `thumb_path IS NOT NULL OR ext IN (图片扩展名)` —— 非图片素材不会拿来当封面
- `PackCard` 自己还有一层 `imgOk`（`onError` 兜底）—— 文件读不出来时同样落到占位

**顺序保持不变**：有 `cover` 就渲染真图（哪怕它是缩略图缓存），**没有才**渲染占位封面。
这与用户「每次刷新时看有没有真正可用的缩略图，有就直接用真文件」的要求一致 —— 判定**每次渲染都做**，不做记忆。

### 2.2 配色

| 任务的项目 | 用什么色 |
| --- | --- |
| 有归属项目 | `pack.projectColor`（该项目的 `projects.color`） |
| 未归类（`project_id = null`） | 待拍板，见 §3-Q4（建议复用中性灰 `#6b7280`） |

**"自定义项目统一一个配色"** 这句需要用户确认口径（§3-Q2）—— 当前理解有两种：
① 用户手动新建的项目都发同一个色；② 未归类 / 自建任务统一一个色。

### 2.3 文字

封面区实际尺寸：宽 **216 ~ 290 px**、高固定 **132 px**（`.pack-card .thumb`，`object-fit: cover`）。
三行信息按"越靠上越次要"排：

```
┌──────────────────────────────┐
│ ▍海南升学集训营                │  ← 项目名  11px，项目色
│                              │
│   海南招生海报                 │  ← 任务名  15px / 500，浅色，最多 2 行
│                              │
│ 202610010001                 │  ← 标识   11px，半透明
└──────────────────────────────┘
```

- 任务名过长 → `-webkit-line-clamp: 2` 截断（**不能溢出撑破 132px**）
- 标识用 `taskCode()`，与卡片下方那行、与备份 zip 文件名**永远是同一个字符串**
- 无工单的自建任务显示 `T0023` 形态（第 58 批已定的规则）

### 2.4 ★ 核心决策：真图片，还是 CSS？

**先说可行性结论：两种都能做。** 本次**真跑过实测**，不是推测：

> 用项目自带的 sharp 渲染一张含中文的 SVG（`sans-serif` / `Microsoft YaHei` / `SimHei` 三种字体声明），
> 三个都正常出字，无方框、无乱码、无缺字 —— 产物见 `docs/images/44-实测-sharp渲染中文SVG.png`（已肉眼确认）。
> 原因：sharp 0.33+ 的 SVG 由 **resvg** 处理，走系统字体库，Windows 上直接吃 `C:\Windows\Fonts`。

所以这是**工程取舍**，不是能力边界。逐项对比：

| 维度 | **A. 真图片**（主进程 sharp 合成整张） | **B. CSS / DOM**（渲染层画） |
| --- | --- | --- |
| 中文渲染 | 实测可行，但依赖 resvg + **目标机器的系统字体**；精简/英文版系统可能缺中文字体 | **系统原生字体，永远不会出问题** |
| 文字清晰度 | 位图，必须**先定分辨率** —— 正好撞上刚讨论的 320 / 512 取舍 | **矢量文字，任意缩放倍率都锐利** |
| 项目/任务改名、工单号变化 | 必须设计**缓存键**（名 + 标识 + 色 + 尺寸），否则会出现「改名了图还是旧字」的经典 bug；有键就得有失效与清理 | **下次渲染自动正确，零失效逻辑** |
| 磁盘与清理 | 每任务一个文件 + 缓存目录 + 孤儿清理 | **零文件** |
| 打包体积 | 要预置背景图 + 进 `extraResources` | **零** |
| 主进程改动 | 新模块 + 缓存 + `view:packs` 扩展 | **一行都不用改** |
| 主进程渲染开销 | 每次刷新若有 N 个无图任务 → N 次 sharp（必须缓存，否则刷新卡顿） | **零**（浏览器排版） |
| 能不能当"真文件"用 | ✅ 能塞 zip / 传企微 | ❌ 只存在于界面 |

**推荐 B（CSS/DOM）**，理由很直接：

1. **A 的全部优势（当一个真文件用）在本项目里目前一条都不成立** ——
   备份 zip 原样打包不注入、报表走企微 `thumb_url`、详情弹窗不看封面。
   A 付了缓存/失效/打包/字体依赖的全部成本，换到的是**零收益**。
2. **B 的"不能当文件用"是可补齐的**：真到那天，用渲染层 `canvas` 把同一个 DOM 导成 PNG 即可 ——
   **字体还是系统字体**，比在主进程渲 SVG 更稳。所以 B 是更好的地基，而不是"退而求其次"。
3. **B 免掉了本批最容易出的那类 bug**：改名不同步、缓存不失效、孤儿文件。
4. 代价只有一条：**如果哪天需要"网盘上也有这张占位图"，要再加一层导出**。到时候再说。

> **备选 B'（混合）**：预置一张每种配色的背景图放 `resources/`，文字仍用 CSS 叠在上面。
> 只有在「背景要有质感 / 插画感，纯 CSS 画不出来」时才值得 —— 见 §3-Q6。
>
> **✅ 2026-10-10 拍板：采用 B（CSS/DOM）。** 六个待拍板问题见 §3。

### 2.5 界面落地（实际实现）

`PackCard` 里原来那个只有图标的 `Placeholder` 换成了 `GenericCover`（`PackCard.tsx`）：

```tsx
/** 未归类任务的兜底项目色（与 db.ts 的 PROJECT_COLORS 末位一致） */
const GENERIC_COVER_COLOR = '#6b7280'

function GenericCover({ pack, code }: { pack: PackCardType; code: string }): React.JSX.Element {
  const pc = pack.projectColor ?? GENERIC_COVER_COLOR
  return (
    <div className="gen-cover" style={{ ['--pc' as string]: pc } as React.CSSProperties}>
      <div className="gc-top">
        <span className="gc-dot" />
        <span className="gc-proj">{pack.projectName ?? COPY.card.noProject}</span>
      </div>
      <div className="gc-mid">
        <div className="gc-name">{pack.name}</div>
      </div>
      <div className="gc-bottom">
        <span className="gc-code">{code}</span>
        <span className="gc-mark" title={COPY.cover.markTip}>
          {COPY.cover.mark}
        </span>
      </div>
    </div>
  )
}
```

调用点保持**三分支原序**（真图优先，失败才落占位）：

```tsx
{pack.cover && imgOk ? <img … onError={() => setImgOk(false)} /> : <GenericCover pack={pack} code={code} />}
```

样式关键点（`main.css`，**10 个项目色都必须保证文字可读**）：

- 底色**不是**直接用项目色 —— `#e8a33d`（橙）`#8fa83d`（橄榄）这类浅色配白字对比度不够。
  做法：把项目色按低比例**混进深底**
  `linear-gradient(152deg, color-mix(in srgb, var(--pc) 30%, #16181c), color-mix(in srgb, var(--pc) 11%, #0f1013))`，
  再叠一层同色低透明度斜纹（`repeating-linear-gradient(135deg, …)`）做质感。**同款样式、只换色**。
- 项目名**不直接用 `var(--pc)`**：橙 / 橄榄 / 灰在压暗底上仍偏沉。
  统一用 `--pc-ink = color-mix(in srgb, var(--pc) 74%, #ffffff)`（往白里提亮 26%）——
  灰 `#6b7280` 会提到 `#9197a1`，十色都验过（见 §6 的自检图）。
- 左侧一条 3px 项目色竖条（`::before`），与卡片下方项目名徽标呼应。
- 右下角一枚中性色「占位」胶囊 —— **不放右上角**（那里被 `.pact` 编辑钮和 `.miss-flag` 丢失角标占了）。
- 任务名 `-webkit-line-clamp: 2`，溢出截断；中期区 `flex:1 / min-height:0` 保证底行不被挤出 132px 固定高。

### 2.6 明确不做

- **不改** 主进程封面逻辑（`listPacks` / `view:packs` 一行不动）
- **不写** 任何文件进 `_thumbs/` 或工作区
- **不落库**：占位是实时算的，不进 `assets.thumb_path`、不加 `packs` 列
- **不注入** 备份 zip / 导出 zip
- 不给详情弹窗加封面（它本来就没有）

## 6. 断言与场景（已落地）

**`accept.ts` 的 `[53]` 段（8 条）** —— 钉住「占位是纯渲染层的事」：

| 断言 | 防的是什么 |
| --- | --- |
| 有成品图任务 `coverPath` 指向真缩略图 | 真图分支没被误关 |
| **只有文档、没有图 → `coverPath === null`** | 界面**据此**才画占位（核心口径） |
| 未归类任务同样 `coverPath === null` | 未归类也走占位 |
| 未归类任务 `project_id` / `projectColor` 均为 null | 界面用兜底灰的**依据** |
| 有项目任务带出 `projectColor` | 换色的**依据** |
| 无图任务 `assets.thumb_path` 全为空 | **不落库**：占位不进缓存 |
| `packs` 表没有新增封面列 | **不落库**：本批无迁移 |
| 成品图删掉后 `coverPath` 回落到 null | 第 8 批口径不变；占位自动顶上 |

**`_shotapp` 的 `gencover` 场景（23 条）** —— 在真界面上验：

- 有图卡：渲染 `<img>`、**不画** `.gen-cover`
- 无图卡：五件套齐全（圆点 / 项目名 / 任务名 / 标识 / 占位角标），文案逐项比对字典
- 换项目 → `--pc` 换色（蓝 `#4f8cff` vs 红 `#f0603f`）
- 未归类 → 显示「未指定项目」+ `--pc = #6b7280`
- **超长任务名**：`line-clamp` 生效（高 40px = 2 行上限、`scroll 59 > client 40`），
  底行仍留在封面可视区内（132px 没被撑破）
- 没有卡片同时出现 `.gen-cover` 与旧的 `.ph` 灰图标

**视觉自检（十色）**：10 个项目色各出一张真实尺寸封面逐色核过 ——
底色与文字色都按实现里的混色公式算，全部可读（最险的是灰 `#6b7280`，提亮到 `#9197a1`）。

## 7. 风险（含实测结论）

1. **浅色项目色的可读性**（橙 `#e8a33d` / 橄榄 `#8fa83d` / 浅紫 `#d9a0ff` / 灰 `#6b7280`）——
   靠「底色混进深底 + 文字往白提亮 26%」解决。**已逐色眼验**（§6 末条），四色都清楚。
2. **占位与真图混淆** —— 卡片右下角加了「占位」胶囊（Q4）。角标刻意压成中性色，不抢项目名的戏。
3. **任务名过长撑破 132px 固定高** —— 已 `line-clamp: 2`；
   场景里用 33 字的超长名验过（高 40px、底行仍可见）。
4. **视觉冗余**（封面写了项目名 / 任务名 / 标识，卡片下方又各写一遍）——
   这是需求明确要的（「上面写有项目、任务名和工单号」）。实测看下来**不算过密**：
   封面那行是大字（扫视用），卡片下方是小字 + 徽标（精读用）。
5. **未归类任务的兜底灰与「用户真把项目色设成灰」在视觉上无法区分** —— 可接受：
   灰色项目本来就不该指望靠颜色区分。
