# 第 53 批：封面文件（`_封面.jpg` / `_封面.png`）方案

## 1. 需求

用户 2026-10-08 提出：

> 成品、工程、素材文件夹中文件若无能抓取缩略预览图的文件，可以在文件夹中放入一个
> 特定文件名（或特定前/后缀）的 jpg/png，软件扫到符合命名规则的文件就抓取成为
> 软件内与报表、工单中的缩略图（预览图）。

**已确认的四个决定**：

| 点 | 用户拍板 |
|---|---|
| 命名规则 | **固定文件名 `_封面.jpg` / `_封面.png`** |
| 与真实成品图的优先级 | **仅当没有可抓取的文件时才用它** |
| 是否出现在文件列表 | **照常出现，可管理** |
| 覆盖范围 | 软件内封面 **+ 工单「缩略图」列 + 报表**（报表复用工单的图，自动跟着） |

## 2. 要解决的问题（为什么需要它）

PPT / AI / ZIP 这类格式 **sharp 抓不出缩略图**。后果是：

- **包卡片没有封面** —— `listPacks` 的封面查询只认
  `thumb_path 非空` 或 `ext IN (jpg/jpeg/png/webp/gif/bmp)`；
  一个只有 `.pptx` 的包取不到任何候选 → `coverPath = null` → 卡片空白。
- **工单「缩略图」列永远是空的** —— `completeTicketTask` 拿「成品」里的文件逐个
  `ensureAnyThumb`，`.pptx` 失败 → `thumbPaths` 为空 → 直接返回
  `completeNoThumb`（"没有可用的成品图"）。用户点「完成任务」只会拿到这个报错。
- 报表的缩略图来自工单的 `thumb_url` → 一并是空的。

**用户真实现状即为此**：包「培训PPT」的 `03-工程` 里只有 `.pptx`，
`02-素材` 里是 mockup 图（能抓，但那不是"成品封面"的语义）。

## 3. 命名规则（刻意的严格）

- 文件名词根**必须恰好是 `_封面`**（精确相等，不是"包含"）
- 扩展名认 `jpg` / `jpeg` / `png`，**扩展名不分大小写**（`_封面.PNG` 也认）
- `jpeg` 一并收：它和 `jpg` 是同一种格式的两种后缀，只认一个会让人白踩坑

**明确不认**（避免误伤普通素材）：

| 文件名 | 认不认 | 为什么 |
|---|---|---|
| `_封面.jpg` / `_封面.png` | ✅ | 就是这个规则 |
| `_封面.PNG` | ✅ | 扩展名不分大小写 |
| `_封面.jpeg` | ✅ | jpg 的另一种后缀 |
| `封面.jpg` | ❌ | 缺下划线 —— 太容易和普通素材撞名 |
| `_封面图.jpg` | ❌ | 不是精确相等 |
| `_封面.gif` / `_封面.webp` | ❌ | 只认 jpg/jpeg/png |
| `_封面`（无扩展名） | ❌ | 图片必须有扩展名才能判类型 |
| `x_封面.jpg` | ❌ | 前缀不符 |

下划线开头还有个附带好处：在资源管理器里天然排在最前，用户一眼能看到。

## 4. 优先级：只做兜底，不抢戏

**核心口径：只有在"没有任何可抓取的文件"时才用它。**

- 包封面（`listPacks`）：原有查询（成品>素材>工程，取第一个有 `thumb_path` 或图片扩展名的）
  **保持原样优先**；只有它返回空，才退到封面文件。
- 「完成任务」（`completeTicketTask`）：先按原逻辑对「最新版本的全部成品」逐个抓图；
  **只有一张都没抓出来**，才退到封面文件。
  - 另外补一处：「一个成品都没有」时也退到封面文件（原来直接报 `completeNoAsset`）——
    这种包通常就是"只丢了个 PPT 进来"，用户既然放了封面，就该用。
  - 兜底成功后 `thumbFail` 归零：那些"抓不出来的成品"不再算"缺张"，
    否则界面会同时提示"成功 1 张 + 缺 1 张"，自相矛盾。

**为什么不做成"优先"**：用户的原话是"若无能抓取缩略预览图的文件"——
它的定位是**补空白**，不是**替代真实成品图**。做优先会改变现有所有包的行为。

## 5. 它仍然是一个正常素材

按用户拍板：**照常出现在文件列表里**——可打标签、算进文件数、参与搜索。
它不是"隐藏的配置项"，只是**顺带**能当封面。

好处：用户想换封面就正常删掉/替换那个文件即可，不需要另一套 UI 或设置项。
本批**不新增任何界面**（零新按钮、零新设置），完全靠命名约定 + 扫描。

## 6. 实现要点

| 位置 | 改动 |
|---|---|
| `workspace.ts` | 新增 `COVER_BASENAME` / `isCoverFileName()` / `findCoverFile(packId)` |
| `tickets.ts` `completeTicketTask()` | 两处兜底：无成品时 / 抓不出图时 |
| `listPacks()` 包封面 | **不改** —— 见下 |

### 6.1 包卡片封面**不需要改代码**（施工中发现，如实记下）

原以为包卡片也要补兜底，写完后核对发现**原来就抓得到**：

```sql
-- listPacks 里原有的封面查询（一字未改）
WHERE pack_id = ? AND missing_at IS NULL
  AND (thumb_path IS NOT NULL OR ext IN ('jpg','jpeg','png','webp','gif','bmp'))
```

候选条件**已经包含 jpg/jpeg/png**，而本批的封面文件只可能是 jpg/jpeg/png ——
所以放进包里**本来就会被它选中**。再加一段"兜底"是**永远走不到的死代码**，
还要多一次查询。故**撤掉**，只保留一句注释说明为什么这里不用动。

**唯一真正缺的一条路是「完成任务」**：它只查 `role='成品'`，
封面文件放在 `02-素材` / `03-工程` 就够不着 —— 这才是本批要补的。

### 6.2 SQL 细节

匹配用 `file_name LIKE '\_封面.%' ESCAPE '\'` ——
SQL 里 `_` 是**单字符通配符**，不 ESCAPE 的话会匹配到 `X封面.jpg`。
扩展名的大小写在 JS 里判（SQL 里判很啰嗦）。

**不删不改磁盘**：本批只读文件名，不移动、不改名、不新建任何文件。

## 7. 验收口径

**accept**

- `isCoverFileName` 的**正例与反例逐条**（含上表所有"不认"的情形 + 大小写扩展名）
- `findCoverFile`：有则返回路径、无则 null；`missing_at` 非空的**不算**
- 包里有多张时取**更靠前**的（成品 > 素材 > 工程）
- **包封面（回归保护）**：只有 `.pptx` 的包 `coverPath = null` → 放入 `_封面.png` → `coverPath` 变成它（**靠原有查询**，非本批新增代码）
- **不抢戏**：包里同时有正常图片和 `_封面.png` → 封面仍是**正常图片**（成品优先）
- **「完成任务」兜底**：只有 `.pptx` 的包原来返回 `completeNoThumb` →
  放入 `_封面.png` 后**成功**且返回的是封面那张
- **无成品**的包（连 pptx 都没有）放入封面 → 也能成功
- `_封面.png` 自己**照常入库**（在文件列表里能看到、算进文件数）

**界面场景**

- `versions` 场景：包卡片封面能正常显示（回归保护，别把原有封面弄坏）
