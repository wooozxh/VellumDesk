# 60 · 导出报表双模板方案（流水报表 + 月度报表）

> 状态：**已确认并实施**（2026-11-18 用户拍板「开工」，第 86 批）
> 分支：`feature/pslink-preview`（起点 HEAD `d8b10ba`，第 85 批）
> 前置：`docs/22-导出报表方案.md`（单模板方案，本批在其上扩类型）
> 本文**不含任何内部标识符**（表格编号 / 子表 ID / 字段 ID / 真实姓名一律不出现）。

---

## 0. 一句话

导出弹窗从「一种报表」扩成「两种」：**流水报表**（现有逻辑，12 字段，按起止日期）和**月度报表**（新增，9 字段，按起止日期筛、**一位设计师一张子表**，供向上汇报月度产出）。两套模板、两套字段映射，共用同一套取数与缩略图链路。

**两个前置结论**：
1. 智能表格的「子表文件夹 / 分组」没有开放 API，只能平铺；子表名带月份前缀，同月自然相邻（证据见 §2.3）。
2. 「设计师 → 制作人」术语统一**已取消**（用户 2026-11-18 决定），全项目继续叫「设计师」。

## 1. 需求（用户原话，2026-11-18，三轮）

**第一轮**：

> 导出报表首先可以选择我是要导出这种叫流水报表、就是总报表，就是之前的那个逻辑，选择起始时间，然后按照模板导出字段。还有一种叫做导出月报表，月报表是我们公司现在新要求的，就是会向上汇报每一位制作人、也就是我们的同事们的月度产出。需要的字段我都写在模板里了。有一些字段是留空就可以了，必须得是设计师手填的，比如物料体量，备注也是要设计师手填的。

**第二轮**：

> 每次导出的时候建一个文件夹，文件夹名字就是几月份，然后里面会有四张智能表格子表，分别命名为制作人的名字 —— 一个子表就是一个人的单子。无制作人的单，结果报跳过 N 条就可以。老流水模板可以修。

**第三轮（推翻前两轮的命名与术语）**：

> 我把表里的制作人又改回设计师了，今后都以设计师相称，术语统一这个事儿就不需要了。文件夹可以接受平铺，每一个子表的名字就是「几月谁谁谁月度报表」，我到时候手动再去归到文件夹里。我怕万一不倒一个月、可能倒半个月，所以还是希望能有个起始时间。一单多人就是每个人表里各出现一次就可以。

拆成六条硬要求：

1. 弹窗里能选类型：流水 / 月度。
2. 月度报表按**设计师**归集，**一人一张子表**。
3. 月度报表**也要起止时间**（不只整月，可能半个月）。
4. 子表命名：`几月 + 谁 + 月度报表`。
5. 无设计师的单**跳过**，结果报条数。
6. 一单多人 → 在每位设计师的表里各出现一次。

## 2. 真表核实（2026-11-18，wecom-cli 实读）

### 2.1 模板子表

| 模板子表 | 字段数 | 模板内记录 | 用途 |
|---|---|---|---|
| 报表模板（总报表） | 12 | 5 条历史残留 | 流水报表 |
| 报表模板（月度报表） | 9 | 1 条空行 | 月度报表 |

### 2.2 月度模板 9 字段（真表顺序与类型）

| # | 字段 | 类型 | 导出时 |
|---|---|---|---|
| 1 | 工单类型（印刷/电子） | 单选（印刷 / 电子） | 软件写 |
| 2 | 编号 | 文本 | 软件写 |
| 3 | 完成时间 | 日期 | 软件写 |
| 4 | 物料名称 | 文本 | 软件写 |
| 5 | 业务归属 | 文本 | 软件写 |
| 6 | 设计师 | 成员（多选） | 软件写（本地设计师子表全量） |
| 7 | 物料体量 | 数字（不限小数位） | **留空**（设计师手填） |
| 8 | 缩略图 | 图片 | 软件写（逐张重新上传） |
| 9 | 备注 | 文本 | **留空**（设计师手填） |

> 已复核：两个模板的成员列名**都已改回「设计师」**，与代码现有常量一致，无需改口径。
> 月度模板没有申请人、印刷数量、印刷金额、绩效金额 —— 绩效核算仍只走流水报表。

### 2.3 「子表文件夹」能力实探（结论：不支持）

| 查项 | 结果 |
|---|---|
| 子表增 / 删 / 改 / 查接口 | 请求与返回里**没有任何分组、父级、目录字段** |
| 新建智能表格文档 | **不能指定父文件夹**（无 folder / parent 参数） |
| 微盘 | 能建文件夹，但**没有「移动已有文档」的命令** |

**结论**：客户端手动能建的「子表分组」，API 未开放，软件只能平铺建表。

**可接受的原因**：子表按创建顺序追加，一次导出连续建的同月几张表天然相邻，视觉上已是一组；用户接受导出后手动归档。

## 3. 唯一必须先修的地基问题

**模板子表改名 → 现有导出已经失效。**

代码读模板用的子表名来自本地配置，当前值仍是旧名「报表模板」；真表里已改名为「报表模板（总报表）」。

实测：用旧名查字段，命令直接失败（非空退出码，拿不到任何字段）。
**结论：现在点「导出」会失败，不是“可能失败”。** 本批第 1 步修掉。

## 4. 方案

### 4.1 类型与字段映射

```
ReportKind = 'flow' | 'monthly'
```

| 逻辑字段 | 流水（flow） | 月度（monthly） |
|---|---|---|
| 工单类型 | 工单类型（印刷/电子） | 同左 |
| 编号 | 编号 | 同左 |
| 完成时间 | 完成时间 | 同左 |
| 物料名称 | 物料名称 | 同左 |
| 业务归属 | 业务归属 | 同左 |
| 申请人 | 申请人 | —（模板无此列） |
| 设计师 | 设计师 | 设计师 |
| 缩略图 | 缩略图 | 同左 |
| 印刷数量 | 印刷数量 | — |
| 印刷金额 | 印刷金额 | — |
| 绩效金额 | 绩效金额 | — |
| 备注 | 备注（本地字段） | **留空** |
| 物料体量 | — | **留空** |

序列化按类型分支：某列在模板里不存在时**静默跳过**；模板缺该类型**应有**的列时才警告。

### 4.2 取数与时间口径

复用现有 `buildReportRows(start, end)`（按完成时间闭区间、排除留底单、JOIN 本地字段 + 设计师子表），两种类型**都传起止日期**：

- 流水：`ORDER BY 完成时间, id`
- 月度：先按设计师分组，组内 `ORDER BY 完成时间, id`

弹窗里月度类型的日期控件默认**当月 1 号 ~ 月末**，但可以改成任意区间（导半个月、导跨月都行）。

**无设计师的单**：跳过，返回 `skipped: N`，toast 明确报「跳过 N 条无设计师」。

### 4.3 月度子表结构（一人一张）

```
2026-11 某某 月度报表        ← 设计师 A 当月的单
2026-11 另一人 月度报表      ← 设计师 B 当月的单
...
```

| 项 | 规则 |
|---|---|
| 拆分粒度 | **一位设计师一张子表**，只装该人在区间内完成的单 |
| 子表命名（整月） | `YYYY-MM 姓名 月度报表` |
| 子表命名（非整月） | `YYYY-MM-DD~DD 姓名 月度报表`（见 §4.4 撞名问题） |
| 设计师来源 | 本地设计师子表全量 |
| 一单多人 | **在每位设计师的表里各出现一次**（按人计产出） |
| 子表内顺序 | 完成时间升序 |
| 空人 | 区间内无单的设计师不建表 |
| 无设计师的单 | 跳过 + 报条数 |
| 字段结构 | 每张表复制月度模板的 9 字段 |
| 缩略图 | 表内每条单逐张重新上传到报表文档空间（现状链路） |

> 「四张」不是常量，按区间内实际有单的设计师人数动态生成。

### 4.4 撞名：半个月导两次怎么办

这是「支持任意起止」带出来的真问题：同一个人同一个月导两次（上半月 + 下半月），如果都叫 `2026-11 某某 月度报表`，两张表同名，肉眼分不清。

| 场景 | 命名 |
|---|---|
| 起 = 当月 1 号 且 止 = 当月最后一天（整月） | `2026-11 某某 月度报表` |
| 其他任意区间（含跨月） | `2026-11-01~15 某某 月度报表` / `2026-11-20~12-05 某某 月度报表` |

这样整月导出保持你要的简洁命名，非整月自动带区间，两张表不会混。**本批不做同名检测/覆盖**（属 D 方向）；如果区间完全重复导两次，仍会建出两张同名表，靠导出时间区分。

### 4.5 配置与容错

- 表格编号沿用现有配置，不变。
- 新增两个模板名配置：流水模板、月度模板（默认值 = 真表现名）。
- 老配置键保留回落：读不到新键时用旧键，避免老工作区升级后配置丢失。
- **模板读不到时不再静默失败**：新增「列出该表格全部子表」的查询，导出前若模板名对不上，弹窗让用户从候选里选，选完记住。

### 4.6 界面

导出弹窗加一行「报表类型」：

- **流水报表**：显示起止日期（现状），12 字段。
- **月度报表**：显示起止日期（默认当月整月，可改），9 字段；下方说明「每人一张子表；物料体量、备注导出后由设计师填写」。

结果 toast：

- 流水：`已导出 N 条到「起~止」`
- 月度：`已导出 N 条 / M 张子表`；有跳过时追加 `（跳过 K 条无设计师）`

### 4.7 导出流程

```
选类型
 ├ 流水：取流水模板 → 0 条直接返回（不建子表）
 │        → 建 1 张子表（起~止）→ 序列化 12 字段 → 缩略图逐张重传 → 写记录
 └ 月度：取月度模板 → 取区间数据 → 按设计师分组
          ├ 无可用分组：直接返回（不建子表）
          └ 有：对每位设计师
                 建 1 张子表（命名见 §4.3，复制 9 字段）
                 → 序列化 7 列（体量/备注不写）
                 → 缩略图逐张重传
                 → 写记录
          → 汇总：张数 / 总条数 / 跳过数 / 警告
```

## 10. 风险

| 风险 | 对策 |
|---|---|
| 同一区间重复导出 → 同名子表 | 非整月命名自带区间，能区分大部分；完全重复仍会重名，靠导出时间辨认（同名检测属 D 方向） |
| 每月 N 张子表，一年几十张 | 月份前缀 + 创建顺序相邻；用户接受手动归档 |
| 多人协作单重复计入 | 已确认按人计产出；若以后要分摊，需先定规则 |
| 模板里 5 条历史记录 + 1 条空行 | 建子表只复制字段、不复制记录；建议顺手清掉 |
| 某设计师当月只有无设计师的单 | 该人不建表；结果报跳过条数 |
| 月度报表不含金额 | 绩效仍走流水报表 |

## 11. 刻意不做

- 不做子表文件夹（API 不支持）。
- 不做术语统一（已取消）。
- 不做每人小计行（靠智能表格视图分组/统计）。
- 不做物料体量自动估算（无口径，用户明确要手填）。
- 不做 26 号切月等自定义结算周期。
- 不做导出前预览、同名覆盖（属 D 方向，另批）。
