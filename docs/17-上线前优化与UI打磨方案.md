## 1. A 块：进度反馈与性能（刷新扫描）

### 1.1 现状实探（2026-10-01 读码确认）

- **主→渲染零推送通道**：全项目没有一处 `webContents.send`；渲染端只有 `scanning` 布尔状态，按钮转圈，用户不知道跑到哪了、要等多久。
- **整条链路单个 IPC 一口气跑完**（`ipc.ts` 的 `scan:refresh`）：`scanAll` → `ensureThumbsForAssets`（缩略图）→ 图片尺寸 → 视频探测 → PSD → PDF，最后一次性返回统计。大库 + 视频多时能等几分钟，全程无反馈、不可中断。
- **缩略图串行生成**（`thumbs.ts` `ensureThumbsForAssets`）：`for` 循环逐条 `await`，一张做完才做下一张。`onProgress` 回调钩子已经存在但**没有任何调用方消费**。
- 启动流程没问题（窗口先显示，四类元信息后台补齐不阻塞），本块不动启动。

### 1.2 改造内容

1. **新增主→渲染推送通道 `scan:progress`**（项目第一个 push 通道）：
   - 主进程 `scan:refresh` 内部按阶段推：`{ stage: 'scan' | 'thumbs' | 'meta', done, total, label }`；
   - preload 暴露 `onScanProgress(cb)` 订阅 + 退订；渲染端 App 顶栏 / 扫描按钮处显示「缩略图 37/214」这类文字进度（细进度条样式待 C 块一起定，避免返工）。
2. **缩略图并发化**：串行改并发（图片 sharp 并发 3~4；视频 ffmpeg 抽帧并发 2，避免多进程抢 CPU；PSD/PDF 保持串行——pdfjs 同进程渲染）。完成后逐条回写 `thumb_path`（现逻辑已是逐条 UPDATE，保留）。
3. **元信息阶段复用同一通道**：图片/视频/PSD/PDF 补齐也报 `done/total`。
4. **验收**：accept 补断言——注入假数据源跑 `ensureThumbsForAssets` 验证 onProgress 回调次数与 done 单调递增、并发完成后落库条数与串行一致；**进度推送属主进程改动，配一条界面场景断言**（环境坑速查：凡动 IPC/全局链路必须配场景）。断言 658 只增不减。

### 1.3 明确不做（避免范围膨胀）

- 不做扫描中途取消（要动 `scanAll` 内部结构，风险大收益小；等进度可见后用户体感已解决大半）。
- 不动启动速度（现状已达标）。
- 不做增量扫描 / 文件系统监听（watch 库是另一个量级的工程）。

## 2. B 块：代码签名 / 安装体验

### 2.1 现状与后果

- 安装包**无签名**。同事下载 NSIS 安装包运行时，Windows SmartScreen 大概率弹「Windows 已保护你的电脑」蓝底红字——需要点「更多信息 → 仍要运行」。**不拦死，但第一印象差**，且每个同事第一次装都会撞。
- 签名在**出包机器**上做（即本机），不影响同事机器，纯出包流程改造。

### 2.2 三条路线（2026-10-01 行情，需拍板）

| 路线      | 成本                                           | 效果                                                    | 周期                              |
| ------- | -------------------------------------------- | ----------------------------------------------------- | ------------------------------- |
| ① 不买证书  | 0                                            | 装机说明写清「更多信息→仍要运行」两步绕过；红条仍在                            | 立即                              |
| ② OV 证书 | 约 1800~3200 元/年（国内代理报价，GlobalSign/Sectigo 等） | 弹窗从「未知发布者」变为显示公司名；SmartScreen 信誉需下载量累计，初期仍可能弹（弹的是温和版） | 企业资质审核 1~3 工作日 + USB Token 顺丰邮寄 |
| ③ EV 证书 | 约 3100 元/年起                                  | **立即**获得 SmartScreen 信誉，不弹                            | 审核更严，周期更长                       |

注：CA/B Forum 规则要求私钥存硬件 Token，OV/EV 都要邮寄 U 盘，没有纯线上秒发。

### 2.3 若买证书（②或③）

- electron-builder 配置 `win.signtoolOptions`（证书颁发者+Token PIN，Token 插本机出包时用）；出包后 `signtool verify` 验证双签。
- 需要你提供：企业主体（营业执照，营销中心挂靠的公司名）+ 经办人信息。
- **不影响本批代码施工**：证书审批/邮寄与 A、C 块并行，到位后出包时接上即可。

## 3. C 块：UI 细节打磨（用户点名清单，已核实）

### 3.1 痛点1：标签管理面板选颜色的按钮「外圆内方」

- **现状**：`TagManagerModal` 的颜色选择器是原生 `<input type="color" className="tm-color">`；CSS 给外框加了 `border-radius: 50%`，但 Chromium 的内层色块（`::-webkit-color-swatch`）不受外框圆角影响 —— 于是外圈是圆的、里面是方块；且输入框 24×20 非正方形，圆形实际是**椭圆**。
- **改法**：补两条伪元素规则（`::-webkit-color-swatch-wrapper` 与 `::-webkit-color-swatch` 各自 `padding:0` + `border-radius:50%` + 去内边框），尺寸统一成 **20×20 正方圆点**，与列表里的 `.tm-dot`（11px 圆点）视觉同源；hover 时描边提亮。
- **影响面**：纯 CSS，零逻辑改动；不动文案。

### 3.2 痛点2：标签面板要预制「我设计好的标签」

- **影响面**：`db.ts`（presets/colors）、`copy.ts`（seed 键）、`accept.ts` 三处预制断言（预制「海报」保留、「详情长图/视频号」等换成新名）。

### 3.6 ⚠️ 文案流程的一个例外（需你知悉）

预制清单与「砍维度」属于**结构性文案变更**：`copy.ts` 要**新增** 18 个条目、**删除** 7 个条目（3 状态标签 + 2 维度名 + 2 项目名/备注调整）。而 `tools/copy-sheet` 的 `apply.cjs` 有硬自检「**条目总数不变**」，只支持改值、不支持增删条目。
