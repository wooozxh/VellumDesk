## 0. 一句话

软件里新增一个**不属于任何任务**的素材库 —— 公司通用素材（logo / 字体 / 教材封面…）+ 设计师个人收藏，
按**两层分组**组织，随镜像的 `brand.json` 进 PS 插件供调用。

## 1. 定位与边界（用户 2026-10-10 明确）

- **内容** = **公司通用素材 + 用户自积累素材**（一个**跨任务包**的公司/个人素材池），**不只是"品牌识别素材"**。
- **与任务库的本质差别是「归属」**：任务库的素材挂在「项目 / 任务包」下；**通用库的素材不属于任何任务**。
- **存储**：**工作区内** `<工作区>\_通用素材库\`（用户拍板）—— 资源管理器里可见、可手工整理，贴合
  本项目铁律「**本地磁盘是唯一真相，软件只是镜子**」。
- **分组：两层**（父组 → 子组），文件夹**用户可自定**。
- 用户给的示例结构：
  ```
  D:\vellum_workspace\_通用素材库\
    公司素材\
      品牌logo\
      字体\
    个人收藏\
      背景\
      纹理\
  ```

## 2. 为什么放 `_通用素材库`（下划线开头）

- 扫描器 `collectFiles` **跳过所有 `_` / `.` 开头的项**（`workspace.ts:71-78`，软件自用目录的既有约定）
  → 通用库**不会被任务扫描误登记**成"未归属散文件"。与 `_thumbs` / `_system` / `_回收站` 同一路数。
- 它有**自己的扫描器**（只扫这一个根），与任务扫描互不干扰。

> ⚠️ 踩过的坑（第 53 批）：`_封面.jpg` 因为下划线开头**进不了库**。所以通用库**必须有自己的扫描**，
> 不能指望通用扫描会捡到它。

## 3. 数据模型（迁移 22）

两张新表，**独立于 `assets`**：

```sql
CREATE TABLE IF NOT EXISTS brand_folders (
  id             INTEGER PRIMARY KEY AUTOINCREMENT,
  parent_id      INTEGER REFERENCES brand_folders(id) ON DELETE CASCADE,  -- NULL = 顶层
  name           TEXT    NOT NULL,
  sort_order     INTEGER NOT NULL DEFAULT 0,
  rel_path       TEXT    NOT NULL DEFAULT '',   -- 相对工作区根：_通用素材库\公司素材\品牌logo
  sync_to_plugin INTEGER NOT NULL DEFAULT 1,    -- 分组级同步开关
  created_at     TEXT    NOT NULL,
  UNIQUE(parent_id, name)
);
CREATE TABLE IF NOT EXISTS brand_assets (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  folder_id    INTEGER REFERENCES brand_folders(id) ON DELETE SET NULL,
  file_name    TEXT    NOT NULL,
  ext          TEXT    NOT NULL DEFAULT '',
  size         INTEGER NOT NULL DEFAULT 0,
  abs_path     TEXT    NOT NULL UNIQUE,
  rel_path     TEXT    NOT NULL DEFAULT '',
  thumb_path   TEXT,
  width        INTEGER, height INTEGER, color_mode TEXT,
  duration_ms  INTEGER, video_codec TEXT, probe_info TEXT,
  missing_at   TEXT,
  created_at TEXT NOT NULL, modified_at TEXT NOT NULL, scanned_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_brand_folders_parent ON brand_folders(parent_id);
CREATE INDEX IF NOT EXISTS idx_brand_assets_folder ON brand_assets(folder_id);
```

- 迁移号 **22**，追加在 `db.ts` 的 `migrate()` **末尾**（现最高 21，`db.ts:835-852`）。
- **新表可以自带索引**（老表补列才要求索引写在 ALTER 之后，本批不 ALTER）。

### 3.1 为什么不复用 `assets` 表

复用看着省事（`pack_id` NULL + 加一列 `brand_folder_id`），但会**污染一大堆既有查询**：
未归属池 / 文件视图 / 左栏统计 / 标签计数 … 全都要加"排除通用库"的谓词 ——
这正是坑表里 **「隐身类语义改动要全量过 SQL」** 的高危场景（第 7 批就漏过一处，靠用户实测才发现）。
**独立两张表 = 零污染**；代价只是多写一套（字段全是从 `assets` 照抄，缩略图/元信息采集**复用同一批函数**）。

### 3.2 id 与缩略图命名

- 任务库与通用库**两张表、id 各自从 1 起** → 镜像里的缩略图必须加命名空间：
  `thumb\t<id>.png`（任务）/ `thumb\b<id>.png`（通用）—— 见 `docs/45` §5 契约影响 ②。
- 缩略图缓存**复用** `_thumbs\<key>.webp`（`ensureThumb`，`thumbs.ts:124`），**不新建第二套缓存**
  （key 是 `abs_path|size|mtime` 的 hash，天然不冲突）。

## 4. 磁盘结构 & 扫描

- 根：`<工作区>\_通用素材库\`（**首次使用自动建**；不自动建任何子组）
- 组：`<根>\<父组>\<子组>\` —— **两层封顶**
- 文件：直接放子组里
- **组名 = 文件夹名**，改名**连带改文件夹名**（照 `projects.folder_name` 的路数）
- 软件里建 / 改名 / 排序 / 删除组 → 同步磁盘；反过来在资源管理器里手建文件夹 → 通用库**扫描**时自动认领
  （保住"软件视图 = 磁盘现实"这条铁律）
- 删除/丢失口径照第 8 批：文件丢了 → `missing_at` 标记，**不删记录**（软件永不偷偷扔用户东西）

## 6. 随镜像进插件（`brand.json`）

- 只有 `sync_to_plugin` **生效**的组 + 其素材进 `brand.json`（契约 §5.3）。
- `groups[]` 用**两层**：顶层组 `parentId = null`，子组带 `parentId` —— **这是契约加法**（§十，不升版），
  需两边同时知悉、改契约正文 + 两侧 DECISIONS 各记一条。
  —— **2026-10-11 插件侧已确认**（v0.2.8 落地）；插件侧 `parentId` 宽容处理（缺失 / `null` / 空串 / 悬空 / 三层以上 → 顶层，绝不丢素材）。
- `asset` 结构照契约 §5.4（与 task 一致）；`source`（`company`/`user`）为**可选**字段（✅ 定：要）。
- `thumb` 用命名空间 `b<id>.png`（见 `docs/45` §5）。
