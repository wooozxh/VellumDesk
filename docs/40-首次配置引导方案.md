# 第 54 批（子项 2）：首次配置引导（初装向导）方案（docs/40）

> 本批 = 第 54 批，版本 **1.9.5**，含两个子项：`docs/39-任务快捷方式方案.md`（子项 1）+ 本文件（子项 2）。  
> 两件事**不改数据库结构**（无新增迁移），方案分别过审后一起施工、一起出包。

---

## 1. 需求（用户原话）

> 安装后首次打开软件弹出配置引导，包括 wecom-cli 认证、工单/报表配置、工作区选择等全局配置。

**用户附带的一条（2026-10-09）**：

> 欢迎窗口后续我可能会改样式，现在还没想好。

→ 直接后果：**欢迎页 / 向导的视觉样式本批不定稿**（见 §7），本批只落「流程 + 功能 + 骨架」。

## 2. 现状：软件现在的"首次体验"是**四个碎片**，散在不同地方

| 碎片                   | 现在在哪                                                | 现在怎么触发                   |
| -------------------- | --------------------------------------------------- | ------------------------ |
| 工作区择址                | 主进程启动时**自动**做（首选 `D:\vellum_workspace`，没 D 盘落到「文档」） | 无界面、无确认                  |
| 企微扫码授权               | 「企业微信连接引导」弹窗                                        | 首次启动**自动弹一次**；入口常驻在工单设置里 |
| 工单表配置（粘智能表格链接 + 选子表） | 「工单同步设置」弹窗                                          | 用户自己去点齿轮找                |
| 报表表配置（粘链接）           | 「导出报表」弹窗里的一格                                        | 用户月底导出时才第一次见到            |

**问题**：新同事装完打开软件，看到的是**工单队列**（启动默认视图），一屏空白，**没有任何一句"这台机器还没配过，建议先做这几步"**。素材管理那些（工作区、项目、标签）倒是开箱可用，但工单这条路要自己摸出"先扫码 → 再粘链接 → 再勾子表 → 报表还得再粘一次"。

**本子项要做的**：把这四步**串成一条一次走完的引导**，并且**只对真正的新人弹**。

## 3. 向导流程（6 步）

| 步  | 名称         | 内容                                                           | 必做？      |
| -- | ---------- | ------------------------------------------------------------ | -------- |
| S0 | **欢迎**     | 一句话说清"这个软件能干什么、接下来要配什么（大概 2 分钟）"；按钮：`开始配置` / `我以后再说`         | —        |
| S1 | **工作区**    | 显示软件**已经自动选好**的位置（含完整路径）+ 「更改位置」按钮（复用既有的选目录并切过去）；一句话说明"整个文件夹拷走 = 完整备份"     | 建议做（可跳过） |
| S2 | **连接企业微信** | 扫码授权区（与工单设置里的引导**共用同一个面板**）；一句话说明"只影响工单，其余功能完全离线可用"     | **可跳过**  |
| S3 | **工单表配置**  | 说明 + **「打开工单同步设置」按钮** —— 直接复用已有的设置弹窗（粘链接 / 连接 / 勾子表 / 保存），**不在向导里重造一套** | **可跳过**  |
| S4 | **报表表配置**  | 向导内联：一个输入框 + 「记住这个链接」（新开一个只写配置、不导出的口子）；明确标注"**月底导报表才需要**"                    | **可跳过**  |
| S5 | **完成**     | 一张"这台电脑配了什么"的清单（工作区 / 企业微信 / 工单表 / 报表各自标 已配置·已跳过·未配置）+ 各项以后去哪找；按钮：`完成` | —        |

- 顶部有简单步骤指示（`第 N 步 / 共 6 步`），支持 `上一步`（S0 无）。
- **每一步都能跳过**——不逼人配（用户可能只是纯素材用户）。
- 向导**不替用户做任何决定**：不自动扫描、不自动同步、不自动改任何已有配置。
- **点「完成」** → 写标记 + **自动跳到工单队列**，并提示"想立刻拉数据，点一下「同步工单」"（用户拍板 W11）；
  **点「我以后再说」** → 只关掉、只写标记（人家说了以后再说，不硬把人拽到工单队列）。
- S5 的汇总**只报事实**：企业微信看授权状态、工单表读一次配置状态、报表看有没有存过链接 —— 不猜。

## 4. 触发与状态（本子项最容易出错的地方）

### 4.1 判据：**库是不是本次新建的**

- **弹的三种情况**：真正的新装 / 换了 Windows 登录账号 / 换了新电脑（工作区里没有库 → 这次现场新建）→ 都是"库本次新建"
- **不弹的两种情况**：
  - **老用户升级**（库里 `media.db` 早就在，哪怕配置文件换了新目录、要重选一次工作区）→ **不弹**
  - 已经走过一次向导（点过「完成」或「我以后再说」）→ **不弹**
- ⚠️ 判据刻意**不用"配置文件在不在"**：第 28 批 userData 目录改过名，老用户升级时配置文件本来就是"没有"的——拿它当判据会**把老用户全弹一遍**。库在不在，才是"这台机器配没配过"的真相。

### 4.2 状态标记（meta，无新增迁移）

| 键                         | 写入时机              | 含义                         |
| ------------------------- | ----------------- | -------------------------- |
| `setup_wizard_done` = `1` | 点「完成」**或**「我以后再说」 | 以后不再自动弹                    |
| 不写                        | 点窗口右上角 ✕ / Esc 关闭 | **下次启动再弹**（"我还没决定"≠"以后再说"） |

### 4.3 手动入口（以后想重新配）

「工单同步设置」弹窗顶部那一行（现有「企业微信连接」状态行的位置）**加一个 `重新打开配置向导` 按钮** —— 与现有「打开连接引导」并列，两个入口都常驻。

## 5. 与现有弹窗的关系（**合并，不并存**）

| 现有弹窗                   | 本批之后                                                                       |
| ---------------------- | -------------------------------------------------------------------------- |
| 「企业微信连接引导」（首次启动自动弹的那次） | **取消它自己的首次自动弹**（`onboard` 形态一并去掉），改为由向导 S2 承担；**弹窗本身保留**，继续服务于另外两个入口：① 工单设置里的常驻入口；② 同步失败时自动弹 |
| 「工单同步设置」               | **不动**，且被向导 S3 直接复用（向导里点按钮把它打开，配好关掉即可）                                      |
| 「导出报表」                 | 不动（向导 S4 只负责"把链接配好"，导出仍在这里）                                                |

**实现方式（最小重构）**：把「企业微信连接引导」弹窗里的**扫码区**抽成受控子组件 `WecomConnectPanel`（状态徽标 + 二维码 + 授权链接 + 本机使用者 + 重扫），**向导 S2 与设置里的引导弹窗共用它**。理由：直接把整个弹窗嵌进向导会很别扭（弹窗套弹窗），而复制一份扫码逻辑必然两边跑偏（第 10 批「两套清单」的教训）。

**S3 为什么不重造**：连接 / 列子表 / 勾选 / 标类型 / 保存这套逻辑已经在「工单同步设置」里，且被 `tickets` 界面场景与人工验收长期覆盖。向导里再写一份 = 又多一套要对齐的清单。所以 S3 只放一个按钮，把那个弹窗打开（由 `App.tsx` 托管；`TicketsView` 里那个是同一个组件）。

**S4 为什么可以内联**：它只需要「把链接记住」。原来这条链接是搭着「导出」才落库的，所以新开了一个只写配置的口子 `report:saveLink`（解析链接 → 落配置，**不做任何导出**）。

## 7. ⚠️ 视觉样式：本批**不定稿**（用户明确）

用户 2026-10-09 说「欢迎窗口后续我可能会改样式，现在还没想好」。所以本子项：

1. **本批先用与现有弹窗一致的深色风格占位**（`.modal` + 现有色板变量），保证"能用、不难看"，**不追求定稿**；
2. **所有文字走文案字典** `src/shared/copy.ts` → 以后改文字走 `tools/copy-sheet` 流程，不碰代码；
3. **样式收在 `main.css` 里独立的一段**（`.wz-*` 前缀），不散落到通用类上 → 以后换皮只改这一段（或整段替换成新设计）；
4. 后续若有新版欢迎页设计 → **单独立项换皮**，本批不预留"占位图/插画"这类需要定稿才做得对的东西。

> 一句话：本批交的是**流程骨架 + 功能**，外观是"临时穿的工作服"。

## 8. 明确不做

- **不改安装包（NSIS）向导** —— 那是"装到哪里"，本向导是"装好之后配什么"，两回事
- 不强制：任何一步都能跳过，跳过不写任何配置
- 不在向导里做"首次扫描 / 首次同步"（不替用户决定；同步始终手动点）
- 不做"多用户 / 权限"，不做账号体系
- 不做向导的"稍后提醒"（关掉就是下次启动再弹，不做定时提醒）

## 10. 验收口径

**accept（自动断言，只增不减）**

- 触发判定（纯逻辑，注入"库是否本次新建" + "是否已走过向导"）→ 四种组合逐条：  
  新建库+未走过 → 弹；新建库+已走过 → 不弹；老库+未走过 → **不弹**；老库+已走过 → 不弹
- 状态机：点「完成」/「我以后再说」→ 标记写 `1`；点 ✕ → **不写**
- 步骤定义：6 步的名称 / 顺序 / 哪几步可跳过 → 逐条断言（防止以后加删步骤时漏改清单）
- S4 的 `report:saveLink`：链接里解析不出编号 → 明确回 `bad-link`、**不落库**；正常链接 → 落库且 `reportStatus` 读得回
- **不越界**：走完向导**不产生任何**自动扫描 / 自动同步 / 配置写入（除非用户在某步真的点了保存）

**界面场景**

- 布景一个"新建库 + 未走过向导"的工作区 → 启动弹向导；S0/S1 文案正确、S2 有扫码区、`上一步` 在首步禁用
- 点「我以后再说」→ 弹窗关闭 + 标记落库
- 布景"已走过向导"→ 启动**不弹**
- 工单设置弹窗里有 `重新打开配置向导` 入口（点击能打开）

**人工验收（必须做）**

1. 用全新工作区启动一次 → 向导自动弹出 → 走完（含真实扫码一次）→ 工单队列可同步
2. 重开软件 → **不再弹**
3. 设置里点「重新打开配置向导」→ 能再打开
4. 老库（已有素材的任务库）启动 → **不弹**
