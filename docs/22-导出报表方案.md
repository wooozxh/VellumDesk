## 0. 一句话

给工单模块加「导出报表」：① 工单里没有的本地字段（印刷金额 / 绩效金额 / 备注）在软件里按工单填；② 设计师点「完成任务」时自动取任务包**最新版本里的全部成品图**生成缩略图、写回工单队列（第 27 批起支持多张）；③ 导出时选起止日期（按完成时间），把工单字段 + 本地字段 + 缩略图一起写进「工单报表」智能表格，**每次导出新建一个子表**（复制「报表模板」字段结构）。

## 1. 需求源头（用户原话，2026-10-04）

> 加「导出报表」模块。工单模块想再加一些字段（工单里不提供、按月度/季度在软件里填，比如整个印刷费用）；填好后工单模块有「导出报表」，选起止日期导出 Excel，Excel 里包含这些新字段。另外要给员工算绩效，需要参考成品——设计师完成任务时生成一张缩略图传到工单模块、返回给智能表格，导出报表时带着这张图；「绩效」作为金额字段写进报表（值先空着，最后手填）。

## 2. 现状与技术可行性（真表实探，2026-10-04 已钉死）

| 项 | 结论 |
|---|---|
| 现有 Excel 导出 | **无**。只有「任务包导出成 zip」（`exportPack.ts`），报表导出需新做 |
| 缩略图能力 | 已有（`thumbs.ts`，320px，图/视频/PSD/PDF 全覆盖，存 `_thumbs/`） |
| 设计师端「完成任务」动作 | **现无**，需新增（工单的完成时间/送达日期都是企微表同步来的只读字段） |

## 3. 落库结构（迁移 15）

**本地扩展字段**用独立子表（与 `ticket_designers` 同套路），同步引擎零改动：

```sql
CREATE TABLE IF NOT EXISTS ticket_metrics (
  ticket_no        TEXT PRIMARY KEY,   -- 与 tickets.UNIQUE(ticket_no) 对齐
  print_cost       REAL,               -- 印刷金额（本地，不进工单队列）
  performance_cost REAL,               -- 绩效金额（本地，导出时值可空）
  remark           TEXT                -- 备注（本地）
);
```

**缩略图 URL** 挂 `tickets` 表新增一列（同步字段，从工单队列「缩略图」image 列拉取）：

```sql
ALTER TABLE tickets ADD COLUMN thumb_url TEXT;   -- 工单队列 image 列同步来的 URL
```

## 4. 缩略图链路（设计师端 → 跨机器 → 导出）

> 两处「缩略图」列别混淆：**工单队列**（营销物料设计工单队列）需新增一个「缩略图」image 列（**用户手动加**，同「设计师」列套路）；**工单报表**（本方案目标）的「缩略图」image 列已建好。

1. 设计师在任务包详情点「完成任务」→ 找该工单关联任务包（`pack_id`）→ **最新版本里的全部成品素材** → 逐张 `ensureAnyThumb` 生成缩略图（本地 `_thumbs/`）。<br/>（**第 27 批变更**：原为「第一张成品」，一个包交付 2 张也只会写回 1 张 —— issue #2 反馈后改为全部成品都回传。）
2. 上传缩略图：**逐张** `media upload` → `smartsheet images upload`（工单队列文档空间）→ 各拿一个图片 URL。
3. 写回**工单队列**「缩略图」image 列（`updateRecords`，一条记录写多个 `{title,imageUrl}`）。
4. 其他机器同步工单队列时，读「缩略图」image 列**全部** URL → 存 `tickets.thumb_url`（本地按 `joinThumbUrls` 存：1 张 = 纯 URL，多张 = JSON 数组）。
5. 导出报表时，用 `tickets.thumb_url` 解析出**全部** URL → **逐张**下载并重新 `images upload` 到**工单报表**文档空间 → 写入报表「缩略图」image 列。（跨文档 image URL 能否直接复用待实测，见 §8 #4。）

## 5. 导出流程（选起止日期 → 建子表 → 写数据）

1. 工单模块「导出报表」→ 弹窗选**起止日期**（按 `done_time` 完成时间筛）。
2. 查 `tickets WHERE done_time BETWEEN ? AND ?`，JOIN `ticket_metrics` + `ticket_designers`。
3. 在「工单报表」智能表格 `sheets add` 建子表，命名 = 起止日期（默认 `2026-10-01~2026-10-31`），**同时**复制「报表模板」的 12 字段结构（读 `fields list` 拿到 field_title/field_type/property，原样传给 `sheets add` 的 `fields`）。
4. 逐条 `records add` 写记录：单值列直填；成员列写 `[{userName}]`（设计师全量 `[{userName},...]`）；「工单类型」写单选文本「印刷/电子」；缩略图列**逐张 upload 拿 URL 后一起写**（第 27 批起可多张）。
5. 结束 toast：`已导出 N 条到「工单报表」子表「2026-10-01~2026-10-31」`。

## 12. 第 27 批变更（2026-10-05，issue #2）

**起因**：设计师任务的成品图有 2 张，点「完成任务」后工单队列「缩略图」列只有 1 张。
核实后确认这是**原设计的单图语义**（§4 原写「最新版本的第一张成品素材」），非实现漏做 ——
但一个任务包交付多张成品时只回传一张确实不合理，用户拍板改成**全部回传**。

**改法（最新版本的全部成品）**：

| 环节 | 原来 | 现在 |
|---|---|---|
| 找成品 | `role=成品 AND version_id=? ORDER BY id LIMIT 1` | 同条件但**不限条数**（`ORDER BY id`） |
| 引擎返回 | `thumbPath: string` | `thumbPaths: string[]` + `thumbFail`（缩略图生成失败的张数） |
| 上传 | 传 1 张 | **逐张**传，单张失败继续下一张，最后如实汇报缺几张 |
| 写回工单队列 | `[{title, imageUrl}]` 1 个元素 | 同列写**多个元素**（图片列本身支持多图） |
| 本地 `tickets.thumb_url` | 单个 URL | `joinThumbUrls`：0 张 = NULL、1 张 = 纯 URL（**与老数据同格式**）、多张 = JSON 数组 |
| 同步读回 | `takeImageUrl` 取第一张 | `takeImageUrls` 取**全部** |
| 报表导出 | 单 URL rehost 一次 | 解析全部 → **逐张 rehost** → 一次写入图片列 |

**不静默丢弃**：单张上传失败不中断其余，但界面 toast 会明确报「已写回 N 张，另有 M 张未能上传（可稍后重试）」。

**兼容性**：`tickets.thumb_url` 的「1 张 = 纯 URL」格式与老数据完全一致，**不需要数据迁移**；
既有行的单张值由 `parseThumbUrls` 原样读出。
