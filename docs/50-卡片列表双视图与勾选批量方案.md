# 第 67 批：卡片 / 列表双视图 + 列表勾选批量

> 日期：2026-10-17　｜　分支 `feature/pslink-preview`　｜　迁移号：**无**（纯界面 + 文案，没动 DB）
>
> 用户原话：
> 「现在任务视图、通用库、模板，现在它们都是卡片儿的这种视图，我希望能给它们加一个列表视图，可以切换。
> 为什么？因为以后东西会越攒越多，用卡片视图占的空间就太大了。所以我希望能有这两个视图，
> **卡片视图用来看缩略图选东西，列表视图用来整体的浏览一下里面的内容**。
> 然后在这个列表视图下我可以勾选多选，然后进行一些操作……
> 通用库和模板库里也可以有一个叫**清除**的按钮，当然这个清除**不删本地的文件**，就是不读它了，
> 再扫磁盘可以再读回来。」

---

## 1. 一句话结论

卡片与列表**不是二选一，是分工**：

| 视图 | 干什么 | 为什么 |
|---|---|---|
| **卡片** | 看缩略图挑东西 | 素材/模板是**视觉判断**（哪张是对的那张），没有缩略图根本选不了 |
| **列表** | 一屏扫几十条 + 勾选做批量 | 东西攒多了，卡片一屏只放得下十几个；列表能**横向比**（大小/尺寸/时间/分组） |

所以：**卡片视图保持"单卡操作"不变，勾选批量只在列表视图里做。**

## 3. 三处列表的列

列的取舍原则：**卡片上已经看得很清楚的，列表里不重复；卡片上看不全的，列表里必须有。**

| 视图 | 列 |
|---|---|
| **任务**（packs） | 名称（+「已备份」/「N 个丢失」徽标）· 项目（色点 + 名）· 稿数 · 素材数 · 大小 · 修改时间 · 打开 |
| **通用库**（brand） | 名称 · 所在分组 · 尺寸 · 大小 · 来源（公司/个人）· 修改时间 |
| **模板**（tpl） | 名称 · 所在分组（全路径）· 尺寸 · 分辨率 · **参考线**（4 条/无/未知三态）· 大小 · 修改时间 |

两处刻意的设计：

- **任务列表补了「已备份」徽标**：卡片上是"整张置灰 + 徽标"，列表里不能整行置灰（削弱可读性），
  改成名称后挂小徽标。**不补的话切到列表就看不见哪些备份过了** —— 信息平白丢失。
- **模板库「参考线」独占一列**：模板库存在的理由就是"参考线打好了没"。
  卡片上是缩略图角标（挤在角落），列表里一列扫过去能直接看出**哪几份没打线**。

## 4. 交互口径（几条刻意的决定）

### 4.1 点行 = 勾选，不是打开

列表视图的主用途是"勾一堆再批量做"，所以**整行都是勾选热区**，不用瞄准那个 15×15 的小方块。
要打开任务 → **双击行**，或点最右边的「打开」按钮。

> checkbox 设了 `pointer-events:none` ⇒ 点它等同点整行，不会触发两次（一次 `change` 一次行 `click`）。

### 4.2 表头复选框 = 全选**当前列出的**，不是整库

只作用于**当前筛选/搜索出来的行**。这是安全的默认值 ——
"全选"选到看不见的东西，是批量操作最危险的一类误解。

### 4.3 Shift 连选

和资源管理器一致：点第 1 行 → Shift 点第 3 行 ⇒ 1~3 全勾。

### 4.4 ⚠️ 换分组 / 改搜索词 ⇒ **清空勾选**

不清的话：在「易拉宝」里勾 3 条 → 切到「海报」→ 点批量删除 ⇒
**把看不见的那 3 条也删了**。这是本批最需要防的一类错，宁可让用户重勾。

### 4.5 任务视图：列表勾选 = 备份多选（**不另开一套**）

用户勾一堆任务之后，现成能做的事里「批量打包」是那个。所以：

- 列表勾选**直接写 `backupSel`**（和卡片备份模式共用同一个集合）；
- 勾了 → 顶栏立刻出现「批量打包（n）」，**不必先去点「备份打包」进模式**；
- 列表视图**不显示**备份提示条（表头本身就是全选，再来一条是噪音）；
- 切换视图**清空勾选 + 退出备份模式**（两边的勾选语义不同，带着勾选切过去只会让人误解数量）。

## 5. 「清除记录」到底是什么（这条必须说透）

| 动作 | 磁盘文件 | 软件里的记录 | 能不能回来 |
|---|---|---|---|
| **清除记录** | **不动** | 删掉这条登记 | ✅ **重新扫描磁盘就回来** |
| **删除** | 移到回收站 | 删掉这条登记 | ⚠️ 从回收站手动找回 |

批量条上两个按钮的提示文案都写死了这一点（`bulkForgetTip` / `bulkRemoveTip`），
二次确认弹窗也再讲一遍 —— 用户最怕的就是"我点了一下，我的文件没了"。

**实现上刻意逐条调用现成的单条通道**（`brand:forgetAsset` / `brand:removeAsset` / `tpl:*`），
不在主进程新开批量接口：

- 单条通道已经过了 accept 与真机（含回收站、缺文件、重名、路径边界），批量版等于再写一遍边界；
- 条数是"一屏勾选的量"（几十条级），几十次 IPC 的开销可以忽略；
- **逐条 await、不并发**：这些操作会 rename 磁盘文件，并发容易互相踩；
- **中途失败不中断**：已经成功的那些不该因为后面一条失败就白做；
  最后按「成功 N / 失败 M + 第一条错误」汇总。

## 6. 多选还能干什么（**等拍板**）

本批只接了「清除」「删除」「批量打包」。下面这些是**能做但没做**，按我判断的价值排序：

### 通用库 / 模板库

| # | 动作 | 价值 | 代价 | 状态 |
|---|---|---|---|---|
| 1 | **批量移动分组** | ⭐⭐⭐ 收纳主场景 | 中：磁盘 rename + 改 `folder_id/file_name/rel_path/abs_path` | ✅ **已做**（见 §6.1） |
| 2 | **批量复制到任务包** | ⭐⭐ 把库里东西拿去用 | 低-中 | ✅ **已做**（见 §6.2） |
| 3 | **批量重命名（序号化）** | ⭐⭐ 收模板的主力 | 中：两阶段改名防覆盖 | ✅ **已做**（见 §6.3） |
| 4 | **批量改项目 / 分级 / 场景**（任务） | ⭐⭐ 清理「待归类」 | 低（前端循环调现成的 `pack:update`） | ✅ **已做**（见 §6.4） |
| 5 | **批量导出到文件夹** | ⭐ | 低 | ⏳ 未做（有「复制到任务」后价值下降） |
| 6 | 批量打标签 | ⭐ | 中：两库 v1 都没有标签 | ⏳ 等标签体系进库 |

### 6.1 批量移动分组（已做 · 2026-10-17）

**它是"列表视图"存在理由的另一半**：能勾选之后，第一件想干的事通常是"把这几条归到那个组去"，
而不是删。它还有个隐藏好处 —— **让「清除」变安全**：不想要的先挪到「待整理」组，不必冒险清记录。

**新增**：`brandLib.moveBrandAssets` / `tplLib.moveTplAssets`（**同构**）+ `brand:moveAssets` / `tpl:moveAssets`
+ `MoveToFolderModal`（两库共用的分组选择器：多层按层缩进列出来，第一行固定「未分组」）。

五条口径（都写进了代码注释，也都被 accept `[60]` 钉住）：

| 口径 | 为什么 |
|---|---|
| **磁盘先动、登记后改** | `rename` 成功才更新 `folder_id / file_name / rel_path / abs_path`。反过来一旦搬失败，就会出现"登记说在 A 组、文件还在 B 组"的幽灵记录 |
| **同名自动加序号，且 `file_name` 一起改** | 目标组已有同名文件时改成 `x-2.png`；**登记必须同步改名**，否则界面显示的名字和磁盘对不上 |
| **文件已丢失的只改登记** | 不报错、不动磁盘；下次扫描按新位置重新认领 |
| **逐条做、失败不中断** | 一条被 PS 占用（EPERM/EBUSY）不该让剩下 20 条都不动。返回 `{moved, skipped, failed[]}`，界面按"成功 N / 失败 M + 第一条原因"提示 |
| **目标组必须真实存在** | 组被删了 / 脏 id ⇒ 整批拒绝（`no-target`），绝不把文件搬进"磁盘上没有对应组的目录" |

另：**不做整批回滚** —— 主进程已经搬了一部分，硬回滚反而把成功的也退回去。按 `moved / failed` 如实汇报。

跨盘不是问题：库根与所有分组都在同一个库目录下，天然同盘（`rename` 不会 EXDEV）。

### 6.2 批量复制到任务（已做 · 2026-10-17）

把勾中的条目**复制**进某个任务的 `02-素材`，库里那份不动。

**为什么不循环调单条 `copyBrandAssetToPack`**：那条**每调一次就 `scanAll` 全盘扫一遍** ——
勾 20 条就是 20 次全盘扫描，工作区几千文件时会卡到没法用。批量版一次复制完**只扫一次**。

模板库原来**没有**复制到任务的能力，这次一并补上（`copyTplAssetsToPack`）：PSD 复制进任务后
由 `scanAll` 认领成任务库的一条素材（`role` 按子文件夹判定）。

### 6.3 序号化批量改名（已做 · 2026-10-17）

目标名 `<前缀>-<序号><原扩展名>`，序号按**列表顺序**连续排、左补 0 到 `pad` 位。
弹窗里给**实时预览**（改动前就看到 `易拉宝-01.psd` 长什么样）。

🔴 **必须两阶段**：先全部改成临时名，再改成目标名。否则"A 要改成 B、B 要改成 C"时
A 会先覆盖掉 B —— 文件名互换是最经典的覆盖事故。

🔴 **临时名要同步写进数据库**：第一版只改了磁盘没改登记，阶段二把 `素材-03` 改成 `素材-01` 时，
登记里还留着一条旧 `素材-01` ⇒ **`abs_path` 撞 UNIQUE**（accept 实测报
`UNIQUE constraint failed: brand_assets.abs_path`）。已修。

临时名用 `~seq-` 而不是 `.seq-`：`.` 开头的文件会被扫描跳过，中途崩了就成了"隐身文件"。

其它：文件已丢失的**跳过**（不制造"名字对不上"的假记录）；目标名被别人占着 ⇒ 加 `-2`。

### 6.4 任务的批量设置（已做 · 2026-10-17）

一次改勾中任务的 **项目 / 物料类别 / 使用场景 / 物料分级**。

**直接循环调现成的 `pack:update`** —— 它已经把"改项目要搬文件夹 + 更新记录路径 + 失败回滚"
全做完了（`movePackTo`），批量版再写一遍只会多一处出错机会。**主进程零改动**。

⚠️ 只把**真的选了的字段**传下去：没选的留给 `updatePack` 保持原值。
不能图省事传空串 —— 那会把类别/场景清成「未分类」。

### 任务库

| # | 动作 | 价值 | 代价 | 我的意见 |
|---|---|---|---|---|
| 1 | **批量改项目归属** | ⭐⭐⭐ 清理「待归类」 | 中：任务目录要跟着搬（跨项目 = 换父目录） | 很实用，但要和"任务目录结构"绑死，风险不小 |
| 2 | **批量改物料分级 / 场景** | ⭐⭐ | 低（改 `category/channel/grade` 三个字段，不动磁盘） | 便宜，可以顺手做 |
| 3 | 批量导出汇报 | ⭐ | 低 | 单任务导出已够用 |
| 4 | 批量删除任务 | ⭐ | 高（要连带文件、版本、工单关联） | **不建议做**，误删代价太大 |

## 9. 实拍发现的两处问题（已修）

1. **表头用 `--text-3` 太淡** —— 深色底上 11px 的灰几乎看不清列名。改成 `--text-2`。
2. **列间隙 10px 不够** —— 「7.6 KB」和「公司」粘在一起像一格。改成 12px。

另：任务列表原本把「N 个文件丢失」拼进名称（`任务名（3 个文件已丢失）`），
名字一长就整行被截。改成名称后挂 `N 个丢失` 小徽标，名字单独省略。

3. **顺手修掉上一批欠的那个既有问题**：`BrandLibraryView.doScan()` 扫完弹的是「已导入 N 个文件」——
   可打开视图时已经自动扫过一遍，手动再扫常是 0 新增 ⇒ 显示「已导入 0 个文件」，读起来像"点了导入但没反应"。
   **扫描和导入是两件事**，已拆成 `brand.scanDone` / `scanDoneNone`；模板库的扫描原来**完全没有反馈**，一并补上。
