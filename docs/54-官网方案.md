## 0. 结论先说

**技术上可行，成本很低。** 一个 5 页的纯静态站，GitHub Pages 完全够用；不需要后端、数据库、CMS。

但有三件事是**上线前的硬前置**，不是技术问题：

1. **截图脱敏**：现有手册截图带「海南升学 / 精英升学」等真实项目名，公开前必须用中性演示数据重拍。
2. **Toolbox 的更新说明**：用户已提供 0.8.0→0.9.37 的分段 changelog（四个版本段，2026-10-19）；逐版日期与源仓库仍缺，官网先按版本段展示，不编日期。
3. **仓库与域名**：独立仓库还是 `VellumDesk/docs`；要不要自定义域名（决定 URL 与「官方感」）。

## 1. 目标与非目标

### 目标

- 第一次来的人在一屏内明白：**VellumDesk 是什么、Vellum Toolbox 是什么、怎么配合**。
- 可信的下载入口（Desk → GitHub Release；Toolbox → .ccx）。
- 两个产品各自的更新记录，能持续维护，不靠改 HTML。
- 视觉配得上「官方」：安静、精确、有纸感，和产品一致。

### 非目标（首版不做）

- 登录、表单、支付、评论。
- 多语言（先中文；英文留结构）。
- CMS；内容走 Markdown + 构建。
- 在线试用 / Web 版产品。
- 186 MB 安装包不进 Pages 仓库。

## 2. 可行性核对

| 需求 | 结论 | 说明 |
|---|---|---|
| 静态托管 | ✅ | GitHub Pages 免费，支持自定义域名 + 自动 HTTPS |
| 两个产品介绍 | ✅ | 5 页静态内容足够 |
| 更新记录 | ✅ | Markdown → HTML 构建；或首版手写 |
| 下载 Desk | ✅ | 链到 GitHub Releases（现有 v1.11.0-pslink） |
| 下载 Toolbox | ✅ | `.ccx` 约 0.6 MB，可放站点仓库或 Release |
| 搜索 / SEO | ✅ | 静态 HTML + meta + sitemap，无需 SSR |
| 访问统计 | ⚠️ | 无后端；可选 GoatCounter / Umami，或先不装 |
| 自动部署 | ✅ | GitHub Actions（或 Pages 自带 Jekyll 构建） |
| 国内访问 | ⚠️ | Pages 无国内节点，可能慢或间歇失败；先实测，必要时加镜像 / 国内 OSS |
| 维护成本 | ✅ | 发版时加一个 Markdown + 改一处版本号 |

**GitHub Pages 的硬限制**（soft limits，够用但要知道）：

- 站点仓库建议 ≤ 1 GB；月流量 100 GB 软上限；每小时 10 次构建软上限。
- 只能托管静态文件；不能跑 Node 服务端逻辑（构建可以跑在 Actions 里）。
- 公开仓库免费；站点内容 = 公开内容。

- 主张：`让设计资产，各归其位。`（A）/ `设计留下的每一页，都该有归处。`（B）/ `把素材、模板与出稿，收进一个工作台。`（C）

- 两个产品卡：各 4 个能力标签 + 详情入口。
- Desk 能力：任务与版本 / 素材与模板 / 工单与交付 / 本地优先。
- Toolbox 能力：调色板 / 素材库 / 表格生成 / 出图体检 / 导出审核版 / 新建稿。
- 最新更新 3 条 + 全部更新入口。
- 下载：Desk 1.11.0（Windows，约 186 MB）+ Toolbox 0.9.37（PS 25.0+，.ccx）。

### 产品页

- 一段「它解决什么」的白话；6 个能力（每个一句话 + 一张局部截图）。
- 系统要求 / 安装步骤 / 已知限制（Toolbox 未签名、PS 版本门槛）。
- 下载与版本号；链到更新记录。

### 更新页

- 默认 Desk；Tab 切 Toolbox；每条：版本、日期、一句话摘要、3~6 个要点、可选截图。
- 只写**已发生**的事；Toolbox 历史没拿到前，不编日期。

### 下载页

- 文件名、版本、大小、发布日期、SHA256（有就写，没有就写「随 Release 提供」）。
- 安装说明：Desk 双击 Setup；Toolbox 双击 .ccx，PS 里 `窗口 > 插件 > Vellum 工具箱`。
- 未签名提示：SmartScreen「更多信息 → 仍要运行」；.ccx 安装按 PS 实际提示写。

事实来源：`website/product-facts.md`（每条带本机文件出处）；上线前再核一次版本号。

## 5. 技术方案

### 5.1 形态

**纯静态 HTML/CSS/JS，不引入 React / Next / Astro。** 理由：

- 只有 5 页，内容稳定；框架带来的构建复杂度大于收益。
- GitHub Pages 直接托管，无服务端；出问题好排查。
- 参考站是 Next.js，但我们要的是它的**视觉**，不是运行时。

### 5.2 目录（独立仓库 vellum-site）

~~~text
vellum-site/
├─ index.html
├─ desk/index.html
├─ toolbox/index.html
├─ updates/index.html
├─ download/index.html
├─ 404.html
├─ assets/
│  ├─ site.css
│  ├─ site.js
│  ├─ fonts/            # 可选：自托管拉丁 WOFF2
│  └─ img/              # WebP/PNG + 2x
├─ content/
│  ├─ products.json     # 版本号、下载链接、系统要求（唯一事实源）
│  └─ updates/
│     ├─ desk/2026-10-17-v1.11.0.md
│     └─ toolbox/...
├─ tools/build.mjs      # Markdown → updates/index.html + 首页最新 3 条
├─ .github/workflows/pages.yml
├─ .nojekyll
├─ CNAME                # 仅自定义域名时
├─ sitemap.xml
└─ robots.txt
~~~

### 5.3 构建

- 首版可以**手写 HTML**，只在发版时改；但更新页会很快变成手工活。
- 推荐从第一天就用 30 行的 `build.mjs`：读 `content/updates/**/*.md`（front-matter: version/date/product/summary），生成更新页与首页最新 3 条。
- `products.json` 管版本号、下载 URL、文件大小；页面版本号从它渲染，避免「页面写 1.11.0、下载还是 1.10.0」。
- 构建只依赖 Node 内置 + `marked`（或自己写 20 行 Markdown 解析）；不引框架。

### 5.4 样式与动效

- 设计令牌（色 / 字 / 间距 / 圆角）集中在 `site.css` 的 `:root`；三方向选定后只保留一套。
- 中文：`Noto Sans SC`（正文）/ `Noto Serif SC`（编辑方向标题）；本机已装，网页端用系统回退，必要时自托管子集。
- 动效：CSS transition + IntersectionObserver 入场；`prefers-reduced-motion` 直接关。
- 不引外部 CDN（Google Fonts / jsDelivr 在国内不稳）。

### 5.5 性能与可访问性

- 图片：WebP + PNG 回退，`width/height` 固定，`loading="lazy"`；首屏图 preload。
- 目标：首页 HTML+CSS+首屏图 < 500 KB；Lighthouse Performance ≥ 90。
- 语义标签、可见 focus、正文对比度 ≥ 4.5:1、键盘可达。
- SEO：每页 title/description/OG；`SoftwareApplication` JSON-LD；sitemap；`robots.txt`。

## 6. 部署

### 6.1 仓库选择

| 方案 | URL | 优点 | 缺点 |
|---|---|---|---|
| A. 现有仓库 `VellumDesk/docs` | https://wooozxh.github.io/VellumDesk/ | 一个仓库 | 应用提交会触发站点构建；应用与官网耦合 |
| B. 独立仓库 `vellum-site` | https://wooozxh.github.io/vellum-site/ | 干净、权限独立、构建只跟站点 | 多一个仓库 |
| C. 用户站 `wooozxh.github.io` | https://wooozxh.github.io/ | 根路径、最像官网 | 一个账号只能一个；会占掉根域名 |

**建议 B**，后续加自定义域名（如 `vellumdesk.cn` / `vellum.design`，需先查注册与商标）。自定义域名只需在仓库根放 `CNAME`，DNS 加 CNAME/A 记录，Pages 自动签 HTTPS。

### 6.2 GitHub Actions

~~~yaml
name: pages
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: node tools/build.mjs
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with: { path: . }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment: github-pages
    steps:
      - uses: actions/deploy-pages@v4
~~~

> 首版纯手写、无构建时，可不用 Actions：Settings → Pages → Deploy from branch → `main` / root。加 `.nojekyll` 跳过 Jekyll。

### 6.3 发布流程

1. 发版：拿到新版本号与安装包。
2. 在 `content/updates/<product>/` 加一个 md（版本、日期、摘要、要点）。
3. 改 `content/products.json` 的版本 / 下载链接 / 大小。
4. `node tools/build.mjs` 本地预览。
5. commit + push → Actions 部署。
6. 线上核对：版本号、下载 200、移动端、404。

## 10. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| GitHub Pages 国内访问慢 / 间歇 | 同事打不开 | 先实测；准备国内 OSS/COS 镜像；页面 < 500 KB |
| 截图泄露真实客户名 | 合规 / 商务风险 | 上线前统一重拍；加 review 关卡 |
| Toolbox 只有分段 changelog、没有逐版日期 | 更新页无法写发布日期 | 先按 v0.9.11–37 / v0.9.6–10 / v0.9.0–5 / v0.8.0 四个版本段展示；日期留空，等插件侧补 |
| 版本号漂移 | 页面写 1.11.0、下载是旧包 | `products.json` 单一事实源 + 构建时校验 |
| 安装包未签名 | 用户不敢装 | 下载页写清 SmartScreen / PS 提示；后续考虑签名 |
| 「Vellum」商标冲突 | 公开使用风险 | 上线前检索 / 咨询；站内用「Vellum 工作台」中文名降低混淆 |
| GitHub 账号安全 | 站点被改 | 2FA、独立仓库、Actions 最小权限、不在仓库放 token |
