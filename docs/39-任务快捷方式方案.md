# 第 54 批（子项 1）：任务「创建桌面快捷方式」方案（docs/39）

> 本批 = 第 54 批，版本 **1.9.5**，含两个子项：本文件（子项 1）+ `docs/40-首次配置引导方案.md`（子项 2）。  
> 两件事**不改数据库结构**（无新增迁移），方案分别过审后一起施工、一起出包。

---

## 1. 需求（用户原话）

> 在任务详情界面中添加按钮「快捷方式」，点击后在桌面创建该任务文件夹快捷方式。

## 2. 要解决的问题

「任务」在磁盘上就是一个文件夹。设计师一天要反复进这个文件夹放文件、取文件。现在的路径是：

**开软件 → 任务视图 → 点任务卡片 → 进详情 → 点「打开文件夹」**（5 步，且每次都得先开软件）。

桌面快捷方式 = 一次点，以后**从桌面双击直接进任务文件夹**，不开软件也能干活。这是「任务文件夹」到「日常文件操作」之间最省事的一座桥。

**它同时天然满足三条产品铁律**：用户主动点才建（不替用户做决定）、不删不改任何素材（不静默丢弃）、快捷方式在工作区之外（不干扰扫描，软件视图不受影响）。

## 3. 界面

| 项   | 设计                                                                  |
| --- | ------------------------------------------------------------------- |
| 位置  | 任务详情弹窗**顶部按钮组**，「打开文件夹」**之后**、 「打包交付」之前                             |
| 文案  | `快捷方式`（走文案字典，用户可改）                                              |
| 图标  | 新增线性图标（显示器 + 屏内小外跳箭头），与现有图标同规格（24 网格、1.6px 描边）                 |
| 点击后 | ① 正常 → 轻提示「快捷方式已建好：桌面 + 开始菜单（<任务名>）」；② 目标位置已有同名 → 弹确认（覆盖 / 取消）；③ 失败 → 说明原因的提示 |
| 不做  | 不加右键菜单、不在任务卡片上加入口、不做「固定到开始菜单磁贴 / 任务栏」（见 §9）                                 |

## 4. 技术实现（**含本机探针实测结论**）

### 4.1 选型：Electron 自带的 `shell.writeShortcutLink`

零新依赖、Windows 原生（写 `.lnk`）。**不引入任何第三方快捷方式库。**

### 4.2 一次性探针实测（2026-10-09，Electron 39.8.10，Windows）

探针只在**系统临时目录**里建/删，跑完即清；结论有三条**与直觉相反**，必须写进代码：

| 验的事                           | 结果                                                                         | 对方案的影响                                        |
| ----------------------------- | -------------------------------------------------------------------------- | --------------------------------------------- |
| `target` 指向**文件夹**            | ✅ **可行**。`.lnk` 建成（1113 字节），`readShortcutLink` 回读的 `target` **精确等于**该文件夹路径 | 主路径成立，不必退回 PowerShell 方案                      |
| 桌面**已有同名** `.lnk` 时再 `create` | ⚠️ **不报错、直接覆盖**（返回 true）                                                   | 「重名」只能由**软件自己判**是否存在来决定要不要弹确认 —— 不能指望 API 抛异常 |
| `target` **不存在**时             | ⚠️ **照样建成功**（生成一个指向不存在位置的死链）                                               | 建之前**必须自己检查**任务文件夹还在不在，否则会给用户造一个点不开的快捷方式      |
| 带 `icon` 参数                   | ⚠️ 能建，但**回读的图标值不是写入值**（存疑）                                                 | 默认**不指定图标**（用 Windows 文件夹默认图标，最符合「这是文件夹」的直觉）  |

> 探针是一次性脚本（项目外、临时目录、跑完即删），不入库。

### 4.3 落点与命名

- 落点（用户拍板 D4）：**桌面 + 开始菜单**，两处各建一个
  - 桌面 = `app.getPath('desktop')`
  - 开始菜单 = `%APPDATA%\Microsoft\Windows\Start Menu\Programs\`（`.lnk` 放这里就出现在"所有程序"里）；
    该目录正常都存在，万一没有就先建一个，**建不出来只影响这一处**，桌面那一路照写
- 文件名：`<任务名>.lnk`，任务名先过净化（非法字符 `<>:"/\|?*` → `_`，并去掉结尾的点和空格）
- 超长名：截断到安全长度（保留可辨识前缀），避免超 Windows 路径上限
- 快捷方式里 `cwd` 留空（文件夹快捷方式不需要工作目录）
- **个别落点失败不连坐**：另一处照写，返回结果里如实列出哪几处没写成

### 4.4 代码落点（纯逻辑与副作用分离，沿用既有惯例）

| 位置                                                | 内容                                                                                                                                                                                                    |

| `src/main/ipc.ts`                                 | 新增 IPC `pack:createShortcut(packId, overwrite?)`：校验任务文件夹在不在 → 探测两处是否已有同名 → 组装 plan → 注入真 writer（`shell.writeShortcutLink`）→ 返回结果                                     |

## 5. 边界与异常

| 情况                  | 行为                                               |
| ------------------- | ------------------------------------------------ |
| 任务文件夹已不在磁盘          | 提示「任务文件夹不在了，请先点「刷新/扫描」」——**不建死链**（探针第 3 条的直接后果）  |
| 桌面**或**开始菜单已有同名 `.lnk` | 弹确认「已有同名快捷方式，是否覆盖？」→ 确认则两处都覆盖（`replace`），取消则**什么都不做** |
| 某一处写失败（如精简系统没有开始菜单目录） | **不连坐**：另一处照写；结果里如实说明"有的位置没写成"                    |
| 桌面/开始菜单路径取不到       | 提示具体原因（不静默）                                      |
| 非 Windows           | 本项目只出 Windows 包；接口层直接回「当前平台不支持」                  |
| 名字含非法字符 / 超长        | 净化 + 截断（与建任务同一套规则，用户已熟悉）                        |
| 任务名里带 `.` 结尾 / 空格结尾 | 一并走同一套净化规则                                        |

## 7. 验收口径

**accept（自动断言，只增不减）**

- `sanitizeShortcutName` / `shortcutPathFor`：非法字符、结尾的点与空格、超长截断、正常名 → 逐条
- `buildShortcutPlan`：
  - 任务文件夹**在** + 两处都**无**同名 → `needsConfirm=false`，`places` 两处带出 lnkPath
  - 任务文件夹**在** + **任一处**有同名 → `needsConfirm=true`
  - 任务文件夹**不在** → 返回「不可建」状态（**不产出 plan**）
- `runShortcut`（**注入 mock writer**）：
  - 未确认覆盖 → **一次 writer 都不调**（`wrote=false`）
  - 确认覆盖 → 对已有同名的那个位置用 `replace`、其余用 `create`，两处都被调到，`target` 正确
  - **一处失败不连坐**：writer 对 startMenu 抛错时，桌面那份仍写成、`failed` 里如实含 startMenu
- ⚠️ **真写 `.lnk` 不进自动测试**：`accept.cjs` 跑在纯 node 下，`require('electron')` 拿到的是路径字符串、没有 `shell` API —— 与项目既有做法一致（网络/Electron 副作用走注入，真链路靠人工验收）

**界面场景**

- 任务详情弹窗里出现「创建桌面快捷方式」按钮、文案正确（**不真点**，见 D8）

**人工验收（必须做，一次就够）**

1. 打开一个任务 → 点「快捷方式」→ **桌面**和**开始菜单**都出现 `.lnk` → 双击能直接打开该任务文件夹
2. 再点一次 → 弹「是否覆盖」→ 选覆盖，正常；点取消 → 两处都不动
3. 去资源管理器把任务文件夹改名 → 回软件点「刷新扫描」→ 再点按钮 → 提示「任务文件夹不在了」（不建死链）

## 8. 关联

- 「打开文件夹」：同一个目标路径，本子项是它的"常驻版"
- 第 7 批（`docs/09`）任务生命周期：改名 = 文件夹改名 → **旧快捷方式会失效**（指向老路径）。本批**不自动跟随**（不猜、不替用户清理桌面），只在文档与提示里说清；后续若要"自动更新快捷方式"单独立项
- 与子项 2（首次配置引导）**互不影响**，可分别施工、分别验收

---

## 9. 明确不做

- 不做「固定到开始菜单磁贴 / 任务栏固定」—— 那两个没有公开 API（本批做的是**在开始菜单「所有程序」里放一个快捷方式**，Windows 的标准做法，可逆）
- 不做「自动跟随改名」（要遍历桌面 + 改用户盘上的文件，越界）
- 不做"批量给多个任务建快捷方式"（桌面和开始菜单都会花）
- 不删任何已存在的快捷方式（包括本功能自己建的旧链接）
- 不给快捷方式指定图标（探针显示图标字段回读存疑；用文件夹默认图标最不容易出错）
