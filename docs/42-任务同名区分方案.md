# 第 56 批：任务同名区分（卡片挂工单标识）

> 用户提出（2026-10-09）：**任务重名时，界面上分不清哪个入口是哪个任务。**
> 建议在任务卡片上显示「审批编号」——那是唯一值字段。
> 用户拍板：**按推荐方案 D 做，先只做显示层，做完先不出包。**

---

## 一、现象与根因

### 现象

任务列表里出现两张**名字一模一样**的卡片，点进去才知道哪个是哪个。

### 根因（已定位，`src/main/tickets.ts`）

从工单自动建任务时，**任务名直接取工单的「物料名称」字段**：

- 单设计师：`任务名 = 物料名称`
- 多设计师（第 18 批）：`任务名 = 物料名称-本机姓名`

两张工单只要「物料名称」填得一样，就长出两个**同名任务**。

### 关键细节：磁盘上其实分得清，界面分不清

`createPack` 遇到重名文件夹会**自动加后缀**（`物料名称-2`、`物料名称-3`），
所以磁盘上从来不撞。但：

- 数据库 `packs.name` 存的是**原名**（不带后缀）
- 卡片显示的也是 `packs.name`

→ 结果：**"磁盘分得清、界面分不清"**，不是数据坏了。

> 现在唯一的补救是鼠标停在卡片上冒出的完整文件夹路径（含 `-2`），
> 要一个个停、路径又长，等于没有。

## 二、方案（用户拍板：方案 D —— 显示层）

**不动命名口径、不动磁盘、不动表结构。只把「这张任务是从哪张工单来的」显示出来。**

### 选定的手段

| 项 | 决定 |
|---|---|
| 挂什么 | **工单编号（唯一键）+ 申请人** |
| 挂在哪 | 卡片**名称正下方，常显**一行 |
| 手工建的任务 | **不显示这一行**（没有工单，界面保持干净） |
| 范围 | **任务卡片 + 任务详情弹窗**（两处一致） |
| 命名层改造（方案 C） | **本批不做** —— 先做显示层，风险最小 |

### 界面形态

**任务卡片**（`PackCard`）：

```
┌───────────────────┐
│                   │
│      [缩略图]      │
│                   │
├───────────────────┤
│ 海南招生海报        │  ← 名称（原有）
│ 工单 202609041237 陈晓 │  ← 新增：编号（等宽小字、弱色）+ 申请人
│ 12 个文件 · 36.2 MB │  ← 原有
│ [项目] [类别]       │  ← 原有
└───────────────────┘
```

- 编号用**等宽 + tabular-nums** 小字（对数字友好、好比对）
- 申请人跟在编号后面（略深一点的色，是一个"人话"锚点）
- 整行过长时省略号截断；**鼠标悬停给出完整信息**：
  `工单编号 / 物料名称 / 申请人 / 交期 / 审批状态`（缺的项不出现）

**任务详情弹窗**（`PackDetailModal`）标题右侧带同样的「工单 编号 · 申请人」，
点进去和卡片对得上。

## 三、数据从哪来（零迁移）

`tickets` 表在**建任务时**就把 `pack_id` 写了进去（第 13 批，迁移 10），
任务被删时外键 `ON DELETE SET NULL` 自动清空。

所以在 `listPacks` / `getPackDetail` 里**顺带查一次**即可：

```sql
SELECT pack_id, ticket_no, applicant_name, due_date, title, approval_state
  FROM tickets
 WHERE pack_id IS NOT NULL
 ORDER BY pack_id, id
```

- **一次查询**建 `pack_id → 工单展示信息` 的 Map，不在包循环里逐条查（避免 N+1）
- 一张任务理论上可能挂多张单（历史手工干预）：**取 id 最小的一张做代表**，
  另带 `ticketCount` 总张数（>1 时界面可提示）
- 手工建的任务 → 查不到 → 字段全 `null` / `0` → 界面不显示标识行

**不改表、不加迁移**（迁移号仍是 21）。

## 五、验收口径

新增断言（喂假数据，不碰真企微 / 真表）：

1. **有工单**：applySync 建出的任务，`listPacks()` 里该包的 `ticketNo` = 工单编号、
   `ticketApplicant` = 申请人、`ticketCount` = 1
2. **无工单**：手工 `mkPack` 建的任务，`ticketNo === null && ticketCount === 0`（界面据此不显示）
3. **详情一致**：`getPackDetail(id)` 的 `pack.ticketNo` 与 `listPacks` 里那条相等
4. **删任务清关联**：任务被删后，工单记录仍在但 `pack_id = NULL`（原有第 13 批断言已覆盖，
   本批确认**查询不会因此崩**）
5. **一任务多单**：手工插第二张同 `pack_id` 的工单 → 代表取 id 小的那张，`ticketCount = 2`
