# 32 · 打包交付：尺寸作用范围修正 + 命名模板 {项目名} 修正 + UI 重排 + 文件结构预览

> 日期：2026-10-07　性质：bug 修复 + 界面重排 + 小幅功能　分支：`main`
> 起因：用户实测「尺寸输入进不了压缩包文件名」，并反馈打包交付界面逻辑混乱，给出 6 点重排清单。
> 前置：`docs/18-M5交付打包方案.md`（打包交付一期）

---

## 一、诊断结论（三个真问题）

### 1.1 尺寸改后 zip 名不更新（确认 bug）

`PackExportModal.tsx` 的 zip 名自动生成 effect 用了 `if (zipName) return` 兜底
（本意「用户手改过就不再自动覆盖」），副作用是：首次自动生成后 zipName 已非空，
之后改「尺寸」永远 return，「未知尺寸」纹丝不动。

**修法**：加 `zipNameTouched` 标记（只有手动编辑 zip 名输入框时置 true），
effect 条件改为 `if (zipNameTouched) return`。两条语义互不干扰。

### 1.2 尺寸对所有分组都生效（需求要改）

后端 `buildDefaultInnerName` 与 `applyCustomTemplate` 对成品/素材/工程一视同仁都拼 `size`。
**改成**：只有「成品」「工程」两个分组带尺寸；「素材」「未归属」不带。

### 1.3 `{项目名}` 占位符名不副实（额外发现）

`applyCustomTemplate` 里 `{项目名}` 与 `{任务名}` 都替换成 `packName`（= 任务名），
整条链路（`InnerNameOptions`）没把 projectName 传进去。
**改成**：`{项目名}` → 真项目名，`{任务名}` → 任务名，两者并存、各自正确。

---

## 二、后端改动（exportPack.ts）

1. `InnerNameOptions` 加 `projectName: string | null`。
2. `buildInnerPaths` 对每个 entry 算 `sizeForFile = (role === '成品' || role === '工程') ? sizeText : ''`，
   传给 `buildDefaultInnerName` / `applyCustomTemplate`。
3. `buildDefaultInnerName`：`parts = [packName, size].filter(Boolean)`（素材 size 为空自动去段）。
4. `applyCustomTemplate`：加 `projectName` 变量，`{项目名}`→projectName、`{任务名}`→packName；
   全部替换后清理连字符 `-{2,}→-` 与首尾 `-`（素材 `{尺寸}` 为空时不留 `--`）。
5. 新增 `previewPackExport(input)`：复用 `buildPackExportPlan`（不碰磁盘），返回
   `{ zipName（含 .zip）, innerPaths[], fileCount, totalSize }`。

## 四、界面重排（PackExportModal）

新顺序：

1. 版本 / 打包范围 / 文件明细 —— 不动
2. **尺寸**（短控件 ~160px，提示改为「仅用于成品与工程文件」）
3. **自定义文件名模板**（逻辑保留，占位符提示保留）
4. **压缩包名称**（改尺寸后「未知尺寸」实时更新）+ 下面收一行两个 checkbox：
   「保留原文件名」「包内加一层同名文件夹」
5. **输出位置**（路径 + 选择文件夹）
6. **文件结构预览**（新增）：复用 `packExportPreview`，随改动防抖 ~300ms 刷新，
   渲染成字符树（`├─`/`└─`/`│`），展示包内目录与最终文件名
7. **按钮**：开始打包在左、取消在右、高度调小

字符树示意（wrapFolder 开）：

```
海南升学规划中心-招生海报-1920x1080-20261007-V1.zip
└─ 海南升学规划中心-招生海报-1920x1080-20261007-V1/
   ├─ 成品/
   │  └─ 招生海报-1920x1080-V1-主视觉-20261007.png
   ├─ 素材/
   │  └─ 招生海报-V1-配图-20261007.jpg      ← 素材不带尺寸
   └─ 工程/
      └─ 招生海报-1920x1080-V1-源文件-20261007.psd
```
