## 3. 开工探针实测结论（2026-09-25，证据在案）

出包前先跑了一次探针（`npx electron-builder --dir`），**两个预判的坑全部实测命中**：

| 坑 | 实测证据（原始日志） | 处理 |
|---|---|---|
| **双配置打架** | `• loaded configuration  file=package.json ("build" field)` —— 出包的确实只有 package.json 的配置，`electron-builder.yml` 被完全忽略。已核 `app-builder-lib/out/util/config/load.js` 的 `loadConfig()`：**只要 package.json 存在 `build` 字段就直接采用，不合并 yml** | 配置只留 `package.json` 一处，**删除 `electron-builder.yml`** |
| **原生模块被迫重编译** | `• executing @electron/rebuild electronVersion=39.8.10` → `• preparing moduleName=better-sqlite3 arch=x64` → `⨯ Error: Could not find any Visual Studio installation to use`（node-gyp 找不到 VS，出包中断） | 配置显式 **`npmRebuild: false`** —— 延续 DECISIONS「better-sqlite3 v13 用 N-API 预编译二进制，不做 electron-rebuild」的已验证结论 |
| **出包二进制需下载** | `%LOCALAPPDATA%\electron-builder\Cache` 初始**不存在**（NSIS / winCodeSign 要从 GitHub 拉）；electron 本体 `electron-v39.8.10-win32-x64.zip`（130 MB）**已有缓存**无需下载 | 出包前设 `ELECTRON_BUILDER_BINARIES_MIRROR` 国内镜像（见第 4.3 节） |

### 3.1 探针顺带修掉的一个环境故障（与配置无关）

探针第一次运行 19 秒即失败：

```
Error: Cannot find module 'D:\proj_media\node_modules\agent-base\dist\index.js'
```

**根因**：`agent-base` 与 `https-proxy-agent` 的 `dist/index.js` 被改名为 `index.js.DELETE.<hash>`。这是 **npm 在 Windows 上删不掉被占用文件时的「延迟删除」标记**，标记后未被清理，文件就等于消失了。

**处理**：核对 `package-lock.json` 版本一致（`agent-base@7.1.4` / `https-proxy-agent@7.0.6`，与 node_modules 实际安装版本相同），确认属误标，恢复文件名并用 `require()` 验证两个包均可正常加载。

**教训（写入本文件备查）**：`node_modules` 里出现 `.DELETE.` 后缀文件 = npm 延迟删除残留，症状是"模块找不到"，**恢复文件名即可，不必重装依赖**。

## 4. 最终配置形态（唯一权威 = `package.json` 的 `build` 段）

### 4.1 关键字段与理由

| 字段 | 值 | 为什么 |
|---|---|---|
| `appId` | `com.mediabutler` | 与主进程 `electronApp.setAppUserModelId('com.mediabutler')` 保持一致（否则任务栏图标/通知归组会错） |
| `productName` | `素材管家` | 开始菜单、卸载列表、窗口显示名 |
| `directories.output` | `release` | 出包产物与 `out/`（编译产物）分开，避免混在一起 |
| `files` | 排除式（见 4.2） | 沿用 electron-vite 官方模板风格，逐项排除不该进包的东西 |
| `extraResources` | `resources/ffmpeg` → `ffmpeg` | FFmpeg 放在 asar 外（可执行文件不能在 asar 内运行），落到 `<安装目录>/resources/ffmpeg` |
| `asarUnpack` | canvas / pdfjs / 原生 `*.node` | 原生二进制与 wasm 不能在 asar 内加载 |
| **`npmRebuild`** | **`false`** | **本批核心修正**：三个原生模块（better-sqlite3 / sharp / @napi-rs/canvas）全是 N-API 预编译，本来就不需要重编译；开着只会去调 node-gyp 然后因缺 VS 工具链而失败 |
| `win.executableName` | `MediaButler` | 主程序 exe 用 ASCII 名更稳（中文 exe 名在部分环境有兼容问题），而快捷方式/显示名仍是「素材管家」 |
| `win.artifactName` | `素材管家-${version}-安装包.${ext}` | 交付给同事的文件名一看就懂 |
| `nsis.oneClick` | `true` | 一键安装，同事零决策（双击 → 装好） |
| `nsis.perMachine` | `false` | **兑现拍板点 2**：装到当前用户目录，免管理员权限 |
| `nsis.createDesktopShortcut` | `always` | 桌面有图标，汇报时好指 |
| `nsis.shortcutName` / `uninstallDisplayName` | `素材管家` | 中文显示名 |
| `nsis.deleteAppDataOnUninstall` | `false` | 卸载不删用户数据（配合第 6 节铁则） |
| `nsis.differentialPackage` | **`false`** | **实测修正**：默认 `true` 会为"自动更新的差分升级"生成一个**不压缩、块对齐**的 `.nsis.7z` 塞进安装器，实测把安装包从约 350 MB 顶到 **847.9 MB**。本项目不做自动更新，这 500 MB 纯属白背，故关闭 |

### 4.2 打包排除清单（防安装包虚胖）

| 排除项 | 理由 |
|---|---|
| `!resources/ffmpeg/**` | **最关键**：FFmpeg 由 `extraResources` 单独提供一份；若不排除，`files` 的默认 `**/*` 会把它再打进 asar，安装包白白胖 267 MB |
| `!_dl/**` | FFmpeg 下载缓存（172 MB 的 zip），纯开发产物 |
| `!_shotapp/**` | 界面验证壳，内含 Electron 用户数据 |
| `!素材工作区/**` | 开发期遗留的工作区目录（含测试数据库） |
| `!docs/**`、`!*.md` | 需求文档与方案文档 |
| `!src/**`、`!tsconfig*.json`、`!electron.vite.config.*` | 源码与配置，运行时只需要 `out/` |
| `!accept.*`、`!shot-*` | 验收脚本与截图产物 |
| `!build/**` | 图标源文件（electron-builder 自己会读，不需要进 asar） |
| `!.vscode/**`、`!.eslintcache`、`!eslint.config.mjs`、`!.prettier*`、`!.editorconfig`、`!*.tsbuildinfo` | 开发工具配置 |

### 4.3 出包命令（含镜像）

```bash
cd D:\proj_media
set ELECTRON_BUILDER_BINARIES_MIRROR=https://npmmirror.com/mirrors/electron-builder-binaries/
npm run build:win
```

`ELECTRON_BUILDER_BINARIES_MIRROR` 不设的话，NSIS / winCodeSign 会从 GitHub 拉，国内大概率卡死或超时。这条连同"怎么出新安装包"一并写进 `README.md`。

## 6. 工作区兜底规则（本批唯一的业务逻辑改动）

延续铁则「**软件永远不悄悄扔掉用户放的东西**」——所以**绝不悄悄改用户已经配置好的库路径**。

| 场景 | 行为 |
|---|---|
| **首次启动、无配置** | 自动择址：先试 `D:\素材工作区`，能建目录就用它；建不了（没 D 盘 / 无写权限）改用「文档\素材工作区」。把最终选中的路径写进配置文件 |
| **已有配置、路径不可用** | **不动配置**。界面顶部显示醒目提示条，写明具体路径与可能原因（盘未挂载 / 移动硬盘未连接 / 无权限），并提供「更改位置」按钮 |
| **已有配置、路径可用** | 正常，无提示 |

> 为什么要区分这两种情况：如果同事的移动硬盘没插上，而我们"自动改到文档目录"，他就会看到一个**空库**，以为素材全丢了 —— 这比报错严重得多。所以**只在首次启动（还没有任何配置）时才自动择址**。

### 6.1 关于「更改位置」入口（用户未单独要求，我判断必须做）

只给提示不给出口 = 同事看到"工作区不可用"却无解。而后端 `ws:setRoot` IPC **第 1 批就已存在**，缺的只是一个选目录的按钮。故本批补上最小闭环：提示条上的「更改位置」→ 系统选目录对话框 → 调用已有 `ws:setRoot`。

> 若用户认为超出本批范围，可单独砍掉这个按钮（只留提示条），不影响其余部分。

需求文档对应：**第 365 条「库迁移：换电脑或换盘后，批量修改库的根目录路径，无需重新登记」**。本批只做"单个库根目录可改"这个最小入口；"批量修改多条库路径"属于库迁移模块，后续单独排期。

## 7. 界面改动（仅两处）

1. **状态栏版本号**：来源 `app.getVersion()`（即 `package.json` 的 `version` 字段）。改 `package.json` 的 version 就等于改安装包版本号，单一出处。
2. **工作区不可用提示条**（仅在工作区不可用时出现）：顶部一条醒目提示，含具体路径、可能原因、「更改位置」按钮。

## 9. 验收清单（8 个检查点）

1. 双击 `素材管家-1.0.0-安装包.exe` 能装完，**全程不弹管理员权限请求**
2. 开始菜单 / 桌面出现「素材管家」图标，双击能启动，窗口标题与图标正常
3. 新建项目 → 新建包 → `D:\素材工作区` 下真的长出包文件夹与 `01-成品/02-素材/03-工程`
4. 丢一个视频进包 → 刷新扫描 → 视频行显示时长与编码，且有**真抽帧缩略图**（证明 FFmpeg 已随包分发）
5. 丢一张图片 → 信息行显示尺寸与色彩模式（证明 sharp 在打包环境可用）
6. 包内放 PDF 与 PSD → 缩略图正常（证明 pdfjs / canvas 的 `asarUnpack` 生效）
7. 双击素材能调起系统默认程序打开；「打开所在文件夹」可用
8. 从控制面板卸载后：安装目录清空，**`D:\素材工作区` 一个字都不少**（铁则：卸载不动用户素材）

## 10. 已知代价与限制（用户已知情）

1. **安装包体积约 400 MB**（Electron 130 MB + FFmpeg 267 MB + 依赖）—— 用体积换"同事零配置开箱即用"
2. **未做代码签名**：安装时 Windows 会弹「已保护你的电脑 / 未知发布者」，需点「更多信息 → 仍要运行」。要消除需买代码签名证书（约 1000–3000 元/年），**本批不买**
3. **图标仍是脚手架默认的 Electron 图标**（用户确认先用默认）—— ⚠️ **正式对外分发前必须替换**
4. **无自动更新**：更新软件 = 重新发新安装包让同事装一遍
5. **最后一关 AI 验不了**：AI 只能在开发机上验证"能生成、能装、装上能用"；"在一台从没装过开发环境的电脑上能否运行"必须由用户在一台同事电脑或虚拟机上确认
