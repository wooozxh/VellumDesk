# 第 69 批：模板缩略图改成「信息卡」（HTML 渲染 + PSD 关键词）

> 日期：2026-10-17　｜　迁移号：**24**（`tpl_assets` 加 `keywords`）
>
> 用户原话：
> 「模板库那边整个功能都没问题，但缩略图有点太模糊了……我想给每个模板做一个清楚一些的缩略图。
> 你先给我一个缩略图比较合适的大小，然后我做一个样式的模板，你再帮我在软件上改需求：
> 每次导入模板或者扫描磁盘之后，把新导入的都生成缩略图，按我给的样式生成。」

---

## 1. 为什么原来糊（根因）

模板缩略图不是渲染 PSD，而是**读 PSD 文件里自带的预览图**（图像资源 1036，代码注释写明「典型 160px 级」），
再塞进 320px 的容器、`withoutEnlargement` 不放大 ⇒ **实际显示的就是一张 160px 的小图**。
卡片显示区 150-200px，Windows 150% 缩放时要 250px 物理像素 ⇒ 必然糊。

**这是硬上限**：软件不解析 PSD 合成图（那需要 Photoshop）。

## 2. 决策：不生成图片，改用 HTML 渲染

用户给的样式（`PSD_template_thumbnail2.png`）**只有文字和几何，没有 PSD 画面** ——
一张「品类大字 + 成品尺寸 + 出血 + 色彩模式」的信息卡。这决定了技术路线：

| | 生成图片（sharp 合成） | **HTML/CSS（本批采用）** |
|---|---|---|
| 清晰度 | 512px 位图，2× 屏刚好，3× 就糊 | 文字是矢量，任何 DPI 都锐利 |
| 改样式 | 要**重建全部**缩略图 | 改 CSS 就行 |
| 改名 / 改分辨率 / 改关键词 | 缩略图过期，得重生成 | **自动跟着变** |
| 磁盘 | 1000 个模板 ≈ 几十 MB + 重建耗时 | **0** |
| 中文排版 | 画字要手算宽度换行、字体 fallback | CSS 天然支持 |

**「每次导入/扫描后生成缩略图」这个需求因此自动消失** —— 信息卡是实时渲染的，
数据入库就显示，没有"生成"这一步。只有**关键词/分辨率**需要读 PSD（本来扫描就在读）。

> 将来若要导出/打印这张卡，再加一个「导出 PNG」按钮（Electron 截一次即可），不影响日常渲染。

## 3. 卡片上的字从哪来

| 图上内容 | 来源 | 说明 |
|---|---|---|
| **品类**（大字） | **文件名**第一个 `_` 之前 | `展架_海南春季.psd` → `展架`；没有 `_` 就取整名；`_` 之后是备注（进 tooltip） |
| **成品尺寸** | PSD **关键词** `80cm×180cm` | 没写才用画布算（**算出来含出血**，会偏大 2×出血） |
| **出血** | PSD **关键词** `bleed:5mm` | 也认 `出血:5mm` / `出血：5mm`（全角）/ `出血3mm` / `0.5cm` |
| **色彩模式** | PSD 头（`colorMode`） | 已在 `readPsdMeta` 里读（4 = CMYK） |

### 为什么尺寸必须优先读关键词

实测用户真实模板 `展架.psd`：

```
画布 4783×10689 @150ppi = 80.99cm × 181.00cm
设计稿写的成品尺寸     = 80cm   × 180cm
差                    = 各边 0.5cm = 5mm 出血  ← 完全吻合
```

**画布 = 成品 + 各边出血**。直接算会显示 `81cm×181cm`，与用户认知不符。
所以关键词里的成品尺寸优先，算出来的只作兜底（并在没有关键词时兜底显示）。

### 关键词怎么读（实测结论）

用户在 XnView（ExifTool）里写 Keywords，**IPTC 和 XMP 两处都写**：

```
展架2.psd（用户实测）
  IPTC 1028（92 字节）:
    record=2 tag=25 → "80cm×180cm"
    record=2 tag=25 → "bleed:5mm"
  XMP 1060:
    <dc:subject><rdf:Bag><rdf:li>80cm×180cm</rdf:li><rdf:li>bleed:5mm</rdf:li></rdf:Bag></dc:subject>
```

实现上 **IPTC 为主、XMP 兜底**（别的工具可能只写一处）。读它**不需要额外 IO** ——
扫描本来就在遍历图像资源段（读 1005 分辨率 / 1032 参考线）。

### 三个实现要点

**① `keywords` 的三态语义，不能压成两态**

| 值 | 含义 |
|---|---|
| `NULL` | 还没读过（下次扫描要补） |
| `'[]'` | 读过了、这份模板没写关键词 |
| `'["80cm×180cm"]'` | 有 |

少了第二态，每次扫描都会把所有「本来就没写关键词」的模板重读一遍（几百个就是几十秒）。

**② 整卡 1:1，内部尺寸全用 `cqw`**

`container-type: size` + `cqw`（容器宽度百分比）⇒ 150px 和 260px 是**同一版式等比缩放**，
不用写两套断点。⚠️ 定义 container 的元素**自身不能用 cqw**（会回退到视口），所以卡内包了一层 `.tc-inner`。

**③ 品类大字的字号按字数反推**

卡内可用宽度约 86cqw，中文字宽 ≈ 1em ⇒ `字号 = min(15, 86 / 字数)`。
不做的话「主视觉-易拉宝」会被省略号吃掉一半 —— 而名字正是这张卡要传达的第一信息。

卡面**固定浅色**（不跟深色主题）：它是印刷品预览，白底才像纸。
