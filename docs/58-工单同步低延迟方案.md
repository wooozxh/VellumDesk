# 工单同步低延迟方案

> 版本：v1（2026-11-02）　状态：**方案评审，未开工**
>
> 一句话：现在有两条延迟闸（官方同步 0~60 分钟、软件轮询 10~60 分钟），
> 想真正做到分钟级只有"软件自己写表"一条路，但它要拿官方同步换。
> **推荐先做"状态提速"（低风险、收益明确），再验证"接管写表"（收益彻底、代价大）。**

---

## 一、问题

工单目前的数据链路是：

```
企业微信审批单 →（官方「审批同步到智能表格」，整点跑）→ 智能表格 →（软件定时轮询）→ 软件工单队列
```

痛点：**审批提交时刻落在同步周期的哪个位置，就等多久，0~60 分钟随机。**
"立即同步数据"按钮能手动加速，但没人愿意一直点，要的是自动。

---

## 二、实测事实（2026-11-02 本机/真实表格验证）

### 2.1 表格现状

文档：`营销物料设计工单队列（2.0）` `s3_ARUAJgaJAKQCNZoPk1NNzRbKyW0dr`

| 子表 | sheet_id | 记录数 | 状态分布 | 无设计师 | 是否同步表 |
|---|---|---|---|---|---|
| 营销物料制作申请（电子物料） | `tlzJfN` | 25 | 已通过 22 / 审批中 2 / 已撤销 1 | 8 | **是** |
| 营销物料制作申请（印刷物料） | `tlD2Vr` | 8 | 已通过 6 / 已驳回 1 / 已撤销 1 | 2 | **是** |
| 工单测试子表 | `tI8OUG` | 1（空行） | — | 1 | 否（普通表，可当沙盒） |

- 「审批单编号」列存在，值形如 `202610060003`，与审批 API 的 `sp_no` **同源可直接对齐**。
- 三个子表的「审批链接」URL 里带 `orgin=approval_sync_to_smart_table`，确认是**官方内置同步**，非人工自动化。

### 2.2 官方同步的行为（官方文档 + 实测）

| 项 | 事实 |
|---|---|
| 频率 | 用户确认最小时限 1 小时；提交时刻决定等待 0~60 分钟 |
| 同步范围 | 「已通过 / 驳回、**未完成**、已撤销、再次发起」都会同步 |
| 系统字段 | 审批单链接、审批单编号、申请人、**申请人部门**、申请人账号、提交时间、完成时间、提交方式、当前审批状态、审批流程、备注 |
| 删除联动 | 审批单被删除，表格记录同步删除 |
| **限制** | **处于同步状态的工作表，禁止配置「接收外部数据」Webhook**（界面灰显，提示"当前工作表处于同步状态，不支持配置外部数据接收"） |
| 取消同步 | 工作表变普通表；**文档未说明能否恢复，按不可逆对待** |

### 2.3 审批 API（官方文档）

| 接口 | 能力 | 限制 |
|---|---|---|
| `oa/getapprovalinfo` | 按模板/申请人/部门/状态批量拉**单号** | 单次 ≤100 条，时间跨度 ≤31 天，600 次/分 |
| `oa/getapprovaldetail` | 单条详情（审批流程、意见、附件、表单控件） | 600 次/分，需逐条调用 |
| 回调 `sys_approval_change` | 状态变化推送 | **需要公网可达 URL + Token + AESKey** |

权限硬门槛：
1. 必须**自建应用**，且被加入「审批 → API → 可调用接口的应用」
2. 自建应用**只能看到应用可见范围内**申请人提交的单（漏人 = 漏单，且不报错）
3. 2023-12 起**不能再使用「审批」系统应用的 secret**
4. 需要 `corpid` + 应用 `secret` 换 `access_token`（有有效期，须缓存）

### 2.4 智能表格 Webhook「接收外部数据」（已全类型实测通过）

| 项 | 事实 |
|---|---|
| 地址 | `POST https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook?key=…` |
| 能力 | `add_records` 新增 + `update_records` 按 `record_id` 更新 |
| 鉴权 | **只需 URL 里的 key**，不需要 `access_token`、不需要 secret |
| 网络 | **不需要公网 IP**，本地直接 POST |
| 频率 | 每工作表累计 3000 条/分钟 |
| 前提 | 工作表**必须不是同步表** |

字段类型实测结果（测试子表，写完已删除）：

| 类型 | 写法 | 结果 |
|---|---|---|
| text | `[{type:'text', text:'…'}]` | ✓ |
| date_time | `'2026-11-05 00:00:00'` | ✓ 自动转毫秒时间戳 |
| number | `500` | ✓ |
| phone_number | `'+8613800000000'` | ✓ |
| url | `[{type:'url', link, text}]` | ✓ |
| user | `[{user_id:'MaXiangYun'}]` | ✓ **必须明文 userid** |
| single_select | `[{text:'已通过'}]` | ✓ **自动匹配 option id** |

两个坑：
- **成员字段必须传明文 userid**（`MaXiangYun`）。表格里读到的是加密 ID（`woJ3SuaQAA…`），直接回写报 `40031 invalid userid`。审批 API 返回的 `applyer.userid` 本就是明文，可直接用。
- **选项字段按中文写即可**，自动落到 option id，无需维护映射表。

### 2.5 软件现状

| 项 | 事实 |
|---|---|
| 表格读写 | 走 `wecom-cli`（**扫码授权**，本机不留长期密钥），支持 `records list/add/update/delete` |
| 调度器 | 启动后 15 秒首拉，之后每 N 分钟（默认 30，可配 10~1440，可关），防重入、静默失败 |
| 写回 | 「指派设计师 / 改状态 / 缩略图」靠 `records update` 写回表格，**是核心功能，不可砍** |

## 三、延迟到底卡在哪

两道闸，任一都能卡住你：

| 闸 | 归谁管 | 现状 | 能调到多少 |
|---|---|---|---|
| 闸 ①：审批 → 表格 | 官方同步 | 0~60 分钟随机 | **不能调**（官方功能） |
| 闸 ②：表格 → 软件 | 我们自己的调度器 | 默认 30 分钟 | **10 分钟**（下限） |

所以现在最坏情况是 60 + 30 = 90 分钟，最好情况是几分钟。
**把闸 ② 调到 10 分钟，最坏变 70 分钟 —— 免费，但不解决问题。**

---

## 四、候选路径

### P0 · 只调调度器（不做方案，作过渡）

**做法**：把自动同步间隔从 30/60 改成 10 分钟；急单用官方「立即同步数据」按钮。
**收益**：最坏 90 → 70 分钟。零成本。
**代价**：没有。
**结论**：**立刻可做**，但不解决问题。作为过渡手段保留。

---

### P1 · 状态提速（只更新状态，不建行）★ 低风险首选

**做法**
```
每 3~5 分钟调 getapprovalinfo 拉近期单号+状态
  → 挑出「表里还是『审批中』、审批侧已『已通过 / 已驳回』」的
  → 按审批单号找到行，update「当前审批状态」（顺带「审批流程」）
```

**收益**：审批一通过，表格几分钟内就变「已通过」，设计师不用干等下一轮同步。
**代价**：需要自建应用 + secret（只用于读审批）。
**风险**：极低。写的是官方同步本来也会写的同样的值，1 小时后它再跑一遍是**幂等**的；失败了也有官方那轮兜底。
**结论**：**收益明确、风险最小，建议第一优先**。但它**不解决"新单进表慢"**。

---

### P2 · 接管写表（取消官方同步）★ 唯一彻底的方案

**做法**
```
取消两个工作表的同步 → 变成普通表 → 开「接收外部数据」拿 Webhook
软件：轮询审批 API → 拉详情 → 按字段名映射 → Webhook add_records 建行
     状态变化 → Webhook update_records
     指派 / 完成时间 → 照旧写回
```

**收益**：新单 **3~5 分钟**进表，全程可控，不再看官方周期脸色。
**代价**
1. **取消同步按不可逆对待**（官方文档没写能否恢复）
2. **表格更新从此依赖软件运行** —— 软件没开、电脑关机，表就不动
3. 官方「审批单删了表格跟着删」的能力丢失
4. 「审批流程」列以后是我们拼的文字，格式与官方略有差异

**风险**：中高。核心是"单点依赖"——如果大家的电脑下班就关，这套等于"上班时间才更新"，可能比现在还差。
**结论**：**收益唯一彻底，但必须先把"软件装哪台常开机器"定下来**，否则做完白做。

---

### P3 · 双写（官方同步保留 + 软件抢先建行 + 按单号去重

**做法**：保留官方同步，软件用自己的渠道抢先建行，靠 `审批单编号` 去重。

**收益**：既快（分钟级）又有兜底（官方那轮最终还是会把数据补齐）。
**代价**：同 P2 的 2~4，但不承担"取消同步不可逆"的风险。
**风险**：**卡在一个未验证点上——官方同步撞到表里已存在的同单号行会怎样？**

| 它的行为 | 后果 | 结论 |
|---|---|---|
| 跳过已存在 | 完美，P3 可行 | 优先选 P3 |
| 覆盖 / 更新 | 也完美（写的是同样的值） | 优先选 P3 |
| **再建一条** | 表里出现重复单 | **P3 废，只能退回 P2** |

**结论**：**理论最优，但必须先实测这一条。** 实测要往生产表塞一行，需单独授权。

---

### P4 · 常驻小服务（P2/P3 的加固项，非替代）

**做法**：把"审批 → 表格"的搬运做成一个无界面常驻进程，装在一台常开机上（前台机 / 服务器），开机自启。
**收益**：解决 P2/P3 最大的缺点——不再依赖"谁的软件开着"。
**代价**：多一个要维护、会崩、需要看日志的东西。
**结论**：**只要走 P2/P3，强烈建议配 P4。** 否则等于把可用性押在某台电脑上。

---

### P5 · 回调推送（远期）

**做法**：审批状态变化回调 `sys_approval_change` → 中转服务 → 写表。
**收益**：秒级，最省调用。
**代价**：**必须公网可达 URL**（域名 + 证书 + 一台服务器），要运维、要备案。
**结论**：**现在不现实**。等有了服务器再考虑，届时可替代轮询。

---

### P6 · 不走软件，靠审批仪表盘（已排除）

企业微信审批自带数据统计/仪表盘，但**没有"设计师"这一列**，无法承载指派。
**结论**：不可行，仅记录。

---

## 五、推荐路线

### 决策树

```
要不要"新单也分钟级进表"？
│
├─ 不要（只要能"审批通过就尽快看到"）
│    → P1 状态提速。改动小、风险低、当天能验证。
│
└─ 要
     │
     ├─ 先实测：官方同步撞到同单号行会怎样？（P3 的前提）
     │    │
     │    ├─ 不重复 → P3 双写 + P4 常驻服务   ← 最稳
     │    └─ 会重复 → P2 接管写表 + P4 常驻服务
     │
     └─ 有没有公网服务器？
          └─ 有 → 可考虑 P5 回调，秒级
```

### 建议的实施顺序

| 阶段 | 做什么 | 风险 | 能拿到什么 |
|---|---|---|---|
| **第 0 步（立刻）** | P0：调度器改 10 分钟 | 无 | 最坏 90 → 70 分钟 |
| **第 1 阶段** | P1：状态提速 | 低 | **审批通过几分钟内可见**（设计师开工这一环解决） |
| **第 2 阶段** | 实测 P3 前提 | 中（要碰生产表一行） | 决定走 P3 还是 P2 |
| **第 3 阶段** | P2 或 P3 + P4 | 中高 | 新单 3~5 分钟进表 |
| **远期** | P5 回调 | — | 秒级 |

**为什么把 P1 排在前面**：它不碰官方同步、不可逆风险为零、写进去的值 1 小时后会被同样的值覆盖（幂等），
但能解决"审批过了表格还显示审批中"这个直接影响开工的问题。**投入产出比最高。**

## 六、待验证清单（决定后面怎么走）

| # | 验证什么 | 怎么验 | 不通意味着 |
|---|---|---|---|
| 1 | 官方同步撞到表里已存在的同单号行会怎样 | 往印刷子表手工加一行带真实单号 → 点「立即同步数据」→ 看是跳过/更新/复制 | 决定 P3 还是 P2 |
| 2 | 审批 API 能否拉到**全部**申请人提交的单 | 配好自建应用后拉 7 天单号，与表格记录数比对 | 可见范围漏人，要回后台补 |
| 3 | 审批模板控件名与表格列名是否一致 | 拉一条详情，比对 `apply_data.contents[].title` 与表头 | 不一致则要维护映射表，工作量上升 |

第 1 条风险最高（要往生产表写），建议：
- 先备份两张表（导出）
- 加的那一行**只填审批单号 + 物料名称**，测完立刻删
- 或者等软件方案在测试子表上跑通后再做

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 取消同步不可逆 | 回不到官方同步 | 取消前导出备份；优先考虑 P3 而非 P2 |
| 表格依赖软件运行 | 软件不开表不动 | P4 常驻服务 + 指定常开机器 + 开机自启 |
| 可见范围漏人 | 静默漏单，不报错 | 上线前用"7 天单号数 vs 表格记录数"对账 |
| secret 落本机 | 泄露 = 能读全部审批单 | 优先做中转服务；否则加密存 + 文档标注 |
| 成员字段加密 ID | 回写报 40031 | 统一用明文 userid（`申请人账号` 列可作对照） |
| 审批模板改字段 | 映射失效 | 映射做成可配置项，不写死 |
| Webhook URL 泄露 | 谁都能往表里写垃圾 | 不提交进仓库、不贴群；泄露后停用并重新配置 |
| 双源冲突 | 同一单两条记录 | 严格按 `审批单编号` 去重；P3 实测不过就转 P2 |

## 八、附录：配置清单

### A. 自建应用（读审批必需）

1. 管理后台 → 我的企业 → 企业信息 → **企业 ID**（`ww` 开头）
2. 应用管理（新版「应用和小程序」）→ 自建 → 创建应用，记下 **AgentId、Secret**
3. 应用管理 → 审批 → API → **「可调用接口的应用」→ 勾上该应用**（最易漏）
4. 应用详情 → 可见范围 → **覆盖所有会提工单的人/部门**
5. 回调（事件服务器）**暂不配** —— 桌面端无公网地址

### B. 工作表 Webhook（P2/P3 用，必须非同步表）

1. 工作表 → 三个点 → 接收外部数据 → 开始配置
2. 复制 Webhook 地址 → 存本地配置（**不进仓库**）
3. 不启用 IP 白名单（换网络即断）

### C. 软件侧现状参数

- 自动同步：默认 30 分钟，可配 10~1440，启动后 15 秒首拉
- 表格读写：`wecom-cli`（扫码授权）
- 写回字段：设计师、当前审批状态、完成时间、缩略图

## 九、结论

1. **延迟的根子是官方同步那 0~60 分钟，不是软件轮询。** 软件调到 10 分钟是免费但不够。
2. **唯一能彻底解决的是"软件自己写表"**（P2 接管 / P3 双写），两者差别只在"官方同步留不留"。
3. **P3 比 P2 好**，但有未验证前提（官方撞同号行的行为）；不成立就退 P2。
4. **只要走 P2/P3，就必须配 P4 常驻服务**，否则可用性押在某台电脑上。
5. **P1 状态提速可以独立做、风险最小**，建议先落地拿收益，再啃 P2/P3。
