## 一、第 1 件：配置 npm 镜像（必须做，1 分钟）

### 为什么

npm 是"软件包商店"。默认商店在国外，装包慢、容易断。**实测你这台机器：**

```
直连淘宝镜像：0.40 秒
直连官方源　：1.39 秒    ← 慢 3.5 倍
```

而且官方源在网络波动时经常直接超时失败。**这一步不做，后面每次装包都可能卡住。**

### 怎么做

打开 **CMD** 或 **PowerShell**（开始菜单搜 `cmd` 就行），把这 4 行一条一条粘贴进去回车：

```bash
npm config set registry https://registry.npmmirror.com
npm config set electron_mirror https://npmmirror.com/mirrors/electron/
npm config set electron_builder_binaries_mirror https://npmmirror.com/mirrors/electron-builder-binaries/
npm config set cache D:\npm-cache
```

**每一行在干什么：**

| 命令 | 作用 |
|---|---|
| 第 1 行 | 装包从淘宝镜像下载 |
| 第 2 行 | Electron 那个 100 多 MB 的运行时，从国内镜像下 |
| 第 3 行 | 打包工具用到的额外文件，也走国内镜像 |
| 第 4 行 | **把包的缓存从 C 盘挪到 D 盘**（你 C 盘只剩 34 GB，这个必须挪） |

### 验证

```bash
npm config get registry
```

看到 `https://registry.npmmirror.com` 就成功了。

## 二、第 2 件：建项目骨架，初始化 Git

**这一步需要先定一个事：项目放哪个目录。**

建议：`D:\projects\素材管家`

- 放 **D 盘**（254 GB 可用），别放 C 盘（只剩 34 GB）
- 路径里**尽量避免中文**，用 `D:\projects\material-hub` 更保险（有些构建工具对中文路径支持不好）

目录名英文化，软件里显示的标题仍然是"素材管家"，不影响。

骨架长这样：

```
素材管家/
├── PROJECT.md          ← 项目身份证（AI 每次开工先读）
├── PROGRESS.md         ← 进度台账（AI 每次收工必写）
├── DECISIONS.md        ← 决策记录
├── README.md
├── docs/               ← 需求文档放这
└── src/                ← 代码（脚手架生成）
```

然后在目录里初始化 Git：

```bash
git init
git add .
git commit -m "初始化项目骨架"
```

（Git 是"存档"工具。每完成一小步就 commit 一次，出问题能退回上一个存档点。**对新手来说，这是最重要的一个安全网。**）

## 三、第 3 件：跑通第一个 Electron 窗口

这一步的目的是**验证环境真的能干活**，不是开始写功能。

### 做法

在项目目录的**上一级**打开 CMD，执行脚手架命令：

```bash
npm create @quick-start/electron@latest
```

它会问你几个问题，按这个选：

| 提示 | 选什么 |
|---|---|
| Project name | `material-hub`（或你的目录名） |
| Select a framework | **React** |
| Add TypeScript? | **Yes** |
| Add Electron updater plugin? | **No** |
| Enable Electron download mirror proxy? | **Yes** ← 有这项就选 Yes，自动配国内镜像 |
| Add ESLint & Prettier? | **Yes** |

> 交互提示可能随版本略有不同。总原则：**framework 选 React，TypeScript 选 Yes，用不到的插件选 No。**
>
> 如果这条命令报错或卡住，备用方案（Electron 官方脚手架）：
> ```bash
> npx create-electron-app@latest material-hub --template=vite-typescript
> ```

### 验证

```bash
cd material-hub
npm install
npm run dev
```

**屏幕上弹出一个窗口 = 环境验收通过。**

窗口里大概是 Electron 的示例页面。这时候你还什么都没写，但它证明了一整条链路（Node → 装包 → 编译 → 启动）都是通的。

关掉窗口、在 CMD 里按 `Ctrl + C` 就停了。

## 四、坑预警（这几条能帮你省好几天）

### 4.1 C 盘空间

- 现状：C 盘 149 GB，**只剩 34 GB**
- `node_modules`（依赖包文件夹）动辄 500 MB，一个项目可能好几个
- 所以：**项目放 D 盘 + npm 缓存挪到 D 盘**（第一条命令里已经处理了）

### 4.2 装包卡住不动怎么办

九成是网络问题，按顺序排查：

1. 确认 `npm config get registry` 输出的是淘宝镜像
2. 把 CMD 关掉重开（配置需要新开窗口才生效）
3. 加长超时时间：`npm config set fetch-timeout 600000`
4. 还不行就删掉 `node_modules` 文件夹重新 `npm install`

### 4.3 原生模块要"重编译"（做数据库那步才会遇到）

素材管家要用 SQLite 数据库，用的是一个叫 `better-sqlite3` 的包。它含有 C++ 代码，**Electron 用的 Node 版本和系统的不一样**，所以要重新编译一次：

```bash
npx electron-rebuild
```

如果这步报错说找不到编译器，需要装一个叫 **VS Build Tools** 的东西（约 3 GB，我到时候带你装）。**现在不用管，遇到了再说。**

### 4.4 杀毒软件

360、火绒这类软件会实时扫描 Electron 生成的文件，导致装包和启动明显变慢，偶尔还会误删。

**建议**：把项目目录加进杀毒软件的信任/白名单。

### 4.5 两个 Node 版本的小坑

你这台机器上其实有**两个 Node**：

| 版本 | 在哪 | 谁在用 |
|---|---|---|
| v24.21.0 | `D:\nodejs\` | **你在 CMD 里用的就是这个**（系统 PATH 里排第一） |
| v22.22.2 | WorkBuddy 自带的 | WorkBuddy 内部使用 |

**日常不用管**。但如果出现"我这边能跑、AI 那边报错"这种怪事，多半是版本差异，知道了就不慌。

## 六、搭好之后，第一步做什么

按需求文档的路线，第一步做 **MVP**（最小可用版本），只做 4 个功能：

1. **入库** —— 选一个文件夹，把里面的素材登记进来
2. **打标签** —— 给素材标项目、类别
3. **检索** —— 按标签筛选、按文件名搜
4. **预览** —— 双击打开，或打开所在文件夹

**先别碰打包和版本管理。** 那两件事是第二步。

原因：MVP 阶段真正的目的是**验证你那套标签体系合不合理**。标签一旦定错，后面所有素材都要重打一遍——这是这个项目里最容易返工的地方。

所以第一版跑起来后，先真实用一两个月，标签改顺了再往下走。

## 七、出问题了怎么办

在这个项目里，遇到报错的标准动作：

1. **把报错原文完整贴给 AI**，不要只描述现象
2. 说清楚"我在做什么操作的时候出现的"
3. 让 AI 先解释"这个错误在说什么"，再动手改
4. **一次只改一处**，改完立刻重启验证

报错不可怕，**猜着改才可怕**——那会把问题越改越乱。
